# 艺术库视觉整理质量升级设计

日期：2026-08-10
状态：已由用户确认产品语义，等待实施计划
主能力线：Art Library（艺术库）

## 目标与边界

保持 `公网 / 对话附件 / 项目图片 → incoming → read_art_images → AI 整理 → approval → libraries` 文件状态机不变。升级 AI 看图后的输出合同、分类证据、人工修订和库级风格提取。没有专属艺术库 Agent，不把视觉质量降格为字符串长度检查。

本设计不实现生产页面、不修改正式 Profile、不打包 Windows，也不自动持久化库级或个人整体风格结论。

## 单图整理合同

新版一次只读取一张候选图，并产出三个独立结果：

1. `styleAnalysis`：面向人的作品解读，包含至少三个可回指当前图片的视觉依据。
2. 三组标签：`patternTags`、`compositionTags`、`moodTags`，由 AI 自由填写并允许用户逐项增删修改。
3. 结构化反推 Prompt：`STYLE / COMPOSITION / SCENE / NEGATIVE`。前三层分别拥有视觉语言、画面组织和可替换剧情，负向层拥有不需要的渲染与漂移约束。

新版元数据使用新的 Schema（数据结构）版本；四层 Prompt 是唯一权威，不与旧 `promptDraft` 双写。非种子旧用户条目继续兼容读取并明确显示为未按新版方法整理，只有真实重新看图并经人工审批后才能升级。

## 分类与整体风格

分类判断时，AI 获得各分类当前标签和2至4个代表作品视觉摘要，不能只看名称和数量。代表摘要来自已批准作品的真实解读，不建立脱离作品的固定分类真相。

“导出关键词”保持确定性、去重、零 Provider（模型服务）调用。“提取风格”是独立的按需行为：当前普通会话读取指定分类或个人全部批准作品的标签，保留出现频率和分类关系，生成库级解读和四层 Prompt。结果默认只出现在当前对话；标签变化后重新请求即重新提取。

## 人工审批

审批允许修订标题、分类、作品解读、色板、三组标签、四层 Prompt 和负向约束。Runtime（运行时）先完整验证修订，再沿现有目录状态机移动整个条目。失败时零移动；暂缓零写入；驳回仍遵守现有精确删除和墓碑规则。

## 旧种子重置

63条早期种子的旧整理结果全部废弃，但原图与可信来源保留。一次性迁移只按稳定 `seed` 标识选择目标，破坏性变更前核对63条记录、原图可读性和 SHA-256，然后把原图重新送入新版待整理路线。旧元数据不能转换成新版结果；非种子条目不得变化。迁移在隔离 Profile 验证后才具备发布资格。

## 错误与质量边界

非视觉模型、缺少真实图片、跨图污染、结构缺失、非法人工修订、种子数量或哈希不符都必须失败关闭。程序可以验证结构、权限、文件事实和禁用直接标题/作者替代，但不能自行证明艺术质量。

视觉质量按方法版本、分类和模型抽样：只看原图生成反推结果，移除原图，替换 `SCENE`，仅用文字生成不同剧情的新图，再由人记录视觉语言是否保持。该证据与普通单元测试分开报告。

## 实施顺序

1. 新版元数据与旧用户条目兼容读取。
2. 单图工具合同和整理方法说明。
3. 分类上下文与库级/个人级风格材料读取。
4. 完整审批编辑合同。
5. 旧种子隔离迁移。
6. 生产页面与真实视觉抽样验收。

任一步要求修改 `incoming → approval → libraries` 状态机、引入第二个 Agent 或无证据删除非种子条目时停止。
