# 艺术库 0.1.19 体验恢复实施计划

## 当前目标

在不回退现有 Runtime 和用户数据的前提下，将 63 张基础藏品真实恢复到三个正式分类，并将生产艺术库主页面恢复为 `0.1.19` 的图鉴式体验。

## 验收与停止条件

- `ACC-ART-033`：新 Profile 与已错误 reset Profile 最终均为巨构艺术 41、暖色风格 18、纪念碑谷 4；seed 不留在 incoming/approval。
- `ACC-ART-034`：重复启动和中断恢复不产生副本；所有非 seed 用户条目逐字节不变。
- `ACC-ART-035`：身份、快照、SHA-256 或目标冲突失败关闭且不写完成标记。
- `ACC-ART-036`：生产 React 首页向直接复用的 `0.1.19` 展示页面注入真实 Runtime 快照；作品点击、展览、详情、审批和关键词/AI 风格入口可达，静态 JSON、iframe 内默认值与 `localStorage` 不决定事实。
- `ACC-ART-037`：1600×1000 两轮截图对照达到已冻结的结构、层级、字级、色彩和动效方向；减弱动效设置下仍可用。
- 若可靠迁移需要猜测条目归属、修改公共合同或产生不可逆用户数据迁移，停止并请求产品/架构决定。

## 顺序

1. 记录本次用户纠正，更新能力规则、验收矩阵与视觉规格。
2. 先写迁移失败测试：分类计数、用户数据不变、幂等、中断恢复、身份/哈希/目标冲突。
3. 实现新的基础藏品清单与物化迁移，替换 Desktop 启动入口；运行 Runtime 定向测试。
4. 写 Renderer 结构与交互测试，将旧图鉴布局/轨道算法移植为真实 React 页面。
5. 运行 Renderer 定向测试、`bun run typecheck`、Production Build（生产构建）和代码冻结后的全量测试。
6. 以隔离 Profile 启动真实桌面页面，做至少两轮 1600×1000 截图校正，并检查退出后无残留进程。
7. 更新 `CONTEXT.md`、`BASELINE.md` 和本计划的实际证据。未经额外授权不提交、不推送、不打包。
