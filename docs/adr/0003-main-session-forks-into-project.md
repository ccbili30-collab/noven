# ADR-0003：个人会话完整分叉为项目会话（待复核草案）

## Status

Draft - Product Behavior Confirmed, Architecture Pending

日期：2026-07-25

## Context

CreatX 用户可能只是打开软件与长期陪伴自己的个人 AI 聊天，在倾诉、回忆或讨论中突然产生创作灵感。如果要求用户新建一个空项目会话并重新解释前文，AI 会表现出失忆，破坏创作情绪和持续关系。

与此同时，没有项目文件夹的个人对话不具备明确的文件写入范围。允许未挂载项目的个人会话直接创作会让文件位置、权限、项目记忆和迁移边界变得不确定。

早期讨论中，用户接受过完整复制语义：项目会话继承分叉前个人会话的全部文本历史，包括可能与后来作品相关的私人回忆；它不是只继承摘要或由系统筛选出的片段。

后续讨论进一步明确：不存在唯一、无限增长的主会话；用户可以创建多个未挂载项目的个人会话，新个人会话还可以选择从旧会话继承默认隐藏的压缩记忆。用户随后确认，该压缩继承与“当前个人会话完整复制转移到项目”不是同一个流程，前者不取代后者。

完整复制转移的产品行为已经确认，但项目迁移、分享和协作时如何处理来源私人对话，以及底层采用物理复制还是其他等价持久化方式，仍未决定。因此，本 ADR 仍是架构草案，不能作为已接受的数据模型或实现方案。

## Confirmed Product Behavior And Draft Architecture

以下产品行为已经确认；其中字段和持久化方式仍是待复核草案：

- 未挂载项目的个人会话在第一版是纯文本对话，不绑定项目位置。
- 该个人会话不注册文件、命令、浏览器或其他工具，没有文件写入权限。
- 文件权限由 Runtime 的工具注册和作用域强制执行，不依赖系统 Prompt 要求模型自律。
- 用户在个人会话要求正式创作时，AI 明确说明当前无权写入文件，并引导用户创建或选择项目文件夹。
- 项目创建是用户授权的产品动作，不由个人会话静默执行文件系统副作用。
- 创建项目时，系统以当前消息为分叉点，完整复制此前全部个人会话记录形成新的项目会话。
- 项目会话持久保存来源会话和分叉点，并知道自己继承自哪个个人会话。具体字段尚未决定。
- 项目会话不需要主动向用户强调自己是复制体。Renderer（渲染层）保持同一个个人 AI 和连续聊天体验，同时显示当前项目范围。
- 项目会话获得当前项目文件夹内的工具和权限，不获得任意系统文件权限。
- 分叉后两条会话独立追加消息，不自动同步后续原始对话。
- 项目进展只有通过用户允许的项目记忆和跨项目蒸馏进入个人长期记忆，不把项目完整聊天自动回灌其他个人会话上下文。
- 项目移动、分享或协作时携带多少来源对话尚未决定，不能沿用早期完整携带假设。

## Consequences

### Positive

- 用户从闲聊进入创作时不需要重新解释灵感来源。
- 主会话保持纯净、低权限，项目会话拥有明确文件作用域。
- 会话血缘、权限和持久化边界可以由稳定 ID 验证。
- 同一个个人 AI 可以在界面上保持连续身份，而底层任务上下文不会永久混成一条无限会话。

### Negative

- 完整分叉会复制可能与项目无关的私人对话，增加项目存储和隐私风险。
- 主会话很长时，完整历史不能不经投影直接发送给 Provider；模型上下文仍需要独立的压缩和选择机制。
- 分叉后的主会话与项目会话可能形成不同理解，需要通过明确记忆蒸馏而不是消息同步协调。

### Neutral

- “完整复制会话记录”是持久化与用户历史语义，不代表每个 Provider 请求都发送完整原文。
- 项目会话知道其来源属于内部状态；AI 是否在特定场景解释来源由用户提问和产品交互决定。

## Privacy Boundary

- 第一版项目默认是个人数据，不能假设适合公开分享。
- 增加项目分享、导出或协作前，必须明确展示项目会话包含从主会话复制的私人历史。
- 是否提供剥离历史、生成公开副本或只分享作品文件，需要单独产品决定和测试，不能静默处理。

## Alternatives Considered

- 新建空项目会话：拒绝，因为会丢失灵感产生过程并迫使用户重复解释。
- 只复制自动摘要：拒绝作为第一版用户历史语义，因为用户要求项目中保留完整对话。
- 主会话直接获得文件工具：拒绝，因为没有明确项目位置和权限边界。
- 主会话与所有项目永久共用一条可写会话：拒绝，因为文件作用域、迁移、取消和项目记忆会互相污染。
