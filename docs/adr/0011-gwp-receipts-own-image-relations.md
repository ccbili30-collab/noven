# ADR-0011：GWP 回执拥有生成时正文图片关系

## 背景

项目文件是内容真相，Markdown 图片引用是最终文章—图片关系。GWP 已经为每个完成对象持久保存正文路径和图片任务 ID，但旧链路又要求 Writer 在提交图片时复制挂接字段，造成同一关系有两个作者，也使历史回执无法自动修复正文。

## 决定

GWP 物化回执是生成时关系的唯一权威。World Materialization（世界物化）只把回执派生为图片队列的挂接意图；Image Runtime（图片运行时）仍独占挂接状态与 `ImageAttachmentService` 调用；Project Files（项目文件）仍独占 Markdown 写入。

应用打开项目时可以从正式回执重放派生意图。任务绑定不同正文时失败关闭；游离任务不推断。图片成功与挂接成功保持两个状态，挂接失败不回滚图片文件或阻塞 GWP 正文完成。

## 理由

该设计复用现有回执、队列表字段和文件写入端口，不增加永久关系模型。它同时覆盖回执先到、图片先到和应用中断，并使旧完整世界可以通过同一生产路径恢复。

## 后果

- 两个 SQLite Store 之间采用持久回执加幂等对账的最终一致性，不承诺原子提交。
- Worker 不再负责 GWP 挂接字段；普通生图仍可显式提交挂接意图。
- 正文发生用户修改或锚点冲突时保留图片成功并报告挂接失败，不覆盖正文。
