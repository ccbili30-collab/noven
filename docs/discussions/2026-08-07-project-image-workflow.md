# 项目图片工作流讨论记录

日期：2026-08-07
状态：核心语义已实现并完成自动化验收；外部 Provider 与 Electron 视觉 Live 待验收
主要能力线：`image-runtime`
相邻能力线：`project-files`、`workspace-ui`、`workbench-registry`、`growth-runtime`

## 用户目标

同一套图片生产与展示能力必须同时服务普通对话、普通 Growth 和 Growth World Pro（GWP），不能由各个 Worker 分别实现队列、图文关联或视觉母版拼接。

用户希望：

- 同一项目中的图片任务严格串行，一次只生成一张；
- 不同项目可以并行生成，但不能形成无上限并发；
- 当前项目可看到图片任务的排队和生成进度；
- 图片成功后从活动列表移除，但持久记录不能删除；
- 任务支持重试、跳过和取消；
- 图片与文章存在可解释的真实关系，并在工作台中形成文字环绕图片的版式；
- 普通 HTML 文件也能使用现有安全预览能力播放。

## 已确认的操作语义

- **重试**：失败或中断的逻辑任务立即重新排到本项目队首。旧 Provider 尝试和错误历史必须保留。
- **跳过**：把任务排到本项目队尾。对失败或中断任务意味着稍后再尝试；对尚未开始的排队任务意味着只改变顺序。
- **取消**：永久放弃该逻辑任务，当前项目继续处理下一张。持久记录保留为 `cancelled`，不得删除或伪装成成功。
- 正在生成的任务不提供“跳过”，因为将已经发出的 Provider 请求重新排队可能造成重复费用和重复输出。它只允许取消；下一张必须在当前请求中止或返回后开始，以维持同项目单并发。
- 成功任务显示绿色完成反馈 3 秒后从活动列表消失；取消任务显示短暂的已取消反馈；失败和中断任务持续显示，直到用户重试、跳过或取消。

## 调度决定

采用一个全局持久 `ImageTaskStore` 和一个按项目分通道的 `ImageTaskQueue`：

- 每个项目最多一个 `generating`；
- 全局第一版最多两个 `generating`；
- 不为每个项目建立数据库、进程或永久 Worker；
- 调度器在可运行项目之间按最早排队任务轮转；
- 每个活动项目拥有独立 `AbortController`；
- 应用退出仍把活动请求记为 `interrupted`，不得自动重提可能已经计费的未知请求。

现有 `IMG-012` 的全应用单 Worker 规则需要被新规则取代。现有 `image_task.project_id` 已能承担项目隔离，不新增项目队列表。

## 图文关系决定

文章正文中的 Markdown/HTML 图片引用是最终、唯一的内容关系事实。不建立隐藏的“文章—图片”关系数据库，也不通过同名文件猜测关系。

图片任务可以持久化一个待执行的挂接意图，但该意图只负责成功后的受控写入，不是最终关系权威：

1. Worker 提交图片任务，并可声明目标 Markdown 文档、替代文字和插入锚点；
2. 图片真实生成并落盘成功；
3. 独立 `ImageAttachmentService` 读取目标文档，验证锚点唯一性；
4. 通过 `ProjectFileCommandPort` 使用最新文件版本进行原子写入；
5. 正文形成标准 Markdown 图片引用后，挂接才算成功；
6. 工作台从真实正文重新渲染，不读取图片队列数据库猜测版式。

图片队列本身不得直接拼接正文。挂接冲突不能把已经成功的图片改判为失败；本次讨论原先将其定义为“图片成功、挂接失败”的独立可见结果。后续 `2026-08-07-silent-image-attachment-mismatch.md` 将 `image_attachment_conflict` 的用户投影改为静默，其他挂接故障仍保持可见。

## 展示决定

- Markdown 普通插图在宽屏默认右侧环绕；横向大图按实际宽高比切换为全宽；窄屏取消浮动并上下排列。
- HTML 使用文件自身的 `<figure>`、`<img>` 和 CSS，不套用 Markdown 环绕规则。
- 普通 `.html` 文件点击后走已有 `creatx-workbench://` 隔离协议，不在 Renderer 使用 `dangerouslySetInnerHTML`，不开放 Electron 或 Node 私有接口。
- Renderer 只读取稳定的图片任务 Projection（投影）和 Event（事件），不读取 SQLite Schema（数据库结构）。

## 明确不做

- 不做无上限跨项目并发或可配置并发控制台；
- 不建立每项目独立数据库、进程或图片 Provider；
- 不自动重提应用崩溃前结果未知的请求；
- 不删除成功、失败或取消任务的持久证据；
- 不按文件名自动猜测文章和图片关系；
- 不让图片或挂接失败阻塞无依赖的正文生成；
- 不在本批实现图片编辑队列、视觉版本状态机或自动重绘旧图片。
