# Growth 蓝图恢复与题材分类修正讨论

日期：2026-08-06
状态：已确认，进入有界实现批次
主要能力线：`creative-skills`
相邻合同：`growth-runtime`、`world-blueprint`

## 用户目标

Growth World Pro 必须优先保证一句明确需求能够顺畅跑完四阶段、生成表现合格的真实正文，并在原会话汇报。蓝图合同和恢复保护不得反过来制造必然冲突。

## 已确认问题

阶段一的 `initialize` 已经创建十二份空层蓝图。旧阶段二又被允许向这些层追加具体对象，阶段三随后被要求扩充完整世界，但 `inspect` 只提供数量而不提供可避让的对象清单。因此阶段三可能提交一批部分已存在、部分缺失的对象，并被蓝图工具正确拒绝。

该问题不是模型单次失误，而是阶段二和阶段三同时拥有具体蓝图对象创建职责。自动改 key、静默跳过或覆盖会隐藏语义重复，不能作为修复。

## 接受的产品决定

1. 阶段一继续判断路线、资料边界、世界方向、题材、主题与基调，并以 `initialize` 建立持久方向容器和十二份空层蓝图。
2. 阶段二只 `inspect` 并验证十二层入口完整、仍未创建具体对象；不得 `append`、`map_sources`、送审或写正文。
3. 阶段三是具体 group、entry、计划路径、基础因果和来源映射的唯一创建阶段。
4. 蓝图工具允许一种可机械证明安全的部分恢复：已存在对象与本次提交的物化语义完全一致时保留，缺失对象继续写入；同 key 但字段不同仍以 `blueprint_conflict` 失败关闭。
5. 工具错误在产生时立即交给 Growth Runtime 持久化 Issue，并以 attempt 与 tool call 身份幂等去重；Worker 正常返回后仍可重复提交同一故障而不产生第二个 Issue。
6. 不增加退出或崩溃后的 Provider/工具自动重放。现有产品合同继续要求活动 Run 停止，重启后由用户显式继续。
7. 不迁移或补生成本轮失败的测试项目；失败测试产物允许丢弃，完整整本产物继续保留。
8. 题材选择扩充为几十个可见题材配置，但共享少量文类偏好母型。题材只排序候选文类，不成为正文必须满足的事实或结构合同。

## 验收边界

- 阶段二不能调用 `append`，阶段三可以。
- 新建项目在阶段三开始时十二层对象数均为零。
- 精确存在的对象加缺失对象可以在同一批次安全完成；语义不同的同 key 对象继续失败。
- Blueprint Worker 的工具故障在 Worker 返回前已经形成持久 Issue；最终回执重复对账不增加 Issue。
- 新增题材全部只引用各层已经允许的 Publication Genre，并保留现有四个 key 的兼容性。
- 不以 Mock 或单元测试宣称新的外部 Provider 整本 Live。
