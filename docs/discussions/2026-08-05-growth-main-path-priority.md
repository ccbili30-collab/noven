# Growth 主链优先级纠正

日期：2026-08-05。

状态：已接受的产品纠正，待通过能力规格、验收矩阵和实现审计完成推广。

## 用户核心准则

用户说出一个需求，Growth 就能稳定地从头跑到尾，产出质量合格的内容，最后在原对话里汇报结果。其他设计都必须为这件事服务。

必要时可以降低事实完整性、关系精度和恢复精度，也允许不冲突的合理扩写，但不能牺牲主链路的可运行性和文本表现。

## 已发现的偏差

此前返修把大量精力投入极端并发、崩溃窗口、Activation 精确一致性和审查清零。它们能提高局部严密性，但也可能增加普通运行分支、失败门禁和恢复合同，使系统接近“为了绝不出错而无法顺畅运行”。

该纠正不否定已经证明必要的底线保护；它改变的是优先级和后续复审的举证责任。任何新增门禁都必须说明它怎样帮助真实需求跑完，或阻止哪一条不可让步的底线风险。没有这种直接价值、且增加常见路径失败面的规则，应删除、简化或延后。

## 正确优先级

1. 一句话明确启动，普通聊天绝不误触发。
2. 一个 Owner 持续带着任务跑完四阶段。
3. Worker 正常生成、写文件并返回结果。
4. 过程可见，最终回复留在原会话。
5. 常见错误自动重试或绕过，不轻易停止。
6. 暂停、继续和退出能够正常工作。
7. 极端并发、毫秒级竞态和崩溃精确恢复属于后续加固，不能持续阻塞主链。

## 不可让步的底线

- 普通聊天不能误触发 Growth。
- 不能同时启动两条互相冲撞的主任务。
- 不能明显重复写入或让正文互相覆盖。
- 不能把失败伪装成成功。
- 错误不能拖死整个软件。
- 最终必须留下真实文件和用户可理解的正式回复。

## 后续复审问题

复审首先回答：现有约束是否直接帮助一条真实需求顺畅跑完；若没有，它是否增加了运行阻力。属于后者的约束不得仅为审查数字清零而继续叠加。

极端时序缺陷只有在会触犯上述底线、破坏常见暂停/继续/退出，或已有真实复现证据时，才可阻塞当前主链批次。其余记录为后续加固，不得取代真实四阶段长跑、内容质量和原对话最终汇报的验收。
