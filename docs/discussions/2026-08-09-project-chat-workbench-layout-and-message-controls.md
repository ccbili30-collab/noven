# 项目对话、工作台布局与本机消息操作

状态：用户已确认产品语义；尚未实现。

## 发现与纠正

用户在 Windows `0.1.14` 真实便携版中确认以下问题：

1. 当前项目导航最小宽度被硬限制为 `220px`，无法通过分隔线压到折叠栏厚度。
2. 当前生产导航在项目下面列出工作台；用户确认项目下面应列出该项目的对话。
3. Workbench（工作台）模式把 Chat（对话）移动到最右，打开工作台会改变空间关系。
4. 当前首条用户消息最多取 40 个字符作为 Session（会话）标题，长中文指令会占据大块标题区域。
5. 现有附件只支持通过按钮打开原生文件选择器，缺少把操作系统文件拖入 Chat 的常见桌面路径。
6. 用户消息没有本机删除、修改后发送和重发入口，长消息持续占据阅读空间。

本记录补充并部分取代 `2026-08-08-desktop-interaction-language.md` 中“项目行展开工作台列表”的旧解释。旧记录关于展开、选中、打开和表面模式独立，以及折叠不得丢失状态的规则继续有效。

## 用户确认的布局

完全展开时固定为：

```text
左侧全局导航 | 中左 Chat | 中右工作台画布 | 最右工作台导航
```

- 左侧全局导航包含资料库、项目和项目下的会话。
- Chat 不因打开、关闭或切换工作台而换位。
- 工作台画布显示真实文件、预览和编辑内容。
- 最右工作台导航显示工作台切换、目录、搜索和资源树。
- 最右导航向右收起，展开态的收起图标朝右；折叠后的恢复图标朝左。
- 窗口空间不足时，先折叠左侧全局导航，再折叠最右工作台导航，保留 Chat 与工作台画布。

左侧导航取消 `220px` 拖拽硬下限，允许连续压缩到现有 `52px` 折叠厚度；到达该厚度时进入真正折叠态。重新展开恢复本次拖动前的展开宽度，而不是恢复为残缺窄栏。折叠、重排和窗口缩放不得重建 Chat 或工作台状态。

## 项目与会话显示

- Chat 顶部大标题显示当前项目名称，标签栏只列当前项目的会话。
- 新普通项目会话按项目独立命名为 `创作（1）`、`创作（2）`、`创作（3）`。
- 编号单调递增；删除会话后不复用，重命名不改变编号分配。
- Session ID 与显示名称完全独立。
- 系统会话、Growth Worker 和明确命名的“艺术库 Chat”不占普通创作编号。
- 用户可通过右键菜单重命名；右键不是唯一入口，现有双击或可见菜单路径继续保留。
- 既有会话不自动批量改名，避免覆盖用户已有名称。

## 拖入文件作为待发送附件

- 操作系统文件拖入整个当前 Chat 面板均可成为待发送附件；不要求精确瞄准 Composer（输入区）。
- 拖入时显示明确有效目标覆盖层，离开或按 Escape 取消。
- 松开后只进入待发送附件列表，不自动发送、不调用 Provider（模型服务）。
- 工作台画布和最右导航不接收聊天附件拖入，避免与未来工作台文件拖动混淆。
- 拖入复用现有短期附件授权、最多 20 项、移除、发送、消费和失败关闭合同。Renderer（渲染层）不得获得任意可伪造绝对路径。
- 文件夹、无路径的构造 File、超量、消失或不可读文件必须分类失败，并保留草稿和已有附件。

## 本机消息操作

只对用户消息提供：

- `删除`：只从本机 CreatX 界面持久隐藏该用户消息。Cline 历史、AI 上下文、Assistant 回复、工具调用和文件副作用均不改变。
- `修改`：把原文带回 Composer；新内容成功进入发送流程后隐藏原消息，并把修改内容作为新回合发送。取消或发送失败时原消息保持或恢复可见。
- `重发`：相同内容作为新回合发送，并隐藏原消息；发送失败时恢复原消息。

用户已明确接受上述语义类似“只删除我这边”，不要求从 AI 侧撤回。界面必须在首次删除时说明边界，不能宣称撤回、历史重写或副作用回滚。活动 Run 期间禁用修改与重发。消息操作必须支持键盘和聚焦路径，不能只依赖 Hover（悬停）。

## 非目标

- 不修改或重写 Cline 已提交消息文件、SQLite 或工具配对。
- 不用 Cline Checkpoint（检查点）创建历史分支。
- 不回滚已经产生的 Provider 请求、工具调用、图片、文件或其他副作用。
- 不让拖入文件自动发送。
- 不在本批处理 Assistant 消息删除或重发。
