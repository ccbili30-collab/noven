# CreatX 项目切换与空白项目界面发现

本记录保存 2026-07-26 对 Web Prototype（网页原型）的产品纠正。它是后续 `workspace-ui` 规格和验收设计的输入，不是生产实现完成声明。

> 后续取代说明：本文仍可作为项目隔离和 Prototype 交互证据，但其中固定侧聊入口不进入第一条生产骨架。当前生产 UI 只显示真实接通的主会话、审批、文件与预览；规则见 `../capabilities/workspace-ui/product-spec.md`。

## 用户纠正

- 参考图中的左侧“项目会话列表”不能直接成为 CreatX 的固定项目布局。
- 项目旁的会话区域首先是用户与当前 AI 对话的地方，不应常驻展示历史会话条目。
- 真正的项目会话集合只在用户进入“交流模式”或查看项目图标的会话入口时出现。
- 项目图标 Hover（悬停）可以提供快速入口，但不能成为唯一可操作方式；稳定打开仍需点击或键盘等价行为。

## 当前原型批次

- 保留已有“长昼档案”及其地图、会话、文件和注册工作台 Fixture（测试夹具），用于视觉和交互对比。
- 新增第二个空白项目。用户切换到该项目时，不得看到长昼档案的会话、文件、预览、侧聊、世界或小说数据。
- 空白项目保留当前 AI 对话面与输入能力，但初始没有消息和创作内容。
- 内置“文件”入口可以存在；空白项目打开后显示空文件视图，不产生虚构文件。
- 切回长昼档案时，它原有的草稿、工作台、文件选择和侧聊状态应恢复，证明项目状态没有串线。

## 后续纠正：工作台与交流是两种布局模式

用户随后指出，参考图把“项目会话列表 + 输入框”常驻在工作台左侧的结构本身就是错误的。上一轮只修复了空白项目的数据隔离，尚未修正这一布局语义。

- 工作台模式固定为：项目栏、当前 AI 对话、中央工作台、注册工作台栏。
- 工作台旁的左侧面板展示当前用户与 AI 的消息和唯一输入框，不展示项目历史会话列表。
- 交流模式固定为：项目栏、项目会话列表、中央完整 AI 对话。
- 进入交流模式后，左侧紧凑对话及其输入框必须转为会话导航；中央完整对话成为唯一输入面，禁止同时出现两套输入框。
- Hover（悬停）或键盘聚焦项目图标时，可以临时弹出该项目的会话列表；它是快速选择入口，不替代稳定的交流模式。
- 点击活动工作台标签或在工作台模式按 `Escape` 时进入交流模式；重新进入工作台模式时恢复该项目此前的工作台选择。
- 两种布局模式及其恢复状态按项目隔离。

## 再次纠正：展开导航是一棵项目会话树

用户进一步指出，上述“交流模式固定为项目栏、项目会话列表”的并列描述仍然错误，本节取代该描述中关于左侧导航结构的部分。

- 交流模式的展开侧栏是一个统一空间，不再同时保留独立的项目方块栏。
- 项目是侧栏中的第一级，每个项目的全部下属会话以缩进和连接线形成第二级，呈现清楚的阶梯递进关系。
- 项目方块栏是统一导航的压缩形态；项目图标旁临时出现的会话小窗也是压缩形态的快速入口。
- 展开侧栏时，项目方块栏和临时会话小窗都不出现；折叠侧栏后才恢复项目方块栏，并允许悬停或键盘聚焦打开小窗。
- 从统一树选择项目或下属会话时保持交流模式，并更新中央完整对话；只有用户明确进入工作台时才恢复该项目此前的工作台。

## 边界

- 本批次只验证浏览器内存状态与界面投影，不声明真实项目创建、SQLite、文件系统、持久化或重启恢复已经实现。
- 项目图标弹层的延迟、固定打开、会话搜索和新建入口，以及项目命名流程和真实创建失败行为仍未决定。
- 该行为当前没有稳定 `workspace-ui` Acceptance ID（验收编号）；原型检查只能作为发现证据。

## 最终纠正：工作台不是与交流并列的模式

用户随后明确指出，“工作台模式 / 交流模式”仍然是错误抽象。本节取代本文前面所有把二者描述为项目模式、保存每项目模式或提供顶栏模式切换的内容；前文保留为纠正过程的历史证据。

- CreatX 的普通项目状态就是完整 AI 会话，不存在需要用户选择的“交流模式”。
- 工作台是右侧注册文件夹的展开结果，不是与会话并列的模式；顶栏不提供“工作台 / 交流”切换。
- 当前界面只有一个权威展开状态：`activeWorkbench: null | folderId`。
- `activeWorkbench` 为空时，展开侧栏显示统一的项目与下属会话树，中央显示完整 AI 会话；侧栏折叠后改为项目方块栏，中央会话不变。
- 点击右侧某个注册文件夹时，该文件夹的工作台展开；展开期间项目导航压缩为项目方块栏，完整会话压缩为左侧当前 AI 对话。
- 再次点击当前注册文件夹或按 `Escape` 时收回工作台，并恢复此前的导航展开状态、当前项目、当前会话和会话草稿。
- 选择另一个项目或某个下属会话时，当前工作台收回，目标项目以完整会话状态打开；工作台展开状态不按项目分别自动恢复。
- 固定的 `文件 / 预览 / 侧聊` 仍属于可折叠右侧工具面板，不是注册文件夹，也不参与 `activeWorkbench` 状态。
- 窄桌面窗口只改变侧栏和工具面板的投影方式，不产生另一套产品状态，也不得清空当前草稿或选择。

## 后续补充：临时视觉调参工具

用户指出，当前视觉细节大量依赖语言描述，难以精确传达组件尺寸、间距和相对关系，因此接受先在可丢弃 Web Prototype（网页原型）中增加临时视觉调参模式。

- 该模式用于用户与 Agent 共同校准当前原型，不是已经接受的 CreatX 正式用户功能。
- 大部分主要组件应能通过可视控件调整尺寸、间距、颜色、显隐和有限的位置关系；关键分栏可以直接拖动。
- 调参过程需要撤销、重置、刷新暂存和 JSON 导出，便于把被用户接受的结果交给 Agent 固化。
- 临时调参 JSON 只是设计交接 Artifact（产物），不是正式皮肤、布局或项目文件 Schema（数据合同）。
- 不采用任意绝对定位保存整个 DOM；当前原型仍需保持响应式约束，避免一次视口下的调整破坏其他窗口尺寸。
