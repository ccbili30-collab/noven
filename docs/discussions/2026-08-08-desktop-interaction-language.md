# CreatX 桌面基础交互语言

状态：已确认。该记录补充并部分取代 `2026-08-08-chat-to-workbench-restoration.md` 中把工作台选择、导航展开和中央表面混为同一状态的早期解释。

## 用户纠正

用户不应反复为成熟桌面软件的基础行为作产品设计：项目、工作台和文件夹只要表达层级，就必须具有可预测的展开与折叠；同一对象再次点击应遵守其可见 Disclosure（展开）语义；文件点击后必须在中央打开；导航收起不能摧毁中央正在进行的工作。

此前实现把 `activeWorkbenchId` 同时用作工作台选择和文件列表展开状态，并把左侧目录渲染为静态标签；另一次修复又把项目导航收起错误地关联到退出 Workbench。这些都不是用户需要继续澄清的产品决策，而是交互模型缺失。

## 接受的基础规则

1. 展开、选中、打开和表面模式是四种独立状态。
2. 项目行只展开或折叠其工作台列表，不改变 Chat / Workbench 表面，不清空中央文件。
3. 第一次点击工作台时选中工作台、展开其资源并在中央打开真实首页或合理空态；再次点击当前工作台只折叠其资源，中央内容保持；再次展开恢复此前目录状态。
4. 每个目录拥有独立折叠状态。点击目录整行或箭头执行相同切换；点击文件打开中央内容，不折叠父目录。
5. 所有可展开项都投影真实 `aria-expanded`、方向图标、完整行命中区和键盘行为。静态文件夹图标不得冒充可交互目录。
6. 导航、面板和目录折叠不得丢失当前工作台、文件、编辑草稿、会话、流式状态、滚动位置或已保存宽度。
7. 相同外观必须表示相同动作。没有行为的品牌下拉、三点或其他按钮不得保留为可点击控件。
8. Menu（菜单）、Popover（浮层）和 Dialog（对话框）统一支持 Escape 关闭、外部点击策略、打开时聚焦和关闭后焦点返回；进行中的不可中断动作除外。
9. 异步操作统一显示 pending、成功、失败和可重试状态，并阻止重复触发。失败必须保留原工作状态。
10. 面板可连续拖动并保留安全范围；达到可读下限后进入折叠或紧凑模式，不继续把完整 AI 对话压成逐字换行。

## 产品决策边界

上述规则是 CreatX 的默认桌面交互语言，不再逐项请求用户确认。只有会改变创作流程、公开合同、权限、持久化或存在多个显著不同合理结果的行为，才需要用户作产品决策。

本批不改变 Runtime（运行时）、Cline Harness（智能体运行框架）、Provider（模型服务）、数据库或项目文件合同。Web Preview 与 Fixture（测试夹具）只能辅助视觉观察，不能作为真实交互完成证据。

## 2026-08-08 实现与证据

- `ProjectNavigation` 已把项目、工作台、目录、文件的展开状态与选中、中央打开、表面模式分离。项目再次点击只收起工作台列表；工作台再次点击只收起资源；目录按自身路径独立折叠；上述动作均不清除中央文件。
- 左侧工作台资源与保留的工作台目录栏复用 `WorkbenchResourceTree`，目录整行、方向图标、`aria-expanded`、鼠标与左右方向键使用同一状态转换；文件点击继续走现有真实打开和保存门禁。
- 项目菜单已统一外部点击、Escape、上下方向键、Home / End 和触发器焦点返回。项目重命名、永久删除、创意库分享和真实工具审批复用 `DesktopDialog` 的初始焦点、Tab 焦点锁定、Escape 策略、外部点击策略及关闭后焦点返回。审批的外部点击保持失败关闭，Escape 等价拒绝。
- 无行为的品牌下拉和 Chat 顶栏三点按钮已移除。Workbench 中 AI 对话宽度限制为 280–620px，默认 320px；窗口缩放时与项目栏、工作台栏一起按比例恢复，中央作品仍保留 300px 安全预算。
- Renderer 定向测试为 7/7、23 次断言；`bun run typecheck` 与 `bun run build` 通过。真实 Electron 自动验收两次通过本批菜单、Dialog、Chat / Workbench、目录、文件、编辑保存、会话保持、分隔线和 1360×860、900×700、860×620 窗口检查，随后均在范围外的 Skill Sequence 场景因 `session_conflict: conversation already has an active Owner turn` 停止；`pageErrors`、`consoleErrors`、`failedRequests` 均为空。因此本批 Renderer 交互范围有真实桌面证据，但全套 `test:desktop` 不标记通过，也没有调用真实 Provider。

异步动作的统一成功、失败和重试视觉仍是跨功能后续工作；本批只统一已经触及的分享 pending 门禁，不据此宣称全产品所有异步操作已经统一。
