# 诺文应用内重启恢复入口

## 用户观察

用户连续遇到会话历史读取 `EMFILE` 与艺术库联网采集失败。两类故障的精确根因尚未完成修复，但完整退出并重新打开诺文能够恢复当前使用。用户要求在软件内提供刷新按钮，减少人工关闭、查找和重新启动的成本。

## 已核对的技术边界

- 会话与 Cline 历史运行在受监督 Electron Utility Process（工具子进程）。
- 艺术库联网采集工具在 Electron Main（桌面主进程）执行。
- 仅刷新 Renderer（渲染层）不能释放上述两个进程的资源；仅重启 Utility Process 也不能覆盖 Main 中的艺术库故障。
- 当前产品只承诺应用重启后读取已持久化历史并开始新的回合；活动 Run（执行轮次）停止，不能自动重放 Provider（模型服务）请求或工具副作用。

## 用户确认的产品行为

2026-08-11 用户确认增加“恢复诺文”入口，真实行为是安全重启整个应用：

1. 展开和折叠的左下导航都可触发。
2. 空闲时直接重启。
3. 存在活动会话、工具、Growth（持续创作任务）或正在生成的图片时，先明确提示会中断且不会自动继续；用户二次确认后才重启。
4. 重启沿用既有退出门禁，先请求取消或暂停、关闭 Store（存储）并清理子进程，然后由 Electron 重新启动应用。
5. 重启后优先恢复触发前的项目与会话；目标已经删除或不可用时回退正常启动选择。
6. 不自动重发上一条消息、不自动批准工具、不把重启描述成 Bug 根因已经修复。

## 本批非目标

- 不修复 `EMFILE` 或艺术库网络错误分类。
- 不增加后台继续、托盘守护、自动崩溃重启或活动 Run 精确续接。
- 不修改 Cline Core（核心）或引入第二 Agent Harness（智能体运行框架）。
