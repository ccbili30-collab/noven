# 艺术库视觉整理质量升级讨论

日期：2026-08-10
状态：产品语义已确认并提升至能力规格
主能力线：Art Library（艺术库）

## 用户明确保留的主链

现有文件状态机保持不变：

`公网 / 对话附件 / 项目图片 → incoming → read_art_images → AI 整理 → approval → libraries`

本次不重做候选摄入、文件移动、人工批准或正式分类状态机。优化目标是 AI 真实看图后的整理质量，以及分类和人工修订所需的信息合同。

## 作品解读

`styleAnalysis` 应明确定义为面向用户的作品解读，不是生成 Prompt，也不是标签堆砌。

解读先识别主体与空间、色彩与明暗、构图与视角、留白、线条、形状、材质以及画面对象之间的关系，再把事实组织为可读、可适度诗意的解释。每条解读至少包含三个可回指当前图片的具体视觉依据。

禁止捏造作者意图、年代、流派或背景；禁止用空泛情绪词代替视觉分析；禁止多图复用同一模板。

## 结构化反推 Prompt

反推 Prompt 面向图像生成模型，目标是在不提供原图时仍能复现视觉语言。它必须区分：

- `STYLE`：媒介、渲染、色彩、形状、线条、边缘、光影和质感。
- `COMPOSITION`：画幅、版式、视角、主体比例、留白、景别层次和视觉节奏。
- `SCENE`：当前角色、物体、动作和环境，允许后续替换剧情。
- `NEGATIVE`：禁止的渲染方式、构图漂移、多余细节、Logo、水印和错误文字。

`STYLE + COMPOSITION + NEGATIVE` 必须可复用，`SCENE` 必须可替换。不得用艺术家、品牌、作品名或标题替代视觉描述，不确定信息不得编造。字段存在和字符串长度不能冒充质量证明。

## AI 整理顺序

1. 使用 `read_art_images` 真实读取图片。
2. 每张图片单独分析，区分可见事实、基于事实的解释和不确定信息。
3. 生成面向人的作品解读。
4. 生成面向模型的结构化反推 Prompt。
5. 提取 `patternTags`、`compositionTags`、`moodTags`；情绪标签必须有视觉依据。
6. 对照真实分类档案和代表作品建议分类。
7. 使用 `submit_art_approval` 进入审批，不自动批准。

## 分类信息缺口

`inspect_art_library` 不能只返回分类名和数量。分类前 AI 需要获得每类的风格关键词、简短风格档案，以及 2–4 个代表作品或代表视觉摘要。比较维度包括媒介与渲染、形状与边缘、色彩与光影、构图与空间、质感与情绪；题材相同不能单独构成同类依据。

### 2026-08-10 后续澄清：关键词是作品与库风格的基础材料

用户纠正了“显式人工维护分类档案”的解释：

- 每张图片由 AI 根据真实视觉自由填写关键词，不受预设词表限制。
- 用户可以逐个删除关键词，也可以自由添加自己的关键词。
- 单个分类的风格提取，以该分类全部作品的关键词为基础，由 AI 对整个作品库作综合解读并形成可复用 Prompt。
- 个人整体风格提取，以个人全部分类、全部作品的关键词为基础，综合出跨分类的个人风格解读和 Prompt。
- 因此，分类档案不能成为脱离作品关键词、另行维护的固定真相；库级解读和 Prompt 是基于当前作品集合重新生成的结果。

这与“分类前需要代表作品证据”并不冲突：代表作品或视觉摘要用于帮助 AI 判断新作品应进入哪个分类；库级风格提取的基础材料仍以作品关键词集合为主。

## 人工审批编辑范围

审批除标题、标签和分类外，还需允许修订：

- 作品解读。
- 结构化反推 Prompt。
- 色板。
- 负向约束。

审批后才进入正式分类；AI 不得自动批准。

## 旧数据边界

早期静态种子的 Prompt 含重复模板、标题拼接、艺术家姓名和品牌引用。最初方案是显示为 `legacy-unverified`，不得自动删除或静默重写。

当前代码证据表明静态种子共 63 条，其中 57 条已导入正式分类、6 条处于候审；三类为“纪念碑谷”“巨构艺术”“暖色风格”。种子元数据已有稳定 `seed` 标识，可用于兼容投影，避免猜测或批量改写用户数据。

### 2026-08-10 后续确认：丢弃旧整理结果并重新分析

用户明确替代前述只读兼容方案：

- 删除这 63 条种子的旧解读、Prompt、标签和分类结果。
- 保留 63 张原始图片及可信来源事实，作为新版方法的重新整理输入。
- 不删除用户后来从公网、对话附件或项目文件收藏的作品。
- 原图重新进入待整理路线，逐张真实视觉读取、生成新版元数据并进入人工审批；不得把旧元数据转换或伪装成新版结果。
- 实施和验收先使用隔离 Profile，不直接修改正式 Profile。

该决定属于有意的数据迁移：旧种子元数据和分类不可保留为产品事实，但原图必须先经哈希和数量核对后才能删除对应旧条目。若无法证明条目具有稳定 `seed` 标识，迁移必须失败关闭，不得按标题、分类名或目录位置猜测删除。

## 质量验收意图

按方法版本、分类和模型抽样：选择新作品，只看图生成解读和反推 Prompt；移除原图后替换 `SCENE` 并仅凭文字生成不同剧情的新图；由人检查视觉语言是否保持。若离开原图后明显漂移，则反推不合格。

结构、文件和工具测试只能证明合同与流程，不能替代真实视觉质量抽检。

## 已确认设计结论

- 新版使用结构化四层 Prompt 作为唯一权威，不与旧 `promptDraft` 双写。
- 单图解析固定产生作品解读、三组标签和四层反推 Prompt 三类结果。
- 工具合同强制一次只整理一张候选图。
- 分类判断读取当前标签与代表作品视觉摘要，不维护脱离作品的固定分类真相。
- 确定性导出关键词与 AI 按需提取分类/个人整体风格是两个独立能力。
- 库级提取结果默认不写回艺术库；每次按当前标签重新生成。
- 非种子旧用户条目兼容读取，只有真实重新看图并经人工审批后才升级新版结构。
