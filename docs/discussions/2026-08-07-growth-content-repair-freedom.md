# Growth 内容错误自动修复与安全绕过

## 用户问题

Growth 长跑中已经出现一种低效状态：内容 Worker 产生可编辑的正文错误后，Runtime（运行时）把对象锁进只读恢复或尝试次数阻塞；即使用户明确授权继续，Owner 仍只能调用不适用于当前对象状态的重试入口。错误持续显示为红色，但系统既不能自行修复，也不能安全绕过，最终把可局部处理的内容问题升级成整条主链停止。

用户要求 AI 在内容生产链中拥有足够的处理自由：能修就自动修，修不了但不影响其余世界时如实绕过；只有无法安全继续的系统级问题才等待人类。写作上的局部错误可以返工或缺失，但不得把失败伪装成成功。

## 已接受语义

1. 内容级错误优先由同一 Growth Run 自动处理，不要求用户重复点击继续。
2. `retry` 按原阶段重试；`repair` 允许 Writer 修改触发错误的当前对象；`accept` 接受已经存在且可验证的正文并重建缺失回执；`bypass` 如实保留缺失范围并继续其余对象。
3. 自动修复期间保持红色“正在自动修复”。只有对象形成可信持久证据后才转为绿色“已修复完成”；授权本身不是成功证据。
4. 安全绕过事务成功后显示绿色“已绕过”。两种绿色状态均停留 3 秒后消失，审计记录继续保存在 Growth Store。
5. 自动修复耗尽时，单个内容对象可以绕过；若该对象是其他未完成对象的必要上游，则同时绕过其依赖子树，并在 Owner 最终汇报中列出缺失范围。
6. 普通资料不足、非关键图片失败和局部内容校验失败不得轻易停止整条主链。项目身份错误、持久状态损坏、并发主任务冲突、正式完成回执覆盖风险和未知副作用重放仍失败关闭。

## 本次根因证据

- “在这个世界里”“本世界”曾被公开正文检查误判为外部创作框架。
- Writer 失败后，已有正文把 `blocked` 或 `retryable` 对象错误对账为 `unknown`。
- `resolve_growth_issue` 授权后只调用接受 `blocked` 的旧重试入口，因此 `unknown + block` 无法恢复。
- 事实抽取早于图片任务校验写入，形成“有 extraction、无正式 receipt”的半状态并阻止后续可信覆盖。

这些问题已提升为 `GRT-034`、`ACC-GRT-062` 与 Workspace UI 对应规则；代码和测试仍以能力规格与可执行测试为权威。
