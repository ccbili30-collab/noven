# 可导入、可理解的诺文项目包

## 新增产品方向

诺文项目不应只是一个文件夹。用户导出并分享项目后，接收方导入即可理解项目用途、当前成果、完整文件结构、用户与 AI 的协作方式、AI 的可见分析与工具活动、关键修正过程和最终结果。案例对话的价值是提供真实使用场景和经验，而不是复制旧模型的隐藏状态。

## 两个不同入口

### 打开文件夹

- 直接使用电脑上的现有目录。
- 只保证恢复真实文件。
- 不凭路径猜测、关联或恢复其他设备上的对话。

### 导入诺文项目

- 接收 Portable Project Package（便携项目包）。
- 恢复项目文件、目录结构、工作台配置和用户主动选择的案例对话。
- 不导入整个 Profile（配置档案）、Cline 数据库或用户全局设置。

## 建议逻辑结构

```text
project-package/
├─ manifest.json
├─ files/
├─ conversations/
├─ workbenches/
└─ checksums.json
```

- `files/` 是唯一项目内容权威。
- `conversations/` 只保存用户主动标记的案例对话。
- `workbenches/` 只保存显示、排序和可见范围设置，不成为第二份文件事实。
- `checksums.json` 用于识别损坏、不完整和重复导入。

物理容器已确定为扩展名 `.np` 的标准 ZIP。用户可见名称为“诺文项目包（.np）”。导入必须同时验证 ZIP 文件头、受支持的 `manifest.json` Schema（数据合同）和校验摘要，不能只凭后缀信任文件。压缩算法和 Canonical Serialization（规范序列化）的具体版本合同仍待设计。

### 已确认的 V1 完整性合同

- `manifest.json` 保存 `schemaVersion / projectId / forkedFromProjectId? / packageId`、项目简介、文件/案例/工作台数量、各交换记录版本、导出时间和导出诺文版本。
- `checksums.json` 为 `files/`、`conversations/` 和 `workbenches/` 中每个文件保存规范相对路径、字节数和 SHA-256。
- `packageId` 由项目身份、简介及全部净化内容摘要确定性生成。导出时间、ZIP 条目时间和压缩差异不参与，因此同内容重复导出得到相同身份。
- V1 只验证 Integrity（完整性），不验证发布者 Authenticity（真实性），不做作者签名或联网证书。导入界面明确显示“发布者未验证”。
- Checksum 通过不等于内容可信。导入不执行文件；HTML、JavaScript 和其他交互内容继续受现有隔离工作台边界约束，不因来自 `.np` 获得额外权限。

## 已确认的文件范围

“完整项目文件”指完整作品和源码，不等于复制开发环境缓存。第一版固定排除：

- `.git/`。
- `.creatx/` 原始内部记录；项目简介和工作台由各自权威 Store 生成净化交换记录。
- `node_modules/`。
- 诺文临时文件、未完成写入、Windows 缩略图和系统缓存。
- 指向项目根外的 Symbolic Link（符号链接）或 Junction（目录联接点）。第一版不跟随链接复制项目外字节。

导出窗口显示排除条目数量、总量和原因。普通隐藏文件、项目内图片、音视频、二进制作品和源码不因类型未知而擅自排除。可配置排除规则延期，避免第一版把密钥、缓存或巨量依赖误带入包。

## 已确认的身份规则

- `projectId` 是跨导出、跨设备保留的稳定项目血统身份，不由本机绝对路径决定。
- `packageId` 标识一次确定内容的项目包，并由规范内容摘要派生或绑定。
- 相同 `projectId + packageId` 重复导入是幂等命中，不重复解压、注册项目或导入案例。
- 相同 `projectId`、不同 `packageId` 表示同一项目血统的不同内容版本，必须提示冲突；第一版不猜测覆盖、合并或升级。
- 本机项目路径和 Runtime 使用的路径派生 Project ID 仍是现有实现事实；如何在不破坏现有项目关联的前提下保存 Portable Project Identity（便携项目身份），属于实现前架构合同。

### 已确认的身份冲突交互

- 相同 `projectId + packageId`：识别为同一包的重复导入，不重复创建目录、项目、案例或工作台；界面定位已有项目。
- 相同 `projectId`、不同 `packageId`：显示内容版本冲突，只提供“取消导入”和“作为独立副本导入”。
- “作为独立副本导入”生成新的稳定 `projectId`，并保存只读 `forkedFromProjectId` 指向来源血统；文件、案例与工作台进入用户选择的新目录。
- Project Catalog 另行保留原包 `importedProjectId + importedPackageId`。再次导入同一原包时定位已导入副本，不重复弹冲突；副本以后再导出则使用新的本地身份生成新包身份。
- 副本成立后与原项目独立，不自动同步、覆盖、合并或继承权限。第一版不提供升级、三方合并或差异应用。

## 已确认的产品入口

- 项目导航的“项目”标题操作区在现有“打开项目”旁增加明确的“导入/导出”入口。
- “打开项目”继续只选择现有文件夹；“导入诺文项目”只选择受支持的项目压缩包，两者不得混成一个自动猜测入口。
- 选择压缩包后由诺文完成校验、选择目标新目录、解压、解析、注册和加载；用户不需要手动解压或整理内部目录。
- 导出属于明确的当前项目动作；未打开项目时可以导入，但不能执行导出。
- 入口必须展示真实阶段和失败位置，不能在校验或解压完成前把项目显示为可用。

### 已确认的界面交互

- “项目”标题操作区使用一个明确的“导入/导出项目”按钮，窗口分为“导入诺文项目”和“导出当前项目”；没有当前项目时导出禁用，导入仍可用。
- 每条项目会话的 Hover（悬停）与键盘操作区提供“作为项目案例”开关，已标记者显示小型“案例”标签。
- 导出窗口列出同一项目全部会话和同一份案例开关；它不保存第二套一次性选择状态。案例标记必须由 Session（会话）关联事实持久化，不能放在 Renderer `localStorage`。
- 删除本地原会话时，其案例标记随会话删除；已经进入其他项目包的只读案例不受来源后续删除影响。
- 项目首页明确区分本地真实案例会话与包内导入的只读案例记录。

## 已确认的项目简介规则

- 导出窗口提供“项目用途、当前成果、使用说明”三个可编辑字段。
- 内容首次由用户填写；可以由用户显式点击“让 AI 起草”，但导出、导入和打开项目都不得自动调用 Provider（模型服务）。
- 简介通过受控项目元数据命令保存，并进入 `.np` 的 `manifest.json`；再次导出时自动带出，导入后的项目首页直接展示。
- 第一版不强制在项目根创建 `PROJECT.md`、`README.md` 或其他可见文件，避免仅为导出而修改用户作品目录。
- 项目简介不是作品文件或文件内容事实。Renderer（渲染层）不能直接写内部元数据；具体 Store（存储）所有权和 `.creatx` 内记录格式需在架构合同中冻结。
- “让 AI 起草”若后续实现，必须作为用户可见、可取消、可审阅的独立动作；失败只保留原表单，不阻止用户手工导出。

## 已确认的导入导出数据流

### 导出

1. 用户从项目标题旁的“导入/导出”进入“导出当前项目”。
2. 窗口展示项目简介、文件数量、总大小、案例对话列表和隐私范围；默认只选择已经标记为案例的会话。
3. 诺文从真实项目目录读取文件，从各自权威 Store 读取工作台与净化案例记录，在临时位置生成 `.np`。
4. Manifest、路径和 Checksum（校验摘要）复核全部通过后，原子改名为最终文件；失败不得留下可被误认成功的半包。

### 导入

1. 用户选择 `.np` 和一个新的目标目录。
2. 解压前检查 ZIP 文件头、版本、条目数量、声明大小、双身份、重复路径、路径穿越和校验清单。
3. 通过后解压到目标目录旁的 Staging Directory（暂存目录），再按真实字节校验。
4. 全部通过后才原子转为正式项目目录、注册项目并加载首页。
5. 任一阶段失败都不注册项目、不显示可用假象、不调用 Provider，并清理本批受控暂存目录。

第一版使用按钮选择 `.np`。未来拖入压缩包必须复用同一导入链，不能建立第二套校验或解压逻辑。

## 案例对话

- 每条项目会话提供“作为项目案例”开关；导出默认不包含任何未标记历史。
- 导出前显示文件数量、总大小、案例对话数量和隐私范围。
- 案例保留用户消息、AI 回复和用户可理解的工具活动摘要。
- 不包含 System Prompt（系统提示词）、隐藏上下文、原始工具参数、完整工具结果、模型密钥、Cookie 或个人配置。
- 对话引用的包内项目文件可通过现有工作台打开真实导入文件。
- 导入案例明确标记“来自导入项目”，默认只读。
- 导入历史不能成为工具授权、当前用户指令，不能修改个人画像或其他项目。

这与现有 `SES-502..505` 的默认无会话、逐条选择、净化导出和导入历史降权方向一致；本记录把“主动标记为案例”与导入后的只读产品形态进一步具体化。

### 已确认的案例交换格式

`conversations/<caseId>.json` 是版本化、净化后的只读展示记录，不是 Cline 原生会话副本。它只允许包含：

- 用户填写或确认的案例标题、用途和关键结论。
- 用户可见消息与 AI 最终回复。
- 白名单化、用户可理解的工具活动摘要，例如读取或修改哪个包内相对文件及其成功/失败结果。
- 指向 `files/` 内真实文件的相对引用。
- 用户确认过的 `continuationBrief`（继续创作说明）。

它明确排除隐藏思维链、System Prompt（系统提示词）、协议消息、压缩上下文、原始工具参数、命令全文、完整工具结果、未打包文件绝对路径、凭据、个人信息、Run、审批授权和任何可执行状态。工具摘要必须由版本化白名单投影生成，不能把未知工具原始内容透传到包中。

## 继续创作

- 导入的案例本身不继续写入。
- “以这个案例继续创作”创建新的本地项目会话，并读取当前真实项目文件。
- 原始案例保持只读且不被污染。
- 第一版不承诺复制旧模型内部上下文。
- 需要交给新会话的历史摘要必须明确、可审阅，并与导入历史隔离。
- `continuationBrief` 随案例记录保存。用户点击继续时先查看并可修改；确认后创建普通本地项目会话，把该说明作为第一条可见用户消息发送，新会话重新读取当前真实项目文件。
- 没有 `continuationBrief` 时必须先由用户手工填写。“让 AI 起草”只能由用户显式触发，结果必须可审阅；失败不污染案例，也不能静默发送空白或未经确认的说明。
- 案例记录永远保持只读。新会话不获得旧 Run、审批、工具结果或隐藏上下文。

## 导入后的项目首页

1. 项目简介：一句话用途、当前成果和使用说明。
2. 示例对话：展示被标记的真实协作案例，支持从消息打开项目文件，并提供“以这个案例继续创作”。
3. 项目文件：展示完整目录、作品和工作台。

项目简介读取已确认的受控项目元数据；导入成功不得临时调用 Provider 生成或补写。

### 已确认的界面位置

- 最右工作台导航新增系统入口“项目首页”，固定第一；现有固定内置“文件”调整为第二。
- 导入完成后自动展开工作台并打开项目首页。完全展开继续遵守“项目导航 / Chat / 工作台画布 / 工作台导航”的既有顺序，不为导入项目建立另一套布局。
- 打开案例中的项目文件引用时，中央画布切换到现有真实文件打开链；返回项目首页不重建 Chat、清空草稿或改变会话。
- 普通文件夹项目也能看到同一个系统入口。没有受控项目简介时只显示可编辑引导和真实文件概况，不自动调用 Provider、不根据目录名伪造用途。
- 本决定明确取代“内置文件工作台固定第一”的旧排序部分；文件内容权威、固定兜底和不可移除语义不变。正式提升时必须同步修订 `workspace-ui` 与工作台规格、验收和测试。

## 安全与失败边界

- 第一版只导入到用户选择的新目录，不覆盖或合并现有项目。
- 相同 Package（项目包）与相同内容重复导入应幂等识别。
- 相同项目身份但内容不同必须提示冲突，不猜测覆盖。
- 工作台元数据损坏时，真实文件仍可重建内置“文件”视图。
- 不导入活动 Run（运行记录）、排队或生成中的付费图片任务。
- 导入成功不自动调用 Provider（模型服务）。
- 不复制整个 Cline 数据库、诺文 Profile、凭据、Cookie 或用户全局设置。

### V1 普通 ZIP 容量边界补充

2026-08-10 在流式导出实施前发现，已选 `fflate 0.8.2` 的 ZIP 写入路径不生成 ZIP64 中央目录，而初始 Schema 的 100,000 条目、16 GB 总内容上限超过普通 ZIP 的可靠范围。用户确认第一版优先简单稳定，不增加 ZIP64 依赖：

- V1 最多声明 60,000 个项目文件与目录条目；加上三个逻辑根及 Manifest/Checksums 后仍低于普通 ZIP 的 65,535 条目上限。
- V1 未压缩项目内容总量最多 2 GB，单项仍不得超过 2 GB。
- 超限导出整体失败并说明原因，不截断、不漏文件、不降级生成部分包。
- 当前图文、小说、漫画、OC 和地图项目属于目标范围；大量原始视频、PSD、工程素材或本地模型可能超限。ZIP64 延期到出现真实大项目需求后再立项。

该补充收紧此前内部 Schema 常量，未形成已发布兼容承诺；它已提升到 `IEX-102 / ACC-IEX-105`。

### V1 导出位置与原子提交补充

真实 Windows 测试证明 Node `rename()` 会覆盖已经存在的同名目标，不能实现已接受的 create-only 提交。用户确认第一版默认把导出选择器定位到可写的 `D:\`；若设备没有可写 D 盘，则回退系统“文档”目录，用户仍可改选位置。

导出 Runtime 使用同目录完整临时文件和硬链接完成原子发布：普通 NTFS 盘可安全成功，同名目标绝不覆盖；不支持硬链接的 exFAT/FAT32 U 盘或部分网络盘明确失败并要求更换位置，不复制出可见半包。该限制优先于“所有盘都能直接保存”，以后若增加原生 create-only Move 能力再解除。

### V1 导入安全实施补充

Task 7 实施时确认，Windows 导入路径不能只拒绝绝对路径和 `..`，还必须拒绝设备名、尾随点/空格以及冒号 Alternate Data Stream（备用数据流），否则规范 ZIP 名称可能映射成不同的本机文件事实。该规则进入唯一 Checksums 路径 Schema，并同时用于导入中央目录预检。

为避免未签名包使用巨大 JSON 或极端压缩条目拖垮 Runtime，V1 对 Manifest、Checksums、单案例和单工作台设置 128 MB 结构化记录上限，并拒绝超过 1,000:1 的异常压缩比；普通项目文件仍保持单项 2 GB、总量 2 GB。导入案例写入项目受控 `.creatx/portable-project/cases/`，不进入 Cline 会话库；工作台继续通过既有 Workbench 写入者导入。

目录提交前失败只清理本批带受控标记的暂存目录。目录已经提交后若元数据或 Project Catalog 写入失败，保留用户文件并把项目内导入状态标为 `committed-unregistered`；调用方必须展示可恢复失败，不能伪称完整成功或删除目录。

## 当前代码事实

- 现有 `import-export` 实现面向隔离完整 Live 运行晋升，协调项目、Owner/Worker 会话、Growth 和图片任务进入同机正式 Profile；它不是通用便携项目包。
- 当前真实项目文件仍由 `project-files` 拥有；工作台只保存同一文件事实的显示与可见范围。
- Cline 继续拥有原生消息、Run 和工具事实。便携包中的案例记录必须是新的净化只读交换格式，不能冒充可恢复的 Cline 原生会话。
- `SES-502..505 / ACC-SES-504..508` 已保存默认无会话、逐条选择、普通分享净化和导入历史隔离方向；Task 1–7 已实现 Schema、导出和安全导入 Runtime，但 Desktop/UI、项目首页、继续创作与纵向 Electron 验收尚未实现。

## 实现前必须冻结

1. 物理容器、扩展名、版本兼容和规范校验合同。
2. Project Identity（项目身份）、Package Identity（项目包身份）与内容摘要的关系。
3. 案例对话导出 Schema（数据合同）、工具活动摘要白名单和文件引用合同。
4. 项目简介的权威来源与编辑方式。
5. “以案例继续创作”的可审阅摘要生成、失败和无 Provider 行为。
6. 新目录选择、重复导入、身份冲突、部分损坏和中断恢复语义。
7. `import-export` 主验收矩阵，以及 `session / project-files / workspace-ui` 的相邻合同。
