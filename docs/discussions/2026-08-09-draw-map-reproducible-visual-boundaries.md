# Draw Map 清晰底图与可复现视觉边界

## 用户纠正

战锤 40K 星图首次示例暴露出三个问题：区域只有六块；圆、椭圆和多边形使边缘过于平滑；蒙版只粗略覆盖宏观位置，没有沿底图已经生成的可见边界。用户确认所有疆域地块应抬升，大裂隙和外层虚空只原位高亮，并把“边缘不要太平滑、必须贴合底图”定为重点。

第二版以同一高清底图为视觉权威，给可见疆域放置内部种子点，再用图像梯度和标记分水岭反推边界。区域由 6 个增加到 25 个，其中 23 个疆域可抬升；内部边界平均图像梯度为地块内部的 2.01 倍。真实浏览器逐区选择通过，平均首次选择为 46 ms。用户确认该效果符合预期，并要求把方法记录进正式 Skill，证明第二次也能生成。

## 稳定结论

1. 图片模型只负责清晰、无文字、无界面的视觉底图；不得同时承担精确 ID 蒙版。
2. 清晰度不是 Prompt 声明。Agent 必须真实读图，确定边界闭合、区域可辨、无文字或 UI；脚本同时检查分辨率、透明度、动态范围和边缘密度。不合格底图重试或失败关闭。
3. 视觉优先路线用区域内部种子点加确定性标记分水岭生成同尺寸蒙版。禁止用圆、椭圆、泰森网格或少量手绘多边形冒充对底图的贴合。
4. 脚本必须输出配准审查图和边界贴合指标；低于门禁时不构建交互成品。
5. 所有疆域是 `land` 并抬升；大裂隙、海洋、外层虚空等巨大非疆域区域原位高亮。
6. Viewer 只缓存当前选择区域，避免高清多区域地图为每个区域永久保留多张全尺寸 Canvas。
7. Provider 有随机性，因此不能保证每次第一次生成就清晰；正式保证是最多有界重试并失败关闭，不让劣质底图进入后续链路。

## 非目标

- 不宣称视觉分区等于官方地理或行政边界。
- 不提供手绘边界、GIS、边界拖动或专用地图编辑器。
- 不把第一次成功底图、坐标或蒙版作为第二次复验输入。

## 第二题材复验结果

2026-08-10 使用全新冰环火山群岛底图、32 个新区域和新坐标完成第二次真实 Provider 前向复验。首次错误种子被最小区域门禁拒绝；数值通过后，配准图又发现两个卫星岛被海洋抢占，按内部视觉盆地补种并移除靠边种子后通过。最终边界/内部梯度比为 3.214，Edge 逐区 32/32 点击、陆地抬升、水域原位、三种关闭、拖动和当前区域缓存通过，浏览器错误为 0。完整证据与限制提升到 `docs/baseline/creatx-draw-map-v25-visual-boundaries-2026-08-10.md`。
