# 传承库与工作台导航统一修复发现记录

## 用户发现

本批统一处理三个问题：

1. 传承库现有素材方向分散且不少条目只根据标题推测内容。内置素材应大致平均围绕 `OC创作`、`艺术欣赏`、`世界观`、`图画创作`。
2. Workbench（工作台）中央画布与最右工作台导航之间的分隔线不能拖动。源码中 `workbench-canvas` 被显式禁用，已有宽度调整函数未接入交互。
3. 对话中的项目图片和项目相对 Markdown 链接不可操作。点击后应自动展开工作台并展示真实项目文件；`文件.md#标题` 应进一步定位到该标题。

## 已确认语义

- 内置传承库保持 20 条，四类各 5 条；目录由版本化 JSON 驱动，不再由页面硬编码分类。
- 用户导入、喜欢和收藏继续保存在个人 Profile（配置目录），升级不能覆盖。
- 素材来源不强制平台配额。中文方法内容优先稳定且可核验的来源；艺术欣赏允许博物馆、美术馆、艺术家官网等来源。不能把标题推测写成已完成分析。
- `workbench-canvas` 支持鼠标拖动和键盘方向键，调整最右工作台导航宽度；中央画布保持至少约 300px，宽度继续使用既有本机偏好持久化。
- 对话项目图片与相对链接复用现有 `openWorkbenchFile` 链，继续经过未保存草稿门禁。
- 相对 Markdown 文件链接只解析当前项目 `ProjectSnapshot` 中真实存在的文件；绝对路径、`file://`、路径穿越和不存在文件失败关闭。
- 外部 `https://` 链接不进入工作台。本批不新增网页嵌入语义。
- `文件.md#标题` 打开文件后定位到匹配标题；点击行为不清除对话、草稿、Run（运行）或滚动。
- 临时聊天附件继续使用既有大图预览，不按名称猜测成项目文件。

## 非目标与停止条件

- 不新增任意绝对路径 IPC（进程间通信）。
- 不建立第二套项目文件数据库，也不复制聊天附件进项目。
- 不改变 Provider（模型服务）协议或 Cline 历史。
- 若标题定位需要绕过真实文件打开链，或传承库数据迁移会覆盖用户 Profile，则停止实现并重新评估。

本记录保存用户语义；权威产品规则提升到 `workspace-ui/product-spec.md`，验收提升到 `workspace-ui/acceptance.md`。
