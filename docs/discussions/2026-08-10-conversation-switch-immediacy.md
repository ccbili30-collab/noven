# 对话切换即时性与路由完整性

日期：2026-08-10  
主能力线：Workspace UI（工作区界面）  
状态：用户语义已确认并提升到 `WUI-050 / ACC-WUI-072`

## 用户报告与纠正

用户报告点击其他对话后长时间没有切换，等待期间发送会串入旧对话。初步修复建议把“切换期间禁止发送”放在首位，用户明确纠正：主要问题首先是会话本身应该快速打开。

接受后的产品含义是：点击会话后，Chat（对话）身份和可见内容必须先切换；项目扫描、Growth Goal（生长目标）和 Workbench（工作台）投影不得阻塞 Chat。防止消息进入旧会话是同一事务的安全不变量，不是用长时间禁用 Composer（输入区）替代快速切换。

## 复现证据

修复前的隔离 Electron（桌面壳）使用两个项目和两个真实 Cline 会话。目标项目包含 1,500 个 Markdown 文件，以稳定放大项目读取窗口。点击 B 后立刻发送唯一消息：

- 界面约 726 ms 后才显示 B；
- Provider（模型服务）收到一次真实请求；
- 消息持久写入 A 的 Timeline（时间线）；
- B 的 Timeline 没有该消息。

正式 Profile 只读扫描另行确认最大约 19 MB 的历史读取、解析和投影约 67–82 ms，不能单独解释长时间等待。该 Profile 证据没有修改用户数据，也不证明每个正式项目的项目扫描耗时。

## 根因

1. 无脏编辑器时，`WorkspaceShell` 仍通过已完成 Promise 延迟导航动作。
2. 跨项目 `selectSession` 在更新会话 ID 前等待项目扫描、Growth 和工作台读取。
3. 新 Timeline 返回前继续挂载旧 Timeline。
4. Composer 发送读取 React 上一帧的 `sessionId`，而不是用户刚选择的目标身份。
5. 多次快速选择没有统一 Epoch（世代标识）和后台项目打开序列，旧结果可能晚到。

## 接受的不变量

- 无需保存时，会话点击同步进入选择逻辑；脏编辑器仍先走原有保存事务，失败时不离开。
- 下一次渲染必须显示目标会话身份，旧 Timeline 立即卸载；历史未到时显示有界加载状态。
- Timeline 与项目投影并行读取；Growth 和工作台在项目核心打开后后台补齐。
- 发送、Steer（追加指令）与 Skill Sequence（技能序列）都按立即更新的目标 Session ID（会话标识）路由。
- 快速 A→B→C 只允许最新选择提交项目投影；项目打开在 Main（主进程）中串行，避免全局当前项目被旧完成结果覆盖。
- 同一会话的重复点击不清空 Timeline，也不重新消费打开后的一次性底部定位。

## 明确边界

- 不新增消息数据库、持久 UI 缓存或公开协议。
- 不改变脏编辑器保存失败关闭语义。
- 本批不优化 Main 的真实文件扫描算法；Chat 不再等待它，但工作台投影仍受项目规模影响。
