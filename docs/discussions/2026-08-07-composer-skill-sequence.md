# Composer Skill 序列讨论记录

日期：2026-08-07

状态：产品语义已由用户确认，进入第一版实现。

## 用户意图

用户需要的不是节点画布、固定世界流水线或把多份 Skill 合并成一个巨型 Skill，而是挂在对话输入框上沿的一个小型 Skill 挂篮。关闭时只显示一个很小的挂签，点击后向上展开。

- 用户在正常对话框中写唯一任务，例如“根据以上文本，依次调用这些 Skill 做出内容”。
- 挂篮只选择 Skill、执行顺序和纳入序列的插槽，不替用户编造五份阶段任务。
- 每条插槽有独立选择状态；未选择插槽继续留在当前会话的挂篮中。挂签旁另有一个独立的“启用下一次发送”勾选按钮，只有明确勾上它，已选择插槽才随下一条消息发送。
- 总启用按钮是一次性状态：消息真正提交时立即自动取消，不等待多轮任务结束；插槽、顺序和逐槽选择状态保持不变。切换会话时也取消临时启用。
- 发送一次后，系统按序为同一个 AI 会话安排多轮执行；每轮加载一个 Skill，并基于同一会话上文和前轮真实项目产物继续。
- 对话中只保留一条正式用户消息，不伪造多条用户指令。
- Skill 是方法，不是任务；用户原话始终是任务权威。
- 同一会话的序列不因发送而清空。切换会话时加载目标会话自己的序列；新会话默认空，切回原会话恢复原序列。

## 第一版边界

1. 只允许 CreatX 当前正式安装并声明可排队的普通创作 Skill；Growth 路线不能嵌套进入序列。
2. 普通发送路径不变；只有至少一个插槽已选择且一次性总启用按钮已勾选时才显式触发多轮。
3. 首轮保存原始用户消息；后续轮次使用可识别、默认不投影为用户消息的内部续轮标记。
4. 每轮仍是 Cline 独占的真实 Run，使用当前会话权限和工具；序列不提升权限。
5. 任一轮失败或取消立即停止后续轮次，已完成文件和回复保留，不伪装整体成功。
6. 第一版序列配置由 Renderer 按会话本机保存；发送时把冻结快照交给 Main 校验。
7. 第一版不承诺应用退出后自动从精确槽位续跑，不建立第二套消息库、Run 数据库或独立 Agent Harness。

## 当前正式可排队 Skill

- `creatx-novel-start`
- `creatx-study`
- `creatx-draw-map`
- `creatx-draw-comic`

因果 Skill 尚未形成生产安装，`creatx-oc-pro` 仍是候选单角色能力，因此二者不能以假入口出现在第一版选择器中。后续只需进入同一个可排队 Skill 注册表即可扩展，不修改序列调度器。

## 交互要求

- 输入框仍是主表面；关闭态只保留挂在输入框上沿的小挂签，点击后挂篮向上展开，不占用输入框旁的常驻横向空间。
- 增加、逐槽选择、一次性启用、Skill 选择、删除和上下移动均有鼠标与键盘可达入口，不能只靠拖动。
- 发送开始后冻结本次序列；运行中可以查看但不能改变正在执行的快照。
- 空挂篮、全部未选择或总启用未勾选时发送等同现有普通聊天；一个已选择 Skill 也走同一序列合同。

## 解释纠正

最初的“输入框旁的小框”表述已被用户后续纠正。它不能实现为常驻侧框，也不能因为插槽存在就自动发送全部内容；2026-08-08 的进一步纠正明确区分“逐槽选择”和“本次启用”。当前权威交互是“输入框上沿挂签 + 向上展开挂篮 + 每槽独立选择 + 一次性总启用按钮”。
