# CreatX 第一版功能优先级修正

## 1. 修正原因

在检查 OpenHands 薄接入风险后，用户明确：CreatX 不应为了理想化权限、特殊会话、后台生命或长期记忆深入修改 Harness（智能体运行框架），更不能让这些次要能力再次拖累比赛版核心创作体验。第一版最重要的是先把真实工具基础与华丽、可见、可创作的产品能力做出来。

本记录取代此前把四档权限、Living 零工具、特殊会话关系、后台继续和长期记忆视为第一版硬门槛的解释。旧文档保留为未来理想设计和讨论证据，不再自动阻塞 Harness 选择或第一版创作闭环。

后续取代说明（2026-07-28）：ADR-0009 进一步接受“审批 / 自由”两种直接切换、新会话默认自由和 Growth 全自动执行，因此本记录中“第一版只使用逐次审批”的结论只描述已完成骨架，不再是当前产品目标。四档权限、后台继续、Living 零工具、特殊会话和长期记忆仍然延期。

## 2. 已接受的第一版优先级

### 2.1 工具层是基础

- Agent 必须能够调用真实文件、图片和其他创作工具，并得到真实成功或失败结果。
- 创作工具继续遵守所选 Harness 的正常权限与确认机制。
- 不允许用只返回“已派发”的前端假工具冒充生图、文件写入或工作台注册完成。
- 精确崩溃续接、Exactly Once（严格一次）副作用和复杂结果未知治理可以延期；第一版至少不能把当前已知失败显示成成功。

### 2.2 四档权限延期

- 计划、审批、协作、自由四档保留为理想产品方向，不是第一版 Harness 硬门槛。
- 第一版直接采用所选 Harness 已有的普通权限模式和审批体验。
- 不为还原四档而修改 Agent 核心、工具注册状态机或持久化格式。

### 2.3 特殊会话关系延期

- 压缩继承、个人会话完整复制转移、十分钟侧聊、精炼回传和会话家族不是第一版要求。
- 第一版只需要所选 Harness 已经可靠提供的普通新建、继续、历史和项目会话能力。
- 某项特殊关系如果可以通过公开接口低成本增加，可以以后单独恢复；做不出来就不做，不阻塞其他创作功能。

### 2.4 后台生命延期

- 关闭 UI 后继续运行、托盘守护、崩溃重连和复杂 Sidecar（伴随进程）恢复属于使用增强，不是第一版硬门槛。
- 如果后台生命容易造成残留进程、状态错位或恢复 Bug，第一版允许应用关闭时停止任务。
- 正常前台使用仍需明确显示当前运行、成功和失败，不能以“后台以后会恢复”掩盖当前错误。

### 2.5 长期记忆延期

- 个人画像、项目画像、跨项目蒸馏和后台复盘对短期用户没有决定性影响，不进入第一版。
- 第一版依赖当前会话上下文、真实项目文件和所选 Harness 自带的普通压缩能力。
- 长期记忆设计保留，但不能成为创作工作台、地图、图片、Growth 或 Study 的前置条件。

### 2.6 Living 简化为角色扮演

- `/living` 第一版只是强制代入视角的 Cosplay（角色扮演）Skill。
- Living 不再切换 Runtime 工具集，也不要求零工具状态。
- Living 不提升权限；角色能否调用工具完全沿用当前普通会话权限。
- 角色自称系统、管理员或觉醒 AI 不产生额外授权，但第一版不为此增加专用安全状态机。
- `/unliving`、继续最近视角和项目角色参考仍可作为普通 Skill 行为实现。

## 3. 第一版 Harness 选择标准

### 必须具备

1. 前端可以替换或稳定嵌入。
2. 普通 Conversation（会话）、消息流、历史和项目工作区可用。
3. 真实工具调用能够等待并返回真实结果。
4. 文件、终端、浏览或等价 Coding Agent（编码智能体）基础工具可用。
5. 可以增加 Skill、Plugin（插件）、MCP（模型上下文协议工具）或等价扩展。
6. 支持需要的 Provider（模型服务），并能在 Windows 上正常启动和使用。

### 加分但不阻塞

- 四档权限。
- 动态工具 Allowlist（允许列表）。
- 特殊会话继承与侧聊。
- UI 关闭后后台继续。
- 精确崩溃恢复与严格一次副作用。
- 长期记忆。
- Living 零工具沙箱。

## 4. 第一版实现方向

第一条目标应尽快证明：

```text
自定义 CreatX 前端
→ 选定 Harness 与真实 Provider
→ 真实创作工具
→ 生成或修改项目文件
→ 工作台展示同一文件
→ 用户继续编辑和创作
```

随后优先恢复比赛版最有感知的能力：世界观、OC、小说、Study、Growth、生图、地图、图谱和动态工作台。复杂基础设施只在真实使用证明必要时增加。

## 5. 不代表什么

- 不代表放弃工具正确性、项目路径边界或真实文件。
- 不代表允许 Mock（模拟）或 Fixture（测试夹具）冒充 Live（真实运行）。
- 不代表 OpenHands 已被选中；Cline、Goose、干净上游 OpenCode 或其他 Harness 仍需按简化标准比较。
- 不代表旧理想设计错误；它们只是从第一版必需项降为未来可选项。
