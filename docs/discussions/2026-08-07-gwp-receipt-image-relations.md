# GWP 回执驱动的正文图片关系

## 用户意图

Growth World Pro（世界生成高级模式）完成一篇正文并提交配图任务后，图片成功时应自动进入对应正文。用户不应逐篇补链接，也不应依赖 Writer 自觉重复填写正文路径。工作台读取真实 Markdown 图片引用展示图文关系，不保存永久 HTML 正文副本。

图片任务需要按项目隔离并保持项目内单队列。失败任务的“重试”进入项目队尾；“跳到最后”只适用于尚未开始的排队任务；“取消”永久放弃当前任务并继续下一项。界面按生成中、等待、失败待处理和短暂终态反馈分区，失败原因必须直接可见。

## 已核对事实

- `WorldMaterializationReceipt` 已持久保存 `artifactPath` 与 `imageTaskId`。
- GWP 完成对象时已经验证图片目标路径为正文同目录下的 `图片/<正文文件名>.png`。
- 图片任务表已经拥有可选挂接字段，第一版无需升级数据库 Schema（数据合同）。
- `ImageAttachmentService` 已是标准 Markdown 图片引用的唯一写入实现，并具备文件版本冲突门禁。
- 现有 Writer Prompt 仍要求 Worker 手工提交 `attachment`，历史完整世界的任务因此可能没有挂接意图。

## 接受的决定

1. GWP 的正文—图片生成关系以物化回执为唯一权威；图片任务的挂接字段是可执行意图，不是第二份内容事实。
2. Runtime（运行时）从回执派生挂接意图：正文为 `artifactPath`，图片任务为 `imageTaskId`，替代 Worker 手工复制。
3. 图片已经成功时，后到的回执立即触发挂接；回执先到时，图片成功后触发挂接。
4. 应用打开项目时扫描该项目正式 GWP 回执并幂等对账，恢复旧项目缺失的挂接意图。
5. 已绑定到不同正文的任务失败关闭，绝不覆盖；没有回执的游离任务不猜测、不自动绑定。
6. 图片成功与正文挂接成功分别持久化。挂接失败不改写图片成功，也不阻塞文字主链；本次讨论原先要求最终 Owner 汇报披露全部挂接失败。
7. Markdown 图片引用是工作台的内容投影权威。HTML 只用于隔离交互作品或按需导出。

## 明确不做

- 不升级图片队列 Schema。
- 不修改正式运行数据库或现有作品文件来模拟迁移结果。
- 不按同名文件、目录邻近或图片 Prompt 猜测关系。
- 不建立图片—正文关系表、HTML 正文副本或第二套工作台内容模型。
- 不让普通独立生图自动选择文章；其关系仍由显式挂接意图决定。

## 已知一致性边界

GWP 回执和图片队列分属不同持久 Store（存储），无法形成跨数据库原子事务。系统采用“先保存回执，再幂等绑定与对账”的最终一致性：任何中断都可以从持久回执重放；重复重放不应重复插图或改变已有正确关系。

## 后续澄清

`2026-08-07-silent-image-attachment-mismatch.md` 后续取代了“披露全部挂接失败”的范围：只有 `image_attachment_conflict` 这类位置不匹配静默保留为内部证据；其他挂接故障继续向用户披露。
