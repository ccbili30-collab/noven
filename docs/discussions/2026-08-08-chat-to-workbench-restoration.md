# Chat 到 Workbench 的项目恢复语义

状态：已确认产品意图。2026-08-08 第一生产批次已开始把项目导航改为工作台入口，并把右侧项目工作台拆为会话列表与文件树；本批追加确认移除常驻检查器，改为按需详情抽屉。

## 用户意图

CreatX 不应把“Chat 优先”解释成每次打开项目都回到全宽对话。项目具有从讨论到创作的自然阶段：

1. 首次打开尚未形成作品的新项目时，以 Chat 为第一表面。
2. 用户或 AI 打开、生成或编辑作品后，项目进入 Workbench（工作台）状态。
3. 此后重新打开该项目，应恢复上次工作台、文件、滚动位置和安全范围内的面板宽度，而不是强制回到 Chat。
4. 成熟项目中新建会话时，保持当前作品打开，在辅助 AI 侧栏中开始空白会话；只有用户显式选择全宽 Chat 时才离开作品主表面。

该语义使 Chat 是项目开始时的主入口，Workbench 是持续创作时的主环境，两者不是永久互斥的页面。

## 已接受的布局方向

参考 VS Code 式职责分区，但不复制其按钮：应用/项目导航、单一工作台文件侧栏、中央作品画布、右侧 AI 对话。项目树与文件树不得重复表达同一层级；Growth、图片任务、权限、模型和 Composer 继续使用 CreatX 自己的真实功能。

2026-08-08 进一步确认会话与项目的导航关系：

1. 项目展开后直接展示下属工作台，不再展示会话列表。
2. Chat 表面由左侧项目/工作台导航和占满主区的对话组成；会话在对话顶部切换。
3. Workbench 表面由项目活动栏、工作台文件树、中央作品画布和右侧 AI 对话组成；会话仍在右侧对话顶部切换。
4. Chat 与 Workbench 复用同一个逻辑对话实例。切换表面不应重建草稿、流式输出、当前会话或滚动状态。
5. “对话不再跟项目绑定”在本轮仅指导航不再隶属于项目树。底层会话继续保留真实 `projectId`，以维持文件权限、工具边界与历史恢复；是否允许在工作台右侧切换到其他项目或个人会话，是后续生产规格需要明确的行为。

2026-08-08 用户进一步确认：

6. 常驻“检查器”不属于作品主表面，应从默认 DOM 和视觉层级中移除；文件元数据、模型/权限/运行状态和 Growth 信息不得继续混在一张永久浮卡中。
7. 工作台入口点击后必须直接进入工作台首页、最近文件或真实作品，不能先展开成文件树再等待第二次点击。
8. 左侧工作台入口使用平级创作空间卡片表达，不使用会话行或文件夹式缩进；文件层级只在右侧文件区表达。
9. 详情能力保留为工作台标题栏的按需入口，打开后可关闭，不重建会话、文件、编辑草稿或流式状态。
10. 用户进一步确认最终 Workbench 采用 VSCode 式三列：左侧工作台与文件资源，中间作品画布，最右侧 AI 对话；Chat 模式不显示最右侧 AI 重复栏或作品画布。
11. 用户补充确认：注册工作台只负责展览，不展开或管理下属文件；文件树属于独立的“文件”入口。本批只调整表面布局，不重新定义文件与 AI 的业务归属。

## 当前边界

- `chat-studio` 与 `reference-studio` 两个 Preview 变体和 Fixture（测试夹具）只用于并列验证 Chat / Workbench，不是生产证据。
- Preview 继续复用生产 `WorkspaceShell` 和 CSS，不建立第二套 UI Runtime（界面运行时）。
- `WUI-028` 中“切换会话后默认进入 Chat”的旧规则已被本次确认取代：生产布局启用新语义时，会话切换不得清除当前工作台、文件或画布状态；旧默认只作为显式兼容路径保留，不能再代表 CreatX 生产行为。
- 项目恢复状态应属于本机 UI 偏好还是项目级产品事实，尚需在生产设计批次中根据跨窗口、跨会话和项目迁移行为决定。

## 后续交互语言纠正

用户随后明确纠正了“注册工作台不展开资源”和“导航折叠退出 Workbench”的解释。最新权威规则见 `2026-08-08-desktop-interaction-language.md`：工作台选择、资源展开、文件打开和 Chat / Workbench 表面必须独立；当前工作台再次点击只折叠其资源，中央内容保持；项目行只折叠工作台列表；所有目录都必须逐级展开折叠。该规则取代本文第 8、11 条及仅为内置“文件”工作台保留资源展开的结论，保留本文作为讨论演进记录。
