# 注册工作台 V1 纵向闭环发现记录

## 1. 本轮目标

六线共享接口完成后，不立即创建多个 Worktree（工作树），而是选择 CreatX 区别于普通 Coding Agent（编码智能体）的第一条真实能力：把现有项目文件夹注册为工作台，并在真实 Electron、Cline、审批、文件和重启链中验收。

本轮只冻结产品行为、最小 `.creatx` Schema（数据合同）、Acceptance（验收）和集成顺序，不实现生产代码。

## 2. 已接受的用户故事

第一条纵向故事收窄为：

> 用户在项目会话中要求 AI 把一个现有文件夹注册为工作台；AI 调用真实 `register_workbench` 工具，用户批准后工作台立即出现，退出并重启应用后仍能恢复。

首批不增加“手动注册”按钮。用户主动注册通过与 AI 对话完成；直接在界面选择文件夹并注册属于后续独立批次。

## 3. 内置“文件”工作台

用户打开或创建项目时，界面自动拥有第一个工作台“文件”。产品语言可以称为自动注册，但技术上它是系统生成的 Built-in Workbench Projection（内置工作台投影）：

- 固定 ID 为保留命名空间中的 `builtin:files`；
- 固定排在工作台标签区第一位，不能删除；
- 直接展示项目真实文件与文件夹，并使用 Project Files（项目文件）能力拥有的统一隐藏规则；
- 不创建 `.creatx`、不调用 `register_workbench`，也不在首次打开项目时产生隐藏写入；
- `.creatx` 丢失、损坏或版本不支持时仍然存在并可用。

持久化记录禁止使用 `builtin:*` ID。这样内置工作台与用户/AI 注册记录不会形成同一份数据的两个权威。

## 4. 注册工作台 V1 表现

第一版只提供一个内置通用文件夹视图：

- 顶部显示工作台名称和项目相对文件夹路径；
- 下方按真实子目录层级分组展示该文件夹子树中的文件；
- 文件仍使用与窄文件面板和预览相同的真实文件身份；
- 不保存 `template`、`layout`、封面、图标、页面、组件或内容类型；
- 用户未指定名称时，标题取文件夹路径的最后一级名称。

“文件/预览”继续是窄幅辅助入口；内置“文件”和注册工作台属于独立工作台标签区。点击工作台标签展开通用工作台，再次点击收回，主聊天保持可见。

## 5. 失败行为

- 同一规范化文件夹最多一条有效注册。重复请求返回已有记录，不重写 JSON，也不改变文件修改时间。
- 有效记录引用的文件夹不存在时，保留工作台标签、标题和原路径，明确显示“文件夹缺失”；不猜测新路径、不自动删除或重新绑定。
- 单条 JSON 损坏、字段非法或版本不支持时，跳过该记录并产生项目级非阻塞诊断；不能让整个工作台注册表或内置“文件”失效。
- 多条有效 JSON 指向同一文件夹时，不选择任意赢家；冲突记录不投影为可用工作台，并产生明确诊断。
- 用户拒绝审批、工具取消、路径非法、文件夹不存在或元数据写入失败时，不产生注册成功回执，也不移动任何项目内容。

## 6. 已确认的工程缺口

现有共享 Port（端口）不能单独完成该故事：

- `ProjectFileQueryPort` 只能扫描文件、预览和按路径读字节，不能验证空文件夹或枚举隐藏的 `.creatx/workbenches/`；
- `ProjectFileCommandPort` 不能表达“仅当目标不存在时创建”，无法用合同阻止极低概率 ID 碰撞覆盖；
- Desktop API（桌面接口）没有工作台 Projection（投影）查询；
- Renderer 只有窄幅“文件/预览”，没有独立工作台标签区和通用文件夹工作台表面。

因此第一条实现必须继续由 `creat1` 集成线完成这些最小合同变化。不能让 Workbench Package 读取绝对项目根、直接访问文件系统，或用单一 `workbenches.json` 绕过接口缺口。

## 7. 明确非目标

- 图片 Provider（模型服务）、封面和图库候选；
- 小说、世界、角色等模板和固定内容类型；
- 复杂布局、页面、组件组合和自定义 Renderer；
- Watcher（监听器）、自动修复外部重命名、版本历史和回收站；
- 工作台改名、重新定位、删除注册和手动注册按钮；
- 多个 Creative Skill（创作技能）或 Creative Plugin 的通用包装。

## 9. Live 后的具体创作项目故事

用户进一步把首条通用注册能力具体化为：

> 用户要求 AI 创建一个名为“小说”的创作项目。AI 创建 `小说/大纲.md` 和 `小说/第一章.md`，注册“小说”工作台；用户能在工作台看到目录和文件，点击文件后在右侧预览真实内容，重启后仍然存在。

这里的“创作项目”仍指当前 CreatX 项目内的真实子目录和注册工作台，不是新建第二个顶层 CreatX 项目。该故事不要求小说专用 Schema、模板或固定正文；文件由 Cline 原生编辑工具创建，工作台继续只注册与投影真实目录。
