# Skill Sequence 真实运行中断与恢复讨论

## 现场

2026-08-08，正式 CreatX 0.1.8 在同一项目会话执行“研究 → 地图 → 人物 → 小说 → 漫画”挂篮序列。研究完成，地图生成并验证了 `1254×1254` 底图，随后序列停止；人物、小说和漫画没有启动。

权威 Cline Hook（钩子）时间线为：

- `03:29:44.479Z`：恢复旧会话时，旧 PID `47296` 被 `stale_session_reconciler` 标记为退出。
- `03:29:45.117Z`：地图轮开始。
- `03:32:31.209Z`：地图第十二次工具调用成功，底图尺寸验证完成。
- `03:32:31.221Z`：首个真实执行错误为 `Agent runtime exceeded maxIterations (12)`。
- `03:32:31.388Z`：同一旧 PID 再次被收束，形成第二个误导性错误。

因此本次中断不是地图、图片 Provider 或合并删除 Skill 导致。第一根因是普通 Session 的固定十二次 Agent 迭代预算不足以完成地图生产合同；第二根因是恢复 Session 没有把执行所有权从旧进程转移给当前 Electron Main Process（主进程），导致错误收尾被旧 PID 污染。

## 已接受产品语义

1. 用户原话仍是唯一正式任务消息。Skill 序列的内部续轮不得伪装成新的用户发言。
2. `maxIterations` 触顶代表当前执行片段预算耗尽，不等于作品失败。系统应读取同一 Cline 历史和真实文件，自动继续当前 Skill。
3. 第一版每个 Skill 最多使用四个十二次执行片段。前三次触顶属于自动恢复过程；第四次仍未完成时，当前 Skill 标记为需要人工处理，后续 Skill 不启动。
4. 序列结果必须区分已完成、当前部分完成和未启动。不得把部分完成伪装为成功，也不得丢弃已生成文件。
5. Checkpoint（检查点）由 Cline 的真实消息、工具结果和内部序列标记推导；CreatX 不建立第二套持久 Run 数据库。
6. 应用重启不会自动重放活动工具。用户在原会话发送新的“继续”后，Adapter 根据历史和文件从未完成 Skill 继续。
7. 恢复会话前必须先收束上次进程真正遗留的运行状态，再由当前进程显式接管 Session。真实并发占用必须失败关闭，不能通过禁用 stale reconciler 掩盖。
8. 同步 `generate_image` 和持久图片队列共用唯一项目视觉 Prompt 编译器。存在最近《统一画风.md》时两者都自动注入；缺失时继续原 Prompt 并准确返回未应用状态。

## 实现边界

- 主能力：`creative-skills`。
- 相邻合同：`provider-harness`、`session`、`image-runtime`。
- 不修改 Cline Core，不增加 Harness，不建立第二套会话或 Run 权威。
- 不处理世界星图表现、日志文件删除、已有图片重绘或数据库视觉版本。
- 不用单纯提高无限预算代替恢复语义；普通聊天继续保持当前有限预算。

## 验收

- 固定十二次预算的受控 Cline Turn 在触顶后自动进入下一执行片段，Timeline 不出现未解决红色错误，最终只保留一条正式用户消息和一条正式 Assistant 结果。
- 地图第二轮失败时，结果明确显示研究完成、地图部分完成、后三项未启动；继续时不重复覆盖底图。
- 进程 A 留下旧 PID 后退出，进程 B 恢复同一 Session 并开始新 Turn；新 Turn 运行期间列举或读取会话不得被旧 PID 标记失败。
- 真实旧进程仍存活时，第二进程不得接管同一 Profile/Session。
- 同步与队列生图对同一作品根编译相同视觉母版；缺母版时都不伪装已经统一。
