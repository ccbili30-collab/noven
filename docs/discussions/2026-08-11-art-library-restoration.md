# 艺术库 0.1.19 体验恢复与基础藏品归属澄清

## 用户纠正

用户明确否定 2026-08-10 将艺术库主页面改造成分类管理列表、并把 63 张内置作品全部重置到候选区的产品解释。艺术库首先是可观看、可漫游、可进入作品详情的个人艺术图鉴；审批只是以后新增图片进入艺术库的入口，不应取代主体验。

用户要求恢复 Windows `0.1.19` 的艺术图鉴、圆环浏览、展览和作品详情语言，但不能回退整个应用或恢复静态页面、`localStorage` 事实源。当前真实 Runtime（运行时）、审批状态机、持久化、安全图片协议、关键词导出和 AI 风格提取必须继续作为权威能力。

后续澄清取代了“只参考旧视觉并在 React 中重做”的早期理解：不要继续手调或复刻，直接使用 `0.1.19` 提交 `285c018` 的页面、CSS 和动效。iframe 可作为旧视觉的 Presentation Boundary（展示边界）；它只能接收父级注入的 Runtime 投影，不能恢复旧静态数据权威。

## 已接受的基础藏品事实

打包静态数据 `creatx/apps/art-library/public/art-library/art-concept-data.json` 中的 63 张作品均为用户预先批准的基础藏品：

- 巨构艺术：41 张；
- 暖色风格：18 张；
- 纪念碑谷：4 张。

其中原 `orbitItems` 的 57 张和原 `approvalItems` 的 6 张都属于基础藏品。旧数据里的 `server_status: rejected` 是被本次澄清取代的旧演示状态，不再决定产品归属。

基础藏品必须真实物化到 `libraries/<分类>/items/<作品>/`，包含原图、`metadata.json` 和 `source.json`。它们不能只存在于静态 JSON、Fixture（测试夹具）、iframe 或页面内存中，也不能进入 `incoming` 或 `approval` 等待用户重复审批。

## 保留边界

- 以后来自公网、当前回合附件和项目文件的新图片继续走唯一 `incoming → approval → libraries` 状态机。
- 目录位置继续是状态权威；Renderer（渲染进程）只读 Main Process（主进程）快照与受限图片 URL。
- 63 张基础藏品采用可验证的稳定 ID、原图 SHA-256、种子快照和确定性分类；不能靠标题或目录名猜所有权。
- 已有用户作品、候选、候审项和分类必须逐字节保留。
- 已执行 2026-08-10 错误重置的 Profile（配置档案）必须可以安全恢复；身份、哈希或目标冲突时失败关闭。

## 明确取代

本记录取代 `ART-016/017` 中“63 张旧种子全部重新进入待整理路线”的产品语义，但保留其安全不变量：稳定种子身份、原图哈希核验、不得猜测归属、不得影响用户条目、迁移可重试且失败关闭。

## 当前不做

- 不回退整个 Windows 版本或其他产品能力；
- 不恢复 iframe 内静态数据或 `localStorage` 为生产事实；
- 不重做视觉整理模型、审批协议或关键词/AI 风格提取；
- 不把旧演示页面本身称为 Live（真实运行）；
- 不在本批提交、推送或打包发布版本，除非用户另行授权。
