# 创意库发送弹窗关闭与大列表性能

日期：2026-08-09
主能力线：`workspace-ui`

## 用户反馈

创意库“发送到对话”弹窗在发送后无法关闭，并且打开、滚动和交互延迟明显。用户确认需要永久修复，而不是只隐藏等待状态。

## 已验证原因

- `CreativeLibraryActions.tsx` 在发送期间把 `DesktopDialog.canClose` 设为 false，并禁用关闭按钮，导致 X、Escape 和遮罩点击同时失效。
- 分享调用复用普通 `sendMessage` IPC；该 IPC 等待 Cline 完整 Run 返回，因此 Provider（模型服务）回复越慢，弹窗锁定越久。
- 正式 Profile 当前有 917 个 Session（会话），弹窗一次性挂载全部按钮。
- 全屏遮罩使用 `backdrop-filter: blur(3px)`，会在图片密集的创意库背景上增加合成负担。该项未单独量化，但不承担产品语义，可安全移除。

## 已确认处理

1. 弹窗始终可通过 X、Escape 和遮罩关闭；关闭只影响选择面，不取消已接收的 AI Run。
2. 创意库分享使用独立的“等待 Runtime 接收”命令，不改变普通消息发送等待完整 Run 的既有语义。
3. Runtime 接收前失败时保留弹窗并显示真实错误；接收后 Provider 或工具失败继续通过既有事件链投影。
4. 会话按标题和路径搜索，并使用固定行高虚拟滚动；全部会话仍可访问，不截断为最近若干条。
5. 移除全屏动态模糊，保留普通半透明遮罩。

## 非目标

- 不取消或后台中止已经接收的 Run。
- 不改变普通 Composer 发送、Steer（运行中追加指令）或 Cline 历史语义。
- 不修改创意库素材、管理前端或会话数据模型。
