# 灰冠诸境交互地图原型讨论记录

日期：2026-08-07

Primary Capability：`creative-skills`

## 用户需求

地图的核心产品能力不是 GIS，也不是完整制图编辑器。用户需要点击一个自然地块后：

1. 地块边界清楚亮起。
2. 镜头能够拉近该地区。
3. 旁边展示所属国家、城市、生物、势力和地貌。
4. 资料能够指向对应作品原文。

第一版同意按自然地区划分，政治归属作为地区属性展示。原因是风原、暖湾和黑苇等地区不适合被永久硬国界替代。

## 原型决定

采用 Leaflet 1.9.4 的 `CRS.Simple`、`ImageOverlay` 和 GeoJSON Feature 组合验证交互。Leaflet 为 BSD-2-Clause 开源项目；原型改编其 Non-geographical maps 与 Interactive Choropleth Map 官方示例。

灰冠诸境 Prototype 位于：

```text
artifacts/grey-crown-map-prototype/
```

它包含三种展示布局，但共享同一地图、地区资料和选择状态：

- A：地图主视图与固定右侧图鉴。
- B：全屏地图与浮动资料卡。
- C：地区目录、地图与图鉴三栏。

## 证据边界

- 地区资料取自现有灰冠诸境真实 Markdown。
- 六块 Polygon 为人工推定的原型几何，不是正式地理事实。
- 原型只嵌入原文摘录，没有接入生产受控文件预览。
- Headless Browser 首轮验证暴露公共 CDN 等待不稳定；原型随后改为本地保存 Leaflet 1.9.4 官方发行文件与完整许可证。生产依赖形式和 Renderer 集成仍未决定。
- 本批不修改 `/draw-map` 数据合同、生产 Renderer、Runtime 或 Cline Skill。

## 待用户验证

1. 点击区域、边界高亮和拉近是否符合预期。
2. A/B/C 哪种信息布局更适合作为工作台。
3. 地图绘制质量是否足以进入下一轮美术迭代。
4. 用户认可后，才决定是否用 GeoJSON Polygon 替换当前隐藏泰森命中与整图高亮变体。

## 2026-08-07 地区蒙版纠正

用户否定了“硬 Polygon 加少量噪声”的地图理解。目标应当是同一块大陆像饼干一样碎成能够严丝合缝复原的地区：海岸和共边具有多尺度细节，宏观走向受山河、海岸、沼泽与历史空间关系约束，微观波折可以程序生成。

第二个隔离 Prototype 位于：

```text
artifacts/grey-crown-region-mask-prototype/
```

它不调用图片模型，只生成结构蒙版：

1. 多尺度确定性高度场生成大陆、冠海边缘、内海和湾口。
2. 六个地区从灰冠诸境的相对位置出发，在 `900 × 560` 微地块上进行多源最短路径生长。
3. 黑脊山、长河与九河、坡度和黑苇湿地改变扩张成本。
4. 同源域扭曲细化共享边缘；相邻地区始终读取同一张像素 ID 图，不产生双边错位。
5. 点击地区后从该权威 ID 图实时提取连续金边；可导出无标签地区 ID 蒙版。

自动与视觉证据：`node --check app.js` 通过；Bun 静态服务监听 `4189`；真实 Chrome 在选中九河盆地后呈现 `像素 ID + 同源金边`，最终视觉截图为 `validation-mask.png`。前两轮分别因内边界过度平滑而被本轮自检淘汰，没有作为最终截图保留在工作树。

该结果只证明“不手绘也能生成共享蒙版与金边”的原型方向。大陆形状、地区数量、地理约束提取、连通性门禁、正式数据合同、Renderer、图片参考输入和 `/draw-map` 迁移都尚未实现。

## 2026-08-07 已知世界尺度扩展

用户认可共享蒙版方向，但指出六区大陆在视觉上像一座较小的澳大利亚，不能代表世界级地图。重新核对 `灰冠诸境` 的真实项目文件后确认：

- `宇宙、自然与地理/` 有 16 份 Markdown，旧蒙版只采用了六个合并宏区。
- 地表存在 11 个具有独立文本依据的地区：冬路与冰隘、黑脊山系、长脊山系、西境长林、三河平原、九河盆地、琥珀草原、东陲风原、南方葡萄阶地、南方盐沼与暖湾、黑苇沼泽。
- 冠海与内海是水域，不应伪装为陆地碎块；地下旧道与根下洞海属于另一个空间层。
- `灰冠诸境总图.md` 明确说明总图地点是关系索引锚点，不是世界全部内容。因此当前证据只支持把灰冠诸境画成被详细记录的已知核心区，不支持凭空补出海外大陆。

地区蒙版原型据此扩展为 11 个地表区，并增加冠海外洋、内海与潮门及外围有机雾层。雾层表达“图志在这里停止，而不是世界在这里结束”，不会生成无文本依据的海外地理。每个选中地区的资料卡增加对应源文件名；所有地块仍共享同一张 `720 × 440` 像素 ID 图和同源金边。为保持交互速度，区域划分从堆式多源最短路径改为同一地形场上的确定性加权生长；山脉、河流和湿地仍进入区域成本。

验证结果：

- `node --check app.js`：通过。
- Bun 静态服务 `http://127.0.0.1:4189/`：HTTP 200，验收后保持运行。
- 系统 Chrome 真实截图单次约 2.4 秒完成；九河盆地和黑苇沼泽两个 URL 选择入口都呈现对应金边、地区编号、源文件和相邻地区。
- 截图为 `validation-full.png` 与 `validation-black-reed.png`。
- Playwright 本机无头浏览器连空壳页也无法正常收束，不能作为本批页面失败证据；临时检查脚本已删除，没有进入原型。

该版本仍是 Prototype（原型），没有接入生产 Renderer、地图 Skill、真实文件跳转或地下层切换，也没有证明正式地图数据合同。

## 2026-08-07 单艺术底图与蒙版抬升

用户进一步确认地图不应为每个地区生成一张完整高亮变体。目标改为一张艺术底图和一张权威地区 ID 蒙版：点击地区时从同一底图按蒙版裁出顶面，原位置留下暗槽，顶面向上移动，蒙版向下重复形成可见厚度侧壁，并同步显示金边和地区资料；点击海面后落回。

本轮仍只修改 `artifacts/grey-crown-region-mask-prototype/`。实施路径：

1. 同一地形算法输出 `structure-guide.png` 与 `region-id-mask.png`，两者均为 `720 × 440`。
2. 通过用户当前 Codex 图片 Provider 的 Frame Lock（画框锁定）模式生成一张无文字、无国界、无额外大陆的 `art-map-generated.png`。
3. Provider 实际返回 `1609 × 978`，没有遵守请求的 `1440 × 880`；因此原图不能直接成为几何权威。
4. `compose-map.py` 将原图按目标比例居中裁切、重采样，并以 ID 蒙版强制重建海陆分界，得到页面实际读取的 `720 × 440 art-map.png`。
5. Canvas 2D 从同一底图和蒙版实时生成顶面、暗槽、侧壁、投影、金边和 330ms 抬升动画，没有保存十一张地区图片。

系统 Chrome 在 `1600 × 950` 下分别生成未选择态 `validation-art-default.png` 和九河盆地抬升态 `validation-art-lifted.png`；两张截图均成功，抬升态显示同源顶面、原位暗槽、连续侧壁、金边、同步标签与对应 `九河盆地.md` 资料。`node --check app.js` 和 HTTP 200 通过。Playwright 本机无头运行问题仍不作为产品证据。本轮没有修改生产 Renderer、公开合同或 `/draw-map` Skill，因此不能标记 `ACC-CSK-501` 至 `506` Live。

## 2026-08-07 V2 地理结构纠正

用户接受“重建地理结构，再让 Provider 只负责美术”的第二条路线。V1 的主要失败不是蒙版点击技术，而是同一粗色块引导同时承担地区、山脉、河流和地貌，Provider 将粗白山线和粗蓝河线机械实体化。

本轮继续限定为隔离 Web Prototype：

1. 保留 `region-id-mask.png` 作为点击、裁切和金边的唯一权威。
2. 新增 `build-geography-v2.py`，把高程、水系和连续地貌从地区身份中分离。
3. 第一份 V2 结构仍呈现亮色山墙和树状河流，保存为 `structure-guide-v2-wall-failed.png`，没有拿去调用 Provider。
4. 返工后改用高程山体阴影、支脉山麓、曲线主河与不同宽度支流，形成 `structure-guide-v2.png`。
5. 使用真实 `codex-imagen2` Responses/Frame Lock 调用，请求 `1600×976`、实际返回 `1672×941` 的 `art-map-generated-v2.png`，再按 ID 蒙版硬约束为 `720×440` 的 `art-map-v2.png`。
6. 页面默认加载 V2，V1 通过 `?map=legacy` 保留；默认隐藏内部地区边线，仅选中时显示金边，抬升侧壁由 13px 降至 6px，原位凹槽改为不透明。

真实结果证明“地区几何与地理美术分离”有效改善了地貌连续性和山谷结构，但仍存在河道偏粗、局部地形渲染感和缺少城市道路符号的问题。该结果不接生产 Renderer、不修改 `/draw-map`，也不构成地图 Skill Live。

### V2 原图显示纠正

首轮 V2 页面错误地把 `1672×941` Provider 原图通过 `compose-map-v2.py` 压到 `720×440`，替换蒙版外海面并添加海岸轮廓，再由同为 `720×440` 的 Canvas 放大显示，造成明显模糊和不必要的外层遮罩。该问题属于原型显示链错误，不是 Provider 低精度。

纠正后，默认页面直接显示完整 `art-map-generated-v2.png`，Canvas backing store（内部像素缓冲）使用原图尺寸，地区 ID 蒙版仅在隐藏层按归一化坐标映射，负责命中、裁切、凹槽与选中金边。`art-map-v2.png` 不再作为可见底图。该路线优先保持艺术原图，蒙版映射精度必须通过全部地区视觉检查继续验证；不能再通过改写原图掩盖模型形变。

定向验收生成 `validation-raw-default.png` 与 `validation-raw-lifted.png`，两张均为真实 Chrome `1600×1000` 截图。相同地图视区的平均相邻像素差从旧显示链 `2.527` 提高到原图链 `6.396`，默认、九河盆地选中和 V1 对比入口均返回 HTTP 200；该数值只证明显示细节没有再次被低分辨率 Canvas 抹平，不是地图美术质量评分。

### 完整矩形 13 区纠正

此前代码把所有非陆地像素保留为 `SEA = -1`，点击时等价于取消选择。这样海洋虽然存在于美术图，却不属于地图内容模型。用户明确要求整张矩形都必须分割、外围海域也必须可选择。

纠正后的 ID 蒙版包含 11 个陆地区、冠海外洋和内海与潮门，共 13 个有效 ID；全部 `720×440 = 316,800` 个像素都有归属。冠海外洋覆盖大陆外侧、四角和未测海雾，内海与潮门覆盖南部湾口水域；“旧图止于海雾”和“未测海域”仍只是范围说明，不伪装成额外世界地区。陆地区保持裁切抬升，海区使用整片提亮与同源边界，避免把带大陆孔洞的整张海面拔成厚板。再次点击当前区域或按 `Esc` 取消选择。

定向截图为 `validation-outer-sea.png`、`validation-inner-sea.png`、`validation-land-13.png` 和 `validation-id-13.png`。ID 截图必须恰有 13 种颜色且没有空白颜色；该原型仍未接生产地图工作台。

## 2026-08-07 项目内交互地图 Skill 原型

用户进一步确认输出页面必须是干净成品：地图占据完整可用画布，不生成固定侧边栏、顶栏、工具栏、图例、调试按钮或蒙版预览；地区介绍只在选中后以靠近点击位置的浮窗出现。浮窗可以拖动和关闭，再次点击当前区域或按 `Esc` 关闭。该产品纠正 supersedes（取代）本记录早期 A/C 固定栏布局在此次地图成品中的适用性，但不删除其历史原型证据。

项目内 Skill Prototype（技能原型）位于：

```text
prototypes/skills/creatx-build-interactive-map/
```

它未安装到 Codex，也未替换生产 `/draw-map`。Skill 接受一张原生高清 PNG、一张同尺寸不透明 RGB/RGBA 地区 ID 蒙版和 `map-manifest.json`，由唯一 Builder 校验尺寸、路径、地区 ID、颜色、透明度、无主像素和空区域，再复制固定 Viewer。原图是视觉权威；蒙版只用于命中、裁切、高亮和边界，不得为了适配低精度蒙版改写或降采样原图。整张矩形必须全部归属到陆地、水域或明确的未知区域。

灰冠真实前向构建输出位于：

```text
artifacts/grey-crown-interactive-map-clean/
```

现有 `art-map-generated-v2.png` 作为 `1672×941` 可见底图；完整 13 色 ID 蒙版用 nearest-neighbor（最近邻）映射到相同尺寸。Builder 实际报告 13 个地区、`1,573,352` 个已归属像素，最小地区 `16,776` 像素。输出复制到当前 4189 原型服务的 `clean/` 子目录用于验收，不改变根页面；预览入口为：

```text
http://127.0.0.1:4189/clean/index.html
```

真实 Chrome `1440×900` 验收结果：默认页面没有可见浮窗、错误、侧边栏、导航、工具栏或按钮；地图保持 `1672:941` 比例并最大化显示。点击九河盆地后显示 `九河盆地` 浮窗和陆地抬升，浮窗从 `(732,418)` 拖动到 `(532,520)`；`Esc` 成功关闭。点击外海真实像素 `(100,100)` 后显示 `冠海外洋` 浮窗和原位水域提亮；再次点击关闭。关闭按钮也成功关闭浮窗，页面无 Console Error（控制台错误）。视觉证据为 `validation-clean-default.png`、`validation-clean-land-card.png` 和 `validation-clean-water-card.png`。
