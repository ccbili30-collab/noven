# 对话图片附件与即时等待反馈

日期：2026-08-09
状态：用户已确认进入实现
主要能力线：`workspace-ui`
相邻合同：`provider-harness`

## 用户意图

用户希望对话图片采用与 Codex 相同的直觉：图片拖入或选择后先在 Composer（输入区）显示预览；发送后继续显示在用户消息中并可查看大图；同一张图片必须真正进入视觉模型，而不是只把本机路径交给 Agent。用户消息成功提交后，Assistant 一侧必须立即显示正在准备回复的状态，不能在首个模型增量前保持空白。

## 已确认故障

1. 当前图片与文本文件都通过 Cline `userFiles` 发送。Cline `0.0.65` 会把 `userFiles` 作为 UTF-8 文本读取，JPG/PNG 因二进制内容读取失败，模型只能看到路径与读取错误。
2. Renderer 已收到 `running`，但当前回合在没有 Assistant、Reasoning（推理）或工具条目时不渲染任何等待状态。
3. 乐观用户消息的附件 `displayPath` 是文件名，Cline 历史投影使用绝对路径；Timeline（时间线）合并因此把同一次发送显示为两条消息。
4. 外部临时目录不是可靠历史来源。图片进入 Cline 正式用户消息后，应以 Cline 持久图片内容作为会话事实；Renderer 只通过受限图片协议读取，不持久化第二套消息或暴露绝对路径。

## 本批产品边界

- 首版聊天视觉附件支持 PNG 与 JPEG。
- 合法图片显示 Composer 缩略图、已发送消息缩略图和点击大图。
- 图片通过 Cline `userImages` 进入模型；文本文件继续通过 `userFiles`。
- 未支持二进制、伪造格式、变化或消失的文件在 Provider（模型服务）请求前失败关闭。
- 单图和单次发送采用明确字节上限，避免 Renderer、Main（主进程）和 Provider 请求无界膨胀。
- 非视觉模型如何拒绝图片由真实 Provider/Cline 错误返回；本批不增加模型 Profile（配置档）的视觉能力字段，不按模型名猜测能力。
- 发送成功进入运行态后立即显示“正在准备回复…”。首个推理、工具或 Assistant 内容、失败、取消、结果未知或会话切换都会移除该占位。
- 不支持视频、音频、GIF、WebP、SVG 或任意二进制预览；不修改 Cline Core；不建立第二套会话附件数据库。

## 验收意图

- 乐观图片附件与 Cline 持久图片附件只形成一条用户消息。
- 延迟首个 Provider 增量期间存在 Assistant 等待提示，首个真实活动后消失。
- PNG/JPEG 请求中出现真实 Cline image content block，不出现二进制 `userFiles` 读取错误。
- Composer 与历史消息均显示缩略图；历史重读后仍可通过受限协议查看，不依赖原始临时路径。
- 大图、超量、伪造签名、缺失与不支持二进制均在 Provider 请求前失败关闭。
