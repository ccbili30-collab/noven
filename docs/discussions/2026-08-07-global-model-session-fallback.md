# 全局文本模型与单会话覆盖

## 问题

完整 Live 档案迁入正式产品后，历史 Owner 会话继续保存原 `creatxTextProfileId`。凭据按安全边界没有随档案迁移；当正式设置中不存在该旧 Profile 时，Adapter 仍用旧 Provider 和模型构造无 API Key、无 Base URL 的连接并向外发送请求。用户已经在设置页配置并选择 DeepSeek，但恢复会话没有采用它，最终把 `/draw-comic` 和多次“重试”发送到默认 OpenAI 地址并收到缺凭据错误。

## 用户确认的产品语义

1. 设置页当前选中的文本模型是全局默认连接。
2. 新会话使用全局默认连接。
3. 恢复会话的原 Profile 仍存在且可解析时，保留该会话自己的模型覆盖。
4. 恢复会话的原 Profile 已删除、未迁移或无法解析时，自动切换到当前全局默认连接，并在发送 Provider 请求前持久更新该会话的 Cline 连接与 CreatX Profile 元数据。
5. 对话框模型下拉继续提供单会话切换；该覆盖只属于当前会话并持久保存，不反向改变全局默认。
6. 全局默认也没有有效凭据时，本地失败关闭，不得构造无凭据连接或发送外部请求。

## 影响边界

该规则只处理“持久会话引用的 Profile 已无法解析”。它不覆盖仍有效的单会话选择，不迁移或复制旧密钥，不改变图片模型配置，也不自动重放此前失败的用户消息或工具副作用。
