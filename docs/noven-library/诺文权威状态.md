## 二、证据等级

### A级：用户明确决定

用户在原始讨论中明确确认，并在十三问逐题返工后冻结的产品判断。它们构成当前产品定义，但不等于已经实现或得到市场验证。

### B级：代码、配置、测试与真实运行结果

只用于说明“已经实现什么”。没有真实运行链支持的能力，不得标为 Live（真实运行）。Mock（模拟）、固定样本和 AI 读者不能冒充真人用户验证。

### C级：已确认方向

例如商业模式、Creative Fork Protocol（创作分叉协议）、多媒体路线与自有模型条件。可以进入规划，但在协议、运行链或用户证据形成前，必须标记为“方向”“假设”或“待验证”。

### D级：研究假设与候选机制

例如具体多智能体拓扑、审美模型、长期记忆架构、模型微调方法和推荐治理算法。只有经过独立验证后才能升级，不能因为论述完整而自动成为产品事实。

任何修改本文的 Agent（智能体）必须说明：原结论、新证据或新决定、覆盖范围，以及仍未改变的边界。

## 三、一句话产品定义

> **诺文是一座面向普通人的创作承接平台：用户可以只带来一个不完整的念头、一次心动、一段经历或对既有内容的回应；一位完整作家接住用户此刻不愿或不能承担的创作压力，让碎片参与持续成为一件有作家、有历史、有读者、有权利边界的作品。**

更短的用户承诺是：

> **你可以随口开始，不必独自承担创作。**

诺文不是：

- 自动小说工厂；
- 一句话批量生成一万字的内容机器；
- 要求普通人学习复杂提示词和创作工作流的软件；
- 模拟全部因果与无限分支的世界模型；
- 把普通人的人生变成默认训练数据的平台；
- 用风格标签或人类作品碎片拼装“AI好文”的滤镜商店。

## 四、时代判断

当前产品建立在两条同时发生的趋势上：

```text
专业创作能力不断向普通人下放
＋
人的完整时间与注意力越来越碎片化
```

短视频平台在中国推动了大规模影像表达下放；AI正在把写作、绘画、设计、编程、音频和视频制作等能力变成自然语言可以调用的能力。

但：

```text
获得生成能力
≠
获得完成作品的能力
```

普通人仍需要跨过点火、取舍、表达、长期维护、发布、读者、反馈与权利关系。诺文要做的不是把作品切碎，而是让人的参与可以碎片化，同时由作者保持作品连续。

这是有现实依据的战略判断，尚没有独立市场数据证明大量普通人会持续创作或付费。

## 五、五个名称的权威关系

### 1. 诺文：平台

诺文是对外产品母体，目标是承载创作入口、作者服务、作品状态、发布、读者回应、分支、来源与权利关系。

平台目标闭环是：

```text
创作点火
→ 创作续航
→ 作品积累
→ 社会回应
→ 再创作
```

当前只有第一阶段书记员路径契约展示，不得把目标平台描述成已经上线。

### 2. 作家房间：统一作家的黑箱边界

作家房间把模型、记忆、检索、复审、人物、时间线、版本、排版和多媒体工具组织在内部；用户在外部只面对：

```text
用户
↕
同一位作家
↕
同一件持续生长的作品
```

作家房间不是多智能体会议界面。内部可以只有一个强模型，也可以使用多个模型和工具；具体结构必须由质量、用户减负、延迟与成本证据决定。作家房间负责组织回合，不是作家本人，也不拥有作品事实。

### 3. 叛逆作家：创作主体与产品灵魂

叛逆作家理解用户并接受明确边界，但不会塌缩成用户、大模型、审美评测、推荐算法、商业效率或市场多数的平均回声。

“叛逆”不是故意反对、冒犯或越权，而是：

> **哪怕一个答案已经被计算证明最好，作者仍要追问：它对这件具体作品、这个具体人物和这个具体的人来说，是真的吗？**

叛逆作家负责作出一个具体创作决定并承担后果。用户可以接受、否决或改变它；双方互相影响，但不能无痕覆盖对方。合格与不合格行为以[叛逆作家行为合同](叛逆作家行为合同.md)为准，不能用固定人格、相同模型、相同 ID 或可读文本替代验证。

### 4. 作品系统：连续性基础

作品系统的目标是区分并维护：

- 用户原始表达；
- 探索与讨论；
- 角色体验；
- 候选版本；
- 正式正文；
- 已确认事实；
- 被用户有意改写的旧事实；
- 来源、授权与分支关系。

稳定要求是：

> **向后记得住，向前写得动。**

用户可以有意识地改写旧设定，AI不能因为遗忘而无痕吃书。当前权威作品状态和正式提交链尚未实现。

### 5. WorldX：研发工作区

WorldX是代码、实验和文档所在的研发工作区，也保存从世界模型收缩到作者产品的历史。当前没有证据支持将其定义为与诺文并列的第二个对外品牌。

## 六、已经冻结的产品判断

### 1. 创作能力下放，作品不能随生成一起消失

诺文不只降低“生成一段内容”的门槛，而要降低从一次创作冲动到拥有一件作品的完整门槛。

### 2. 人类创造力绰绰有余

今天真正稀缺的不是故事和想象，而是让各种职业、地区、阶层和代际的经验获得表达手艺、作品形态与社会回应的条件。

普通人是作品主体，不是平台数据矿。作品保存、公开、推荐、商业使用、诺文内部训练和第三方模型训练必须分别授权。

### 3. 创作负担必须动态判断

创作负担不是所有困难，而是用户为了让真正关心的东西成为作品，被迫承担、却不能产生表达感、创作快感和所有感的劳动。

叛逆作家需要形成创作判断，作家房间负责把目标、授权、边界和交付编译为可执行回合：

- 用户本轮想保留什么；
- 愿意把什么交给作者；
- 哪些内容不能改变；
- 本轮交付什么；
- 结果是否进入正式作品。

权限决定作家可以做什么，经验与品味决定应该怎样做，作品状态保证决定长期延续。

### 4. 工具复杂度应尽量内化

学习、选择、配置和组合复杂创作工具本身也是负担。默认体验是：

> **能丢给作者做的，就丢给作者做。**

用户需要时仍可查看、接管或建立自己的工具，也可以让AI帮助生成个人工具。内化工具不等于隐藏重大改动或取消恢复能力。

### 5. 第一次输出追求第二次创作行为

用户给出一句不完整的话，作者应尽快交付一个具体版本，让用户自然说出“继续、不对、这里别动、剩下你来”。这些回应是确认、否决、保护和授权，不只是参数调整。

Time to First Fascination（首次着迷时间）是候选指标，必须结合反应性质判断，不能把修理AI、廉价刺激或第二次点击冒充真正着迷。

### 6. 作品应随着人的参与逐渐更像这个人

少数模型会造成共同语言与叙事惯性。诺文不以大量风格作者制造虚假多样性，而采用少数能力有高低的通用作者：

- 基础作者：经济、高频，负责点火、常规推进和跨过可用线；
- 高级作者：负责关键理解、重大取舍、结构重写和作品上限。

核心假设是：用户持续保留、否决、修改和补入经验以后，作品会从AI对社会的普遍认识，逐渐深入个人对社会的具体反应。

> **一切作品终究是人眼中社会的倒影。**

该假设尚未得到长期真人用户证据验证。

### 7. 先研究小说，建设多媒体平台

小说适合检验人物、关系、因果、社会理解和长期作者能力，也适合作为作品的语义母体。漫画、音频和视频不是机械转码，而是保留来源、关键事实和授权边界后的再解释。

稳定路线是：

> **以小说建立作品，以多媒体释放作品。**

当前多媒体创作链尚未实现。

### 8. 必须正面面对电子泔水与AI尸块

低门槛首先扩大供给，不自动提高质量。电子泔水的核心是“生成发生、创作没有发生”。AI尸块则是把优秀作品拆成句子、桥段和风格零件，再缝成貌似完整的内容。

AI应从人类美学经验上长出新作品，而不是肢解优秀作品进行拼装。诺文的“抖音时刻”不是日生成量暴涨，而是过去不存在的创作者、作品类型和沉默经验开始成规模出现。

这是一项目标，不是当前事实。

### 9. 强模型可以删除作者房间复杂度

更强基础模型完全可能替代作者房间中的大量机制。每一层契约、检索、复审和模型路由都必须通过消融证明其质量或减负收益，否则应被删除。

基础模型可能较快覆盖通用作者能力。作者房间应随模型进步而变薄，不能以复杂为荣。

自有模型不是首发前提。只有真实闭环暴露稳定缺口、拥有明确授权资料，并证明训练优于提示、状态与工具以后，才考虑微调、专用小模型或自研作者模型。

### 10. 商业激励不能奖励机器产量

首发最可信的商业假设是：

```text
免费点火
＋ Writing Plan（写作套餐）会员续航
＋ 高成本能力按量付费
```

有真实读者和价值后，再考虑阅读、打赏和经授权衍生的服务分成；Writing API（写作接口）、官方创作空间和自有模型属于后续路线。

用户购买的是长期负责作品的作者服务，不是模型名称和Token（文本单元）。当前没有真实价格、付费率、留存、单位成本或毛利数据。

### 11. 开放创作必须建立权利基础设施

Creative Fork Protocol拟借鉴GitHub的协作结构，建立作品仓库、协议、分支、差异、来源谱系、原作者关系和收益回流。

必须坚持：

- 默认保护，开放由真实权利人主动选择；
- 允许创作不等于原作者认可；
- 市场喜欢不能代替授权；
- 平台不能替未参与的权利人开放作品；
- 来源不能被抹去；
- 商业价值按真实协议回流。

平台应在创作前、创作中、发布、收益和争议全链路执行门禁。正式协议尚未形成，落地前必须经过专业法律审查。

## 七、产品闭环

目标闭环是：

```text
普通人的生活、判断与想象
→ 一句话或一段自然表达进入诺文
→ 作者先交付具体版本
→ 用户继续、否决、保护或授权
→ 变化经确认进入正式作品
→ 人物、事实和版本持续积累
→ 作品由用户主动发布并获得真人回应
→ 回应、追问与分支再次进入创作
```

最小闭环不是“生成完成”，而是：

```text
用户给出不完整的东西
→ 作者交付具体版本
→ 用户自然回应
→ 作者承担下一步
→ 作品留下真实变化并可继续
```

当前这两个闭环均未在产品 Runtime 中跑通。

## 八、权利与数据边界

### 1. 用户经历不是默认训练数据

至少应区分：

```text
维持当前作品所需的数据
≠ 匿名产品统计
≠ 个性化作者记忆
≠ 诺文内部模型训练
≠ 第三方模型厂商训练
```

训练授权必须明确、知情、可验证。额外权益不能变成强迫用户交出训练权的条件。

### 2. 未授权站外作品

诺文无权替站外权利人授予改编许可。“标注二创、非盈利、不推流”不能自动取得改编权。

当前保守方向是：

```text
未确认权利的站外作品
→ 仅考虑私人创作沙盒
→ 不进入公共灵感库
→ 不主动推荐
→ 不商业化

公版、作者主动开放或明确授权作品
→ 才能进入公共分支网络
→ 保留来源与原作入口
→ 按协议决定传播、商业化与回流
```

这一方向仍需法律审查和具体产品门禁，不能称为已经解决版权问题。

## 九、当前真实运行状态

诺文现有 UI 链仍以截至 2026-08-12 的留档为准；另有一个截至 2026-08-13 已集中验收的独立作家基底原型。两者没有接通，不能互相冒充完成状态。

### 唯一接入当前UI的真实链

```text
用户输入
→ POST /api/clerk
→ 主笔席位所选模型连接
→ OpenAI-compatible Chat Completions
→ 书记员v4严格校验
→ 左侧显示创作路径契约
```

界面明确说明：只识别与组合，不进入主笔创作；当前不会执行生成的创作路径。

已经实现并留有证据：

- 书记员v4的资源、步骤、依赖、逐步权限、约束、澄清、证据和提交门禁校验；
- 无模型配置时 Fail Closed（失败关闭）；
- 同源、JSON、超时、取消和分类错误边界；
- 模型连接配置与密钥脱敏；
- `/api/chat` 单阶段流式后端原语，但未接入当前前端创作链。

截至留档时，实机没有 `.data/model-config.json`，`/api/config` 返回 `configured=false`，因此当时运行实例没有 Provider（模型服务）Live 配置。

### 独立作家基底原型

`prototypes/writer-agent-foundation/` 已实现诺文所需但尚未接入诺文的最小叛逆作家、作家房间、真实 SQLite 作品系统、OpenAI-compatible Provider 边界和浏览器验证壳。它不是诺文本体，也不修改或依赖诺文工作台。

职责边界已经进入运行代码：叛逆作家通过 Provider 输出创作判断与交付；作家房间只编排回合、取消和恢复；作品系统独占修订、工作线、检查点、授权、责任与决策写入；浏览器只读取投影并发出用户命令。

WR-09 技术运行链已经补齐：两次连续修复仍被否定后进入非内容诊断，不创建第三份修订，并原子回退连续失败修复链；用户回答后进入新的修复尝试且可幂等重放。两个既有任务独立发现有限短语、多问句、“陈述句＋问句”和回答重放模式漂移；多轮最小修复及交叉复核后，双方使用新临时 SQLite 确认反例关闭。

当前集中证据为：19/19 个 JavaScript/ESM 文件语法通过（包括 `public/app.js`）；`npm test` 81/81；固定 Seed 技术压力 T01–T08 为 8/8、114/114；T03 由两个独立 Worker Thread 各自打开同一临时 SQLite，并在 Barrier 上共同进入交付后统一释放，报告记录 `barrierParticipants=2`、`enteredDelivery=2`、一胜一 `STATE_CONFLICT` 和唯一有效修订；浏览器 Fixture 验证通过；未配置 Provider 时验证脚本以真实子进程退出码 2 返回 `PROVIDER_NOT_CONFIGURED`。以上均是 Prototype/Fixture 技术证据，`live=false`。旧的先 A 后 B 顺序 T03 证据已经作废。有限短语不等于通用语义理解，单问句形状不等于问题在文学上真正决定性。

当前集成头还关闭了两项集成回归：Provider 返回后先由作品系统复核授权/CAS 快照，避免 `BOUNDARY_UNVERIFIED` 遮蔽在途 `AUTHORIZATION_CONFLICT`，并保存实际交付为失效产物；浏览器“明确晋升”提交用户操作时的全版本快照，服务端继续在事务中执行 CAS。二者均未放宽权限或作品写入边界。

当前仍有独立的持久化阻塞：另一连接持有 SQLite `BEGIN IMMEDIATE` 超过 `busy_timeout=5000` 时，交付返回原生 `ERR_SQLITE_ERROR` / `errcode=5` / `database is locked`，没有作品写入，但回合仍停在 `running`。该反例不推翻 T03 CAS；它证明稳定持久化错误分类、回合终态和恢复入口尚未冻结。不得将其伪装成 `STATE_CONFLICT`，也不得自动重新调用 Provider。

测试夹具已在成功和失败路径关闭 SQLite、HTTP 子进程与临时目录。Windows 重启测试显式关闭重开句柄后，定向测试为 32/32；当前完整 81 项、固定 Seed 压力、视觉壳和 Provider 失败关闭均已运行。最终冻结验收前后，系统临时目录观察值均为 1732 个 `noven-writer-system-*`、38 个 `noven-writer-http-*`、11 个 `noven-writer-visual-*` 和 0 个 `noven-writer-stress-*`，本轮零增长；旧目录没有删除，归属尚未核实，不能报告为已清理。

当前没有完整真实 Provider 进程配置，没有执行真实慢调用压力、真人 8 回合、同模型直接响应基线或 Commit-Reveal 双盲文学质量与用户负担评审。因此 Live 基础链、最小 Live 作家闭环、WR-01 至 WR-14 的 14/14 产品验收和诺文 Agent 完成都未成立。完整证据见[WR-09 轮次记录](../rounds/2026-08-13-writer-agent-foundation-wr09.md)。

## 十一、必须长期保留的事故红线

在匿名作者评审中，用户先虚构“甲最好”，随后虚构“丙最好”；助手分别为两个相反结论事后选择证据并生成完整审美解释。

用户后来真实阅读后的体验恰好符合其中一种说法，也不能修复此前错误的取证过程。

由此冻结：

- 当前甲、乙、丙排序与用户偏好解释全部不得作为实验结论；
- 审美比较必须执行 Commit-Reveal（先提交、后揭示）：评审判断与用户判断先独立冻结，再互相揭示；
- 用户评价不能触发无痕翻转；
- 后续复查和结论变化必须留痕；
- 不得主动读取或泄露 `artifacts/author-trajectories-2026-08-12/author-label-key.json`；用户完成独立盲评前，标签与底层模型映射保持封存。

该纠正协议本身尚未通过一轮全新审美实验验证。

## 十二、已推翻、降级与不得声称

### 已推翻

- 近期产品中心是真正世界模型或混沌模拟；

- AI主动提供灵感对所有用户都是减负；
- 当前甲、乙、丙排序可以作为作者优劣证据。

### 已降级为候选机制

## 十三、下一阶段唯一优先级

下一阶段不先堆叠架构，不先建设完整社区，也不先制定完整法律协议。

首要任务是把已经通过 Fixture 技术验收的独立作家基底跑成最小真实创作闭环，而不是先接诺文工作台：

```text
用户给出一个不完整的东西
→ 作家快速交付一个具体工作稿
→ 用户自然回应
→ 作家承担下一步
→ 用户明确晋升正式作品检查点
→ 作品、作家责任与关系边界均可恢复
```

验证顺序：

1. 通过进程环境提供完整真实 Provider 配置，验证真实烟雾调用和失败关闭；
2. 使用真实慢调用验证取消、撤权、自然到期、迟到与恢复；
3. 建立同模型直接响应基线，避免把模型本身能力归功于房间；
4. 执行预注册真人 8 回合和 WR-01 至 WR-14 独立场景；
5. 执行 Commit-Reveal 双盲作品质量与用户负担评审；
6. 只有基线暴露明确问题时，才分别加入检索、复审或多模型机制并做消融；
7. 最小 Live 作家闭环成立后，才设计诺文工作台接入、发布反馈、多媒体和分叉网络。

真实用户行为、作品盲评与过程负担必须分开取证。审美比较必须继续执行Commit-Reveal。

具体基础模型选择需要依据当前预算、稳定性与真实基线重新确认；历史上的DeepSeek首发决定是当时预算下的选择，不构成永久绑定，也不等于已经完成接入。

## 十四、完成下一阶段的判据

除[最小作家原型验收矩阵](最小作家原型验收矩阵.md)的 Live 基础链与压力测试外，至少需要观察：

- 第一轮后，用户是否主动产生第二次创作行为；
- 第二句话是创作反应，还是在修理AI；
- 用户是否能用“继续、不对、这里别动、剩下你来”推进；
- 作家是否越过用户保护边界；
- 作家是否作出一个具体取舍，而不是把选择退回用户；
- 作家面对无新证据的施压是否保持判断；
- 作家面对真正的新证据是否有痕改变；
- 作家误解或写坏后是否标记影响范围、保留旧稿并承担修复；
- 重启后是否恢复承诺、分歧、未决问题和下一责任，而不只恢复正文；
- 用户回应是否真实改变正式作品；
- 用户离开再回来时，是否需要重新解释作品；
- 作品是否跨过基本可阅读质量线；
- 用户是否认为作品中有自己的不可替代影响；
- 用户是否愿意回到同一件作品。

作品质量与用户减负是两道独立门槛，不能互相抵消。

社会回应、推荐、多媒体、协议和商业不属于最小作家闭环的完成条件；它们只在前一阶段成立后进入下一轮验证。可读性、记忆和边界合规不能单独证明作家成立。

## 十五、冻结表达

产品层：

> **普通人不缺转瞬即逝的创作冲动，缺的是一位能够接住它、记住它，并继续把它写成作品的作者。**

关系层：

> **用户贡献自己真正关心的部分，作者承担剩余创作压力；双方可以互相改变，但作者不是用户的镜像。**

平台层：

> **创作点火 → 创作续航 → 作品积累 → 社会回应 → 再创作。**

工程层：

> **控制层保护权限、事实与提交；创作层保留作者判断；内部复杂度不能转嫁给用户。**

协议层：

> **作品可以被继续，来源不能被抹去；允许创作不等于原作者认可。**

现实状态：

> **方向已经形成，书记员协议和若干隔离实验已有真实证据；完整作家、长期作品、多媒体、发布社区、商业系统与创作分叉平台均尚未实现。**

最终承诺：

> **诺文要证明的，不是AI能够替人类生成多少内容，而是它能否把创作的权利真正交还给每一个拥有生活、判断与想象的人。**
