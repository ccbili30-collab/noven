# Art Library 产品规格

## 已接受规则

- `ART-001`：CreatX 只有一个本机个人总艺术库。它不拥有专属 AI、专属会话或普通项目绑定关系；任何普通会话可以发现相同的应用级艺术库工具。
- `ART-002`：公网采集只收集公开网页可访问的图片。自然语言收集默认 12 张，单次最少 1 张、最多 30 张；工具也允许明确来源页面，便于已知链接稳定采集。
- `ART-003`：联网采集必须限制协议、重定向、超时、响应大小和公共网络目标，阻止本机、内网、凭据 URL、无限重定向和无界下载。网页内容只是数据，不产生工具权限。
- `ART-004`：下载只接受经文件签名识别的 PNG、JPEG、WebP 或 GIF；记录真实 MIME、字节数、像素、SHA-256、来源页面和最终图片 URL。扩展名和 HTTP `Content-Type` 不能单独证明图片有效。
- `ART-005`：候选下载先进入个人艺术库根下的内部采集区。临时响应未完成、图片无效、尺寸过小/异常或重复时不得形成候选；单张失败不回滚其他真实成功项，结果必须披露成功、跳过和失败数量。
- `ART-006`：候选按完整 SHA-256 在内部采集区、审批区和正式分类间去重。相同字节不能因为不同 URL 形成第二件作品；已存在项返回原身份和位置。
- `ART-007`：新版视觉整理一次只读取和分析一张候选图，避免多图内容互相污染。模型不支持视觉输入时在读取前失败关闭；不能以网页标题、摘要、文件名或确定性模板冒充 AI 识读。旧版一次最多四张的合同被本规则取代。
- `ART-008`：AI 识图后必须分别提交三个结果：面向人的作品解读、三组可编辑标签、结构化反推 Prompt。三者不能合并为一段泛化风格说明；标题、作者显示名、来源、采集日期、建议分类和置信度仍属于完整候审元数据。
- `ART-009`：候审条目是一个完整目录，至少包含原图、`metadata.json` 和 `source.json`。只有元数据和图片都验证成功后，内部采集目录才原子移动到 `approval/<item-id>`；正式分类不能直接接收内部候选。
- `ART-010`：采纳可以带人类修订后的标题、作品解读、三组标签、色板、结构化反推 Prompt、负向约束和目标分类。Runtime 先验证并保存修订，再把整个条目目录移动到 `libraries/<安全分类名>/items/<安全作品名>-<item-id>`；新分类同时创建 `library.json`。目录位置是工作流状态权威，元数据不建立第二状态机。
- `ART-011`：驳回是显式破坏性操作，必须经过当前会话 Tool Policy（工具策略）审批，并且只删除精确解析到个人艺术库审批根内的条目。暂缓不产生文件变更。
- `ART-012`：批准、驳回和候审提交按条目 ID 幂等。精确重试返回已有终态；同一候选使用不同元数据重复提交或同一审批项批准到不同分类时失败关闭。
- `ART-013`：分类风格词导出只读取该分类已批准作品，按稳定作品顺序依次汇集三组风格关键词；清理首尾空白，英文使用 Unicode 小写键去重，中文按规范化完整词去重，保留首次出现的原始显示和值顺序。
- `ART-014`：导出不调用 Provider、不生成新词、不按频率或权重排序，也不包含标题、作者、来源、Prompt 正文和负向词。输出同时包含关键词数组和逗号加空格连接的可见文本，供复制、TXT 导出或发送到对话。
- `ART-015`：艺术库根由 Electron Main Process（主进程）确定，模型和 Renderer（渲染进程）不能传入绝对路径。应用数据根是唯一写入位置，当前创作项目不得承载或镜像个人艺术库候选。
- `ART-016`：打包内 63 条早期 Art Atlas 种子的旧解读、Prompt、标签和分类结果不是新版产品事实。一次性迁移只保留其原图与可信来源，把原图重新送入新版待整理路线；不得把旧元数据转换或伪装成新版视觉结果。本规则取代“把57条直接迁入正式分类、6条迁入候审”的旧行为。
- `ART-017`：旧种子重置只处理具有稳定 `seed` 标识的63条记录，并在破坏性变更前核对数量、原图可读性和 SHA-256。无法证明归属时失败关闭；不得按标题、分类或目录猜测删除，不得影响公网、对话附件或项目图片形成的用户条目。
- `ART-018`：普通会话可以把当前已接纳回合中的图片附件收藏为候选。模型只能按当前回合内的稳定序号选择，Runtime 必须使用与模型输入相同的不可变字节快照；其他会话、历史回合、已结束或未成功接纳的回合不能读取该快照。
- `ART-019`：项目会话可以把当前可信项目内的图片文件收藏为候选。模型只提供项目相对路径，项目身份来自可信 Tool Execution Context（工具执行上下文）；个人会话、其他项目、绝对路径、路径穿越、非图片文件和已变化的项目事实必须失败关闭。
- `ART-020`：公网、当前回合附件和当前项目图片共用同一个候选摄入边界、图片校验、SHA-256 去重和 `incoming → approval → libraries` 状态机。收藏只复制经过校验的字节，不移动、删除或改写附件原文件和项目文件；相同字节跨来源仍只有一个条目身份。
- `ART-021`：生产艺术库页面必须读取 Main Process（主进程）提供的真实 Runtime 投影，并通过真实命令完成批准、驳回、暂缓和风格词导出。`localStorage`、静态 JSON 和展示页面自身状态不得决定工作流事实；展示页面只接受父级注入的当前 Runtime 投影。
- `ART-022`：Renderer（渲染进程）只能通过条目 ID 和受限只读协议显示艺术库原图。Main 必须再次校验 ID、根目录包含关系、记录 MIME 和 SHA-256；Renderer、模型输入、公开合同和持久元数据不得暴露本机绝对路径。
- `ART-023`：`styleAnalysis` 只表示面向用户的作品解读。它必须从当前图片的主体和空间、色彩明暗、构图视角与留白、线条形状、材质质感或对象关系中组织可读解释，并包含至少三个可回指当前图片的具体视觉依据；不得捏造作者意图、年代、流派或背景，也不得以空泛情绪词和跨作品模板代替观察。
- `ART-024`：新版反推 Prompt 的唯一权威结构为 `STYLE / COMPOSITION / SCENE / NEGATIVE`。前三者分别描述视觉语言、画面组织和可替换剧情，负向层描述不需要的渲染、构图漂移、细节、Logo、水印和错误文字。`STYLE + COMPOSITION + NEGATIVE` 必须可复用，`SCENE` 必须可替换；不得用艺术家、品牌、作品名或标题代替视觉描述。
- `ART-025`：作品标签继续由 `patternTags`、`compositionTags` 和 `moodTags` 三组拥有。AI 可以依据真实视觉自由填写，不受固定词表限制；用户可以逐项增加、修改或删除。情绪标签必须有画面事实支持。
- `ART-026`：分类前 AI 不能只看分类名称和数量。只读分类上下文必须提供各分类当前标签、2至4个代表作品或代表视觉摘要，并允许比较媒介与渲染、形状与边缘、色彩与光影、构图与空间、质感与情绪；题材相同不能单独构成同类依据。
- `ART-027`：确定性“导出关键词”和 AI“提取风格”是两个独立能力。前者继续遵守 `ART-013..014`；后者由当前普通会话模型按请求读取一个分类或个人全部作品的当前标签，保留频率和分类关系，生成库级作品解读与结构化 Prompt，不建立专属艺术库 Agent。
- `ART-028`：库级和个人整体风格每次按当前批准作品重新提取，默认只返回当前对话，不固定写回艺术库。用户修改标签后，下一次提取必须反映新事实；需要长期保留时由用户显式导出或保存为项目文件。
- `ART-029`：字段存在、字符串长度、固定模板或本地规则不能证明视觉整理质量。结构测试只证明合同；反推质量必须按方法版本、分类和模型抽样，移除原图、替换 `SCENE` 后只凭文字生成新图，并由人判断视觉语言是否保持。
- `ART-030`：打包内 63 张 Art Atlas 作品是用户预先批准的基础藏品，必须真实物化到正式分类：巨构艺术 41 张、暖色风格 18 张、纪念碑谷 4 张。它们不得进入 `incoming` 或 `approval` 要求用户重复整理或审批。本规则根据 2026-08-11 用户澄清明确取代 `ART-016` 的“全部重置到待整理路线”语义。
- `ART-031`：基础藏品物化必须使用冻结清单中的稳定 ID、原图 SHA-256、seed snapshot 和确定性分类验证所有权。旧 Profile、已执行错误 reset 的 Profile 和中断迁移都必须可安全重试；无法证明归属、身份冲突、哈希变化或目标冲突时失败关闭。不得按标题、现有分类名或目录名猜测所有权。本规则保留并收紧 `ART-017` 的安全不变量。
- `ART-032`：基础藏品直接进入正式库是一次受控产品迁移，不改变以后新增图片的唯一 `incoming → approval → libraries` 状态机。公网、当前回合附件、项目图片及用户已有候选、候审和正式作品不得被迁移改写。
- `ART-033`：艺术库默认入口是可浏览的个人艺术图鉴，而不是分类管理后台。生产页面直接复用 `0.1.19` 提交 `285c018` 的品牌介绍、圆环作品浏览、展览、作品详情、CSS 和动效；允许 iframe 作为该旧视觉的 Presentation Boundary（展示边界），但父级 React 必须注入真实 Runtime 投影与受限图片 URL，iframe 内静态 JSON、`localStorage` 或默认演示值不得决定作品、分类或审批事实。
- `ART-034`：审批是以后新增作品进入艺术库的辅助入口，不能取代图鉴首页。图鉴必须能进入真实分类展览、真实作品详情、候审审批、确定性关键词导出和普通会话 AI 风格提取；恢复视觉不得删减这些现有能力。

## 当前不做

- 视频、音频、网页快照、账号同步、公共收藏和版权授权判断；
- 专用艺术库 Chat、后台常驻采集任务和跨设备队列；
- 自动持久化库级或个人整体风格结论、后台自动重算风格；
- 绕过人类审批让后续新增图片直接入库；63 张用户预批准基础藏品属于 `ART-030` 的受控迁移例外；
- 追溯导入所有历史对话附件；第一版只支持当前已接纳回合的图片快照。
