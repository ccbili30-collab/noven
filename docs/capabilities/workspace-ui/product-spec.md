# Workspace UI 产品规格

## WUI-001 真实 Electron 表面

第一条骨架必须通过生产 Electron Renderer 操作，不能只提供后端测试页或浏览器 Fixture。Renderer 只使用稳定 CreatX Desktop API（桌面接口），不得 import Cline 类型。

## WUI-002 对话与创作画布按任务切换主次

打开项目后，项目导航、真实对话和动态工作台资源栏持续存在；创作画布按当前布局模式出现。Chat 模式以完整对话为主，工作台资源与画布收起；Workbench 模式采用 VSCode 式三列表面：左侧工作台/文件资源，中间真实 Markdown、图片或展览画布，右侧 AI 对话。文件、会话和运行状态详情不得以常驻检查器卡片遮挡作品，必须通过工作台标题栏的按需详情入口打开。不能退回旧版整页聊天、右侧工具抽屉或固定工作台轨布局。

## WUI-003 原生审批可见

未知工具和副作用工具的 Cline 审批必须在真实界面展示工具名称、输入、允许与拒绝。批准 Cline 文件或 Shell 工具时必须说明该次调用可能访问整台机器；界面不能把项目目录描述成沙箱。

## WUI-004 同一文件的文件与预览投影

AI 写入真实项目文件后，右侧文件入口和预览显示同一个 `projectId + relativePath` 文件身份。界面不保存正文副本，也不以视觉流式动画冒充文件已写入。

## WUI-005 真实状态与失败

回复、等待审批、工具运行、成功、失败、取消和结果未知来自 CreatX 合同。Renderer 不根据动画结束或客户端确认自行判定 Run 或工具成功。

普通用户消息成功进入 `running` 后，如果当前回合还没有 Assistant、Reasoning（推理）或工具内容，Assistant 一侧必须立即显示“正在准备回复…”状态。它只表达 Run 已接纳并等待首个真实活动，不冒充模型推理；首个真实活动、失败、取消、结果未知或会话切换后立即移除。

## WUI-006 侧聊延期且隐藏

第一条生产骨架不渲染侧聊入口、禁用按钮或 Fixture 会话。侧聊视觉可以保留在 Prototype；只有真实 Session 能力完成后才进入生产界面。

## WUI-007 可恢复界面

正常重启后界面读取 Cline 已保存历史和当前项目文件。旧活动 Run 不显示为仍在运行或已经完成；用户可以发送新的“继续”回合。

## WUI-008 动态工作台树

内置 `builtin:files` 与注册工作台统一进入工作台下拉选择器。选择工作台只改变树的真实 Projection（投影）和画布来源，不替换、压缩或复制对话组件。内置“文件”保留项目中全部普通可见文件作为兜底视图；注册工作台是面向创作浏览的策展视图，不显示 JSON 实现文件，也不保留因此变成空壳的机器目录。真正的空目录仍按真实状态显示。选择文件后，中央画布读取同一个 `projectId + fileId`。固定“世界/小说/派系”等 Fixture 分类、`data-command` 事件和原型本地状态不得进入生产。

工作台注册、缺失和诊断语义归 `workbench-registry`；Renderer 只显示其稳定 Projection，不解析 `.creatx`。

注册工作台存在有效 V2 主页时，选择工作台后画布立即进入该主页的交互预览，不要求用户再点击文件。AI 的会话级展示请求在项目、会话与工作台身份都匹配时切换当前画布，但不能覆盖尚未保存的编辑草稿。主页缺失、加载失败或令牌失效时显示可理解的失败状态并保留文件树入口。

## WUI-009 Growth 状态是主会话内的真实投影

项目存在 Growth Goal 时，主会话在输入框上方显示真实状态、版本、waiting 原因和当前合法操作；不存在 Goal 时不显示占位进度。审批/自由模式使用可见切换，Growth 运行时保持输入可 Steer。暂停、继续和结束只调用稳定 Desktop API，Renderer 不推断状态或伪造百分比。图片队列不新增独立页面，但在输入区上方提供当前项目紧凑活动栏；内部阶段 Prompt 不作为用户消息显示，但 Agent 回复、工具、文件和分类失败保持可见。

同一自动修复阶段产生的同状态、同错误类型和同摘要 Issue 在界面聚合为一张状态卡，次数与全部技术详情仍可展开，Growth Store 的逐条审计记录不删除。`repairing` 保持红色“正在自动修复”；收到可信修复回执后立即以绿色“已修复完成”替换，安全绕过提交成功后显示绿色“已绕过”，两者均停留 3 秒后自动消失。`needs_help`、`waiting_user` 和其他需要用户行动的问题不得因聚合而隐藏。授权恢复、模型声称成功或普通重试结束都不能单独触发绿色状态。

## WUI-010 项目入口只打开已有文件夹

生产项目入口复用 `chooseProject()` 打开用户选择的已有文件夹，不创建、复制或初始化目录。可访问名称必须使用“打开项目”或“添加已有项目”，不能显示为“新建项目”或“创建项目”。回收站和侧聊延期期间不进入生产可访问树，也不增加占位 IPC。

## WUI-011 外部附件是受控文件引用

用户通过生产 Electron 的原生文件选择器或 Chat Drop（对话拖放）选择项目外文件；Renderer 只获得短期授权 ID、文件名、类型和受限预览 URL，发送时不得提交任意绝对路径。文本文件通过 Cline `userFiles`；真实签名匹配的 PNG/JPEG 经过单图 10 MiB、单批 20 MiB 门禁后通过 Cline `userImages`，不能作为 UTF-8 文件发送。

待发送图片在 Composer 显示缩略图，持久消息从 Cline 图片内容重新投影缩略图并可打开大图。图片字节只通过 `creatx-attachment://` 受限协议按 `sessionId + messageId + attachmentIndex` 读取，不使用 `file://`、通用路径 IPC 或 Renderer 绝对路径。Cline 历史继续拥有正式消息和图片内容；CreatX 不建立第二套消息或附件数据库。文本历史附件仍由 Main 从 Cline 历史解析并复查真实文件后打开。伪造图片签名、缺失、变化、超限和含 NUL 的未支持二进制在 Provider 请求前失败关闭。

## WUI-012 生产默认纸张世界构建表面

Production V1（生产第一版）的 Renderer 默认使用 2026-08-03 批准的纸张世界构建视觉：暖白纸面、细分隔线、克制金色强调、五区固定阅读秩序和中央文档画布。整个页面以新版结构为唯一布局权威，旧玻璃壁纸、模糊卡片、独立文件/预览抽屉和右工作台轨不再参与生产渲染。

Renderer 仍只消费稳定 CreatX 合同。预览中的地图、路线、元数据和绘图按钮只有存在真实生产来源时才能显示；未接通能力必须隐藏，不能用示例地图或 Fixture 冒充项目事实。项目主题文件、设置入口、主题继承和持久切换仍延期。

## WUI-013 会话直接渲染 Markdown 与项目图片

用户、Assistant（助手）和系统消息使用同一套安全 Markdown 渲染，支持标题、段落、强调、列表、引用、代码和 GFM（GitHub 风格 Markdown）表格。消息中的原始 HTML 不执行。

Markdown 图片只能使用当前项目内真实图片的相对路径。Renderer 将路径匹配到当前 `ProjectSnapshot` 的图片 `fileId`，再通过既有 `readFile(projectId, fileId)` 获取 `dataUrl`；不得传递绝对路径，不新增消息图片副本或通用文件读取接口。远程 URL、`file://`、Data URL、绝对路径、路径穿越和不存在的项目图片失败关闭并显示不可用状态。

流式文本增长或无关项目投影刷新不得卸载已经加载的会话图片、重新显示读取占位或重复读取未变化文件。文件项目、身份或修改时间真实变化时才重新读取。Chat 中的图片使用不超过 `460px / 46vh` 的对话级展示上限并随窄容器收缩；工作台作品展示与图文环绕继续使用自身版式，不受 Chat 尺寸覆盖。

## WUI-014 Composer 模型与附件入口

Composer（输入区）底栏左侧以 `+` 打开小菜单，外部文件引用的回形针位于其中；权限只显示当前“审批/自由”状态并可点击切换；右侧显示当前交流模型名称，点击打开已保存连接和“模型配置”。模型配置使用独立抽屉分开交流模型与生图模型。生图配置不是直接生图按钮，且不把会话模型切换成图片模型。第一版不显示语音入口。

## WUI-015 可调整工作区布局与 CreatX 品牌

Workbench 模式各区之间的竖向边界必须是可拖动的真实分隔控件；Chat 模式只保留当前可见区域之间的分隔控件。拖动只调整相邻区域或由主工作表面吸收变化，每个固定辅助区域有明确最小与最大宽度；方向键提供同等调整能力。Renderer 将面板宽度保存为本机 UI 偏好，页面重载后恢复；该偏好不是项目事实，不进入 Desktop API、项目目录或 Cline 会话。布局模式不作为全局偏好跨会话继承。

窄窗口继续按既有规则隐藏检查器并自动收起项目导航，不得为了保留第四条不可见边界造成页面溢出。项目导航顶部显示原生 SVG 飞鸟和 `CreatX` 文字标；当前项目名称与路径保留为独立的打开项目入口，不再占用品牌位置。SVG 不得嵌入原始 JPG 或依赖远程资源。

## WUI-016 同源 Web Preview

开发期网页版必须直接导入生产 `WorkspaceShell`、Markdown 组件和生产 CSS，使浏览器热更新与 Electron 使用同一份 React/TSX/CSS 源码。不得复制页面组件形成第二套 UI，也不得在确认后再人工同步文件。

Web Preview 使用独立内存 Adapter 提供演示项目、消息、工作台、文件和回调。浏览器不得定义或调用 `window.creatx`，不得接入 Electron、Cline、项目文件、Provider、Growth Runtime、图片队列或凭据。页面必须持续显示“演示状态”标记；Fixture 交互只能证明视觉与浏览器行为，不能作为生产 Live 证据。

## WUI-017 全局项目与工作台导航外壳

第一栏必须表达应用级与项目级导航，而不是把当前项目包装成独占整栏的切换卡片。顶部显示用户提供的原始飞鸟 SVG、`CreatX` 与真实全局操作；项目区把当前真实项目作为文件夹根，项目下只显示注册工作台，不显示会话、新会话入口或会话置顶区。长标题单行省略；未加载项目的工作台不得由其他项目 Fixture 或会话标题猜测。

项目列表仍从全部持久 Cline 会话的 `projectId + displayPath` 与当前打开项目投影，不建立第二份项目内容事实。工作台只读取 `WorkbenchSnapshot`。项目置顶、显示别名和“从列表移除”只属于本机界面偏好；重新打开被移除目录后必须恢复显示。

项目行悬停时只显示项目菜单。项目菜单允许前端置顶、通过 Main Process（主进程）受控打开资源管理器、编辑本机显示别名、永久删除该项目全部 Cline 会话、从本机列表移除。删除必须明确二次确认，不能称为归档或暗示可恢复；删除项目聊天不得删除项目文件。存在活动 Growth Goal（生长目标）或运行中会话时，后端必须拒绝删除。

“打开项目”以“项目”标题右侧的紧凑图标呈现；新会话入口位于 Conversation 和右侧项目工作台会话区。标题上方显示艺术库、点子库与传承库等真实全局入口，不再显示会话置顶层。艺术库可在注入明确的外部导航回调后启用，但不得因此虚构艺术库数据合同或把开发 Fixture（测试夹具）称为生产数据；点子库入口按 WUI-028 进入独立浏览页面。

右侧项目工作台中的会话标题支持改名、永久删除和切换，改名与删除继续通过 Cline 历史元数据和现有 Desktop API，不能只修改 Renderer 临时状态。Composer 权限按钮点击后打开“审批 / 自由”选择栏；Growth 运行期间仍由既有门禁禁止离开自由模式。

## WUI-019 斜杠 Skill 选择与确定性启动

Composer 输入首字符 `/` 时，必须从 Creative Skills（创作技能）权威命令目录显示可搜索、可点击且支持键盘选择的命令列表。菜单只负责选择和插入规范命令，不自行创建 Goal、加载 Skill 或伪造运行状态。

Renderer 与 Main 使用同一命令目录。`/growth-world`、`/growth-world-pro` 等已声明别名在进入路由前规范化为下划线形式；Growth 命令必须由 Main 确定性创建或转向持久 Goal。未知的首部斜杠命令必须在 Provider 调用前以 `command_invalid` 失败关闭并提示从列表选择，不能作为普通消息交给模型模仿执行。普通自然语言不受此门禁影响。

已提交的已知斜杠命令在当前 Renderer 页面中必须像普通用户消息一样可见。Growth 命令没有进入 Cline 对话历史时，只保留未匹配的本地消息并在相同持久用户消息出现后去重；它不是新的持久消息事实，刷新或切换会话后可以消失。

## WUI-020 内置艺术库界面入口

艺术库是 CreatX 自有但保持独立视觉空间的静态应用。其可运行页面、浏览数据和展示缩略图必须随 Web Preview、Electron 构建和发布包一同输出，默认入口不得依赖仓库外路径、独立本机服务或另一个项目的运行状态。`WorkspaceShell` 接受内置艺术库地址；全局导航入口与中央图片预览必须进入同一个内部艺术库页面。未提供地址时入口禁用且图片保持普通预览。图片入口必须具备键盘可达名称，悬停或聚焦只做轻微缩放，不改变真实文件内容。

艺术库必须内嵌在 CreatX 主界面：保留左侧全局项目导航，以艺术库替换其右侧整个创作工作区；选择左侧项目、会话或其他全局页面即恢复相应工作区，不再叠加重复的悬浮返回按钮。不得打开额外浏览器标签、浏览器窗口或 Electron 子窗口。Art Atlas 可通过受限内嵌文档维持自己的视觉与路由边界，但不得读取 Electron、Cline、Provider、项目文件或凭据。默认地址解析到当前应用自身携带的 `art-library/art-atlas.html`；打包后的 `file:` 地址只允许落在同一内置目录，HTTP(S) 地址只用于受控开发验证。首批迁入只包含静态浏览、详情和本地审批演示；依赖外部原始资料库的生成器与写入服务不属于该闭环。

会话与点子库使用的 CreatX 语义色板是应用唯一的外壳色彩权威。进入或离开艺术库不得改变项目导航的背景、文字或边界色；同源内嵌 Art Atlas 在每次页面加载和内部导航后读取外壳的纸色、墨色、弱文字、边界、强调色和暗轨色，只保留自身的展览排版、图像与动效。不得再用页面状态类维护第二套导航色板。

Art Atlas 首次片头保留七张作品依次入轨；第七张完成后，轨道从 `100%` 平滑放大到 `125.6%`，HUD 四舍五入显示 `126%`，稳定态在当前桌面画幅呈现五张可见作品。跳过已观看片头时直接使用同一倍率。七个轨道槽仍须保留，离屏作品可以按既有图片生命周期卸载，不能为保持七张解码而牺牲运行性能。

首页在“审批 / 展览”两个入口的几何中点下方显示全大写 `CHAT`。默认文字极淡；鼠标靠近时平滑变为金色并出现克制的分层文字阴影。该位置必须绑定入口组自身，不能依赖视口硬编码坐标。真实艺术库会话尚未接入时，该标记必须保持不可点击，不能伪造提交、回复或持久化。

## WUI-021 领域投影隔离

Timeline（时间线）、Project（项目文件）、Workbench（工作台）和 Growth（生长状态）必须由各自的稳定事件更新。Renderer 不得根据工具名称或工具显示状态猜测项目内容已经变化；真实内容或工作台写入成功后，由写入所有者或 Main 集成边界发布明确的投影失效事件。

项目刷新、文件选择和预览请求必须带有同一项目世代。迁移、删除、切换项目或刷新使选中文件失效时，选择和预览必须原子清除；较早请求的迟到结果不得覆盖较新的项目或文件选择。`.creatx`、机器回执和内部状态始终排除在作品 Projection 之外；遗留在普通内容目录中的 JSON 仍可由内置“文件”查看，但不得进入注册工作台。

## WUI-022 流式输出不接管滚动

Assistant 文本增量、内部推理、工具更新、Growth 进度和项目刷新不得主动改变用户的对话滚动位置。用户发送消息时可以执行一次明确定位；之后只有用户滚动到底部或点击“回到最新”才恢复到底部。用户不在底部时，新内容以非侵入提示表达，不能使用逐 Token 的 `smooth` 或 `auto` 滚动追赶内容。

## WUI-023 对话回合与处理详情分层

每个对话回合在外层只突出用户消息和本轮由 Cline `done.outputText` 确认的最后一条已完成 Assistant 回复。此前的 Assistant 过程文字、Reasoning（推理）、工具和 Growth Worker 活动统一进入该回合的“正在处理 / 已处理”详情；运行中不得提前把阶段说明当作最终回复，也不得由 Renderer 猜测哪段文字是最终回答。

处理详情默认折叠，展开后必须限制高度并在内部独立滚动。Worker 对象身份、真实顺序、成功/失败和结构化错误仍需保留；多个并行 Worker 不得丢失来源后变成外层工具瀑布，内部英文过程不得作为正式回复。Runtime 错误、等待用户检查和 Growth 操作保持在折叠区外。Growth 进度继续只来自持久 Goal 与 Materialization 状态，不能通过 Worker 文本或工具数量推断。

Growth Worker 使用隐藏 Cline Session 时，其消息历史仍是唯一持久活动事实。凡 Session 元数据标记为内部 Growth 阶段，其 user-role 阶段 Prompt 一律不投影为用户消息；不能依赖 Prompt 文本前缀判断。所有 Worker 的最终 `outputText` 只进入带谱系身份的内部活动，绝不能提升为 Owner Assistant 汇报。Owner 最终回复只来自同一 Owner Cline Turn。重新打开应用或会话后，Owner Timeline 必须按持久父子元数据恢复活动，不得另建消息数据库。新 Worker 在创建时冻结人类可读对象标题，旧记录缺少标题时回退到对象 ID。跨 Worker 的精确 Token 交错没有持久证据时，只按 Worker Session 创建顺序恢复，不得伪造原始交错时序。

## WUI-024 可收起、可直接编辑的工作台

工作台目录栏始终保留；画布可以单独收起，详情只作为工作台标题栏的按需抽屉出现，默认不存在于 DOM。收起键固定在画布工具栏最右侧，收起后目录栏提供稳定的重新展开入口，同一个主会话组件横向占用画布释放出的空间。画布通过约 220ms 的宽度与位移过渡滑出，隐藏后不得继续接受焦点；重新展开不重建目录、会话或编辑草稿。展开与收起只属于当前会话的 Renderer 布局状态，不改变项目、会话、文件或工作台注册事实，也不通过全局偏好污染其他会话。左侧项目导航使用与工作台一致的面板收起/展开图标。

Markdown 与纯文本在工作台中默认显示渲染结果。工具栏只保留一个铅笔图标作为编辑入口；进入编辑后显示草稿级撤销与重做按钮，并支持标准 `Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z`。按钮与快捷键共享最多 100 个草稿快照，新的编辑清空重做分支，成功保存后清空本轮历史；该能力不得冒充文件版本恢复。失焦、再次点击铅笔或 `Ctrl+S` 必须进入同一带 `expectedModifiedAt` 的保存事务，成功后回到渲染态。外部版本冲突时失败关闭并保留当前编辑态与草稿。切换文件、项目、会话、工作台或展览模式前先完成同一保存事务，失败时不得离开当前编辑上下文。图片和其他文件保持只读。

固定展览模式只从当前工作台真实 Projection 形成分组、文本卡和图片卡；点击项目仍回到同一真实文件。它不建立小说、角色、地点等固定后端，不读取或展示 `.creatx` 与 JSON 机器状态，也不生成任意 HTML。

## WUI-025 轻量项目版本感知

真实内容写入后，Project Files 所有者在 `.creatx/project-revisions/state.json` 保存单调递增 Revision（版本号）及最近 100 条路径、来源、操作、时间和内容 SHA-256；不复制正文、不初始化 Git，也不把内部状态投影到工作台。

普通项目会话在下一次 Provider 回合前把最近变更以 Cline 原生隐藏运行上下文提供给模型，要求其读取相关文件的当前内容；用户消息仍只显示原话。该索引是导航和变化信号，不替代真实文件，也不声称检测当前第一版之外的任意外部编辑历史。

## WUI-026 界面外观偏好

设置页必须提供可用的“外观”分类。字体提供系统默认、现代无衬线和阅读衬线三类受控选项；字号分为两个互不覆盖的 12–18px 设置：“界面字号”控制导航、目录、菜单、按钮、状态与设置页，“阅读字号”控制用户/Assistant 正文、Composer、Markdown 预览和文本编辑器。工具过程、Reasoning 和 Growth 控件属于界面层。选择立即作用于当前 Renderer，并写入本机 `localStorage`，重新加载后恢复；无效或损坏值回退为系统字体、13px 界面字号和 15px 阅读字号。旧单一字号偏好必须迁移为两个相同值。

外观偏好不是项目事实，不进入 Desktop API、项目文件、Cline 会话或作品 Revision。阅读字号只改变本机显示，不改写 Markdown 文件，也不得通过页面缩放改变工作台几何。工作台编辑/展览切换使用无外框控件，只以激活底色表达当前模式。画布收起与会话展宽必须使用可连续插值的网格宽度，目录标题栏为重新展开控件保留稳定位置，不能在切换时离散跳变。

## WUI-027 统一分隔线

所有持久主区域之间使用同一种 Separator（分隔控件）：视觉上只显示一根 1px 中性线，悬停、聚焦和拖动只改变线色，不改变线宽、不增加阴影或额外把手；透明命中区仍须足够支持 Pointer 拖动。方向键、最小/最大宽度和现有本机宽度持久化继续有效。Pointer 移动期间不得通过 React 状态重建完整工作区，也不得写入布局偏好；只允许更新布局变量，释放 Pointer 后一次性提交最终宽度并持久化。

此前“画布收起时在目录区域内联预览文件”的规则已由 `WUI-028` 替代；真实文件身份和完整工作台编辑能力不变。

## WUI-028 Chat 优先的双模式工作区

首次打开尚未形成作品的新项目时默认进入 Chat 模式：画布收起，项目导航保持辅助宽度，对话使用全部剩余空间。项目树下只展示真实注册工作台，不展示新会话入口或会话列表；会话属于右侧项目工作台区域。工作台入口以平级创作空间卡片呈现，不伪装成文件夹层级。

用户点击工作台入口或点击“展开工作台”后进入 Workbench 模式；点击工作台入口必须直接显示工作台首页、最近文件或真实作品，不得留下中央空白。每个工作台入口在项目下拥有独立资源展开状态；当前工作台再次点击只收起其资源，中央作品继续保持。项目、工作台和目录的展开状态不等于选择或打开状态。中间画布读取工作台真实展览，右侧 AI 对话显示当前项目会话切换条和完整会话。点击文件先沿用既有保存门禁，再读取同一真实文件；点击会话只切换右侧对话，不清空中央文件。左右栏均可独立收起并按比例恢复。切换会话必须先通过保存门禁，并保留当前工作台、文件、画布、编辑状态和面板宽度；保存失败则留在原工作台编辑状态。Chat 与 Workbench 复用同一个逻辑对话实例，表面切换不得重建 Composer 草稿、滚动位置、流式状态或 Growth 投影。

## WUI-029 Codex 参考比例下的主内容构图

Chat 模式以 Codex 同尺寸桌面参考的几何比例为权威，而不是让对话内容和 Composer 铺满全部剩余宽度。宽屏项目导航与工作台目录各使用约 18.5% 视口宽度并封顶 472px；中央 Conversation 吸收剩余空间，但回合、空态、Growth、错误、附件和 Composer 共享最大 1100px 的居中内容列。Composer 空态保持约 94–100px 高、16px 圆角，普通工具按钮约 30px，发送按钮 34px；导航标题图标为 18px，文件树图标为 16px。

面板拖动能力继续保留。Workbench 的完整 AI 对话默认 320px，可在 280–620px 安全范围内连续拉伸；达到下限后不得继续压坏正文。布局偏好升级时不得继续采用旧的窄栏默认值；窗口缩放后，已保存的项目栏、AI 对话和工作台目录宽度按视口比例同步缩放并受各自最小/最大值限制，不能在较窄窗口保留宽屏像素值而压扁主区。精确几何规格见 `creatx/apps/desktop/renderer/CODEX-PROPORTION-SPEC.md`。

## WUI-030 Owner 对话与 Growth 活动分层

Renderer 只把 Owner Cline 历史中的用户消息和正式 Assistant 回复放在外层对话。与当前 Owner Growth Run 有正式谱系关系的阶段、Worker、工具和问题进入独立活动区；不得把无父子合同的 Worker 输出手工合并成 Owner 回复。

## WUI-031 运行展开与终态折叠

Growth 运行中活动默认展开，让用户看到可理解的阶段、进度、对象和错误；原始 Reasoning（推理过程）默认折叠。进入 `completed`、`failed` 或 `cancelled` 后活动区按产品规则自动折叠，正式 Assistant 最终回复保持普通消息可见，不得藏进“思考”。终态折叠时只挂载摘要，用户展开后再挂载内部明细，不能为了保留历史而在后台预渲染数百个不可见节点并拖死会话界面。

活动区是否展开必须由当前 Session 自己的 Run State 与当前项目的 Growth 状态共同决定。Renderer 必须按 Session 保存运行投影，并在过滤非当前会话的 Timeline 事件之前接收该会话的终态事件；不得让其他会话最后一次 `running` 状态跨会话、跨项目或跨恢复沿用。

## WUI-032 权威状态分别投影

对话读取 Cline，进度与终态读取 Growth Store，作品内容读取 Project Files。工作台文件生长不能由聊天文字推测；对话也不能展示项目 JSON、蓝图内部状态或 Renderer 临时缓存，除非用户主动打开对应内置文件视图。

## WUI-033 仅在底部黏附流式输出

只有用户在主对话滚动区已经停留在最下方时，流式消息和 Growth 活动才可继续保持在底部。实现可以保留不超过 8px 的滚动取整容差，但不能把明显离开底部视为仍在黏附。用户一旦向上滚离底部，新增内容不得拉扯现有滚动位置，只显示“回到最新”；用户自行滚回底部或点击“回到最新”后才恢复黏附。跟随只设置最终滚动位置，不使用逐 Token 的平滑滚动；活动区自身的长内容继续在内部滚动。
## WUI-034 点子库瀑布流

点子库是应用级独立创意浏览页面，不属于当前项目文件树或注册工作台。进入页面不得卸载或重置当前项目、会话、工作台选择和编辑上下文；必须提供明确返回创作区的路径。

首批页面使用可追溯的内置整理样本验证卡片密度、中文换行、搜索和双库筛选。灵感库只保留“启发 / 幻想”两个用户可见库：句末为中文或英文问号的完整问题进入“启发”，其他陈述式世界观、异世界和有趣点子进入“幻想”。旧 JSON 的题材字段继续兼容但不参与页面分类；科幻、历史、穿越等只作为搜索标签，不再成为一级题材筛选。

每张普通卡片只以一句完整中文点子为正文，保留画面、因果和人物处境；除作者与明确的本机热度名次外，不默认显示来源、采集时间、题材标签、版权备注或内部 Prompt，也不得压缩成标题、广告标语、关键词或标签堆。点子使用统一米色、尾巴朝右的消息气泡作为正文视觉语法，通过三档稳定宽度、字级和少量主角强调形成阅读节奏；作者和操作位于独立页脚，不得添加虚构聊天身份、时间或已读状态。气泡高度由真实句长自然决定，页面使用单一垂直滚动所有者。

点子卡片以一句完整创意为主体，并显示明确作者和紧凑的喜欢、收藏、分享操作。喜欢与收藏是当前设备上的个人状态，不显示公共计数，不暗示远端互动；本机热度固定为“收藏 2 分、喜欢 1 分”，只用于当前筛选结果的降序排列，同分保持原有顺序。用户导入条目与内置样本必须保持来源身份分离。页面提供原生 JSON 导入和本机刷新，刷新只重读本机 Store，不联网采集、不覆盖用户条目。

分享按钮打开已有会话选择面，确认后将带来源标识的点子作为正常用户消息提交到所选 Cline 会话，并切换到该会话展示真实发送状态。不得只写入剪贴板、Composer 草稿或显示伪成功提示。

## WUI-035 本机传承库互动

传承库继续展示公开创作方法的可追溯入口，并与点子库共享本机喜欢、收藏、JSON 导入、刷新和会话分享语义。卡片显示作者；详情保留来源平台跳转、AI 解读状态和 Skill 尚未生成的真实边界。第一版不因新增互动而伪造已读取视频、已生成 Skill、公共热度或联网更新。

## WUI-036 艺术库专属 Chat

Art Atlas 的 `CHAT` 只发送受控导航意图，真实对话在外层 Renderer 的独立纯净页面中运行。该页面不展示作品图片，保留返回展览及进入审批的明确入口，并复用当前生产 Conversation、Composer、审批、流式消息、取消和错误语义。

每个项目最多绑定一条艺术库专属 Cline 项目会话。绑定由本机创作资料库 Store 持久化，不能依赖会话标题识别；绑定指向不存在的会话时创建并绑定新会话。离开艺术库 Chat 不取消运行，重新进入恢复同一真实历史。未打开项目或 Cline 会话创建失败时失败关闭，不显示可用 Chat。

## WUI-037 内部过程仅在底部黏附

展开的活动过程拥有独立于主对话的滚动状态。活动过程停留在最底部时，流式推理、工具和 Worker 活动继续贴底；用户向上滚离底部后，新增内容不得改变其阅读位置，重新滚到底部后恢复跟随。活动过程收起后重新展开时显示最新内容；已完成过程重新展开时保留其既有阅读位置。内部滚动不得驱动或重置主对话滚动。

## WUI-038 当前项目图片活动栏

Renderer 在项目打开时通过稳定 Desktop API 读取该项目图片任务快照，并用 `image.task.changed` 增量更新；切换项目先清除旧投影，再读取新项目。活动栏默认一行显示真实完成数、总数、当前图片和排队数，展开后依次分为正在生成、等待生成、失败待处理和已成功/已取消短暂反馈。排队任务允许跳到最后和取消，生成中只允许取消，失败或中断允许重试和取消；重试进入项目队尾。失败原因必须直接可见并可展开技术详情。成功绿色反馈 3 秒后消隐，持久任务不删除。活动栏不得读取 SQLite、推断 Provider 状态或显示其他项目。

## WUI-039 工作台图文与 HTML 展示

Markdown 正文中的项目相对图片引用是文章—图片关系权威。宽屏普通插图默认右侧环绕，横向大图按实际宽高比全宽显示；窄屏取消浮动并上下排列。布局不得改变正文文件，也不得通过同名文件猜测图片。

普通 `.html` 文件点击后复用现有 `creatx-workbench://` Token、MIME 和 Content Security Policy 进入隔离 iframe。Renderer 不使用 `dangerouslySetInnerHTML`、`file://` 或 Data URL 执行 HTML，不向预览暴露 Electron、Cline、Provider 或 Node 私有接口。HTML 第一版只预览，不提供源码编辑切换。

## WUI-040 工作台预览与流式事件稳定性

项目图片通过受限 `creatx-workbench://` URL 按需加载，Desktop API 不把完整 Base64 图片作为常规 Preview 跨 IPC 复制。无关项目写入不得卸载或替换当前文件 Preview；只有选中文件身份或 `modifiedAt` 真实变化才重新读取，并在新结果就绪后一次替换。文件消失时原子清除选择，迟到结果不得覆盖后续选择。

同一 Session、同一 Timeline Item 的高频流式 Upsert 必须在 Main 到 Renderer 的边界按刷新帧合并为最新状态。终态及其他同 Session 事件发送前先排空该 Session 的待发 Upsert，不能因合并改变事件顺序或吞掉最终文本。Renderer 更新已有 Item 时不得每次执行全数组过滤和排序；折叠活动和未选中工作台不应因无关增量反复构造大对象。

## WUI-041 预期取消不显示故障

用户主动取消 Growth 后，Renderer 继续显示真实 cancelled 终态和短暂结束反馈，但不得把缺少 Assistant 回复投影为红色持久化错误。只有 Runtime 明确报告非取消的真实持久化、协议、Provider 或工具故障时才显示对应错误；UI 不通过文案猜测错误类别。

## WUI-042 桌面基础交互语言

Renderer 对项目、工作台、目录和文件使用同一层级交互合同。展开、选中、打开和表面模式分别管理；每个可展开节点具有独立状态、正确方向图标、完整行命中区、`aria-expanded` 和键盘操作。折叠导航不改变中央内容；文件打开不折叠父目录；再次展开恢复此前目录状态。相同视觉控件必须具有相同语义，无行为按钮不得投影。

Menu、Popover 和 Dialog 统一处理 Escape、外部点击、初始焦点和关闭后的焦点恢复。异步动作统一投影进行中、成功、失败与可重试状态，失败保留原工作上下文。面板拖动到可读下限后转为折叠或紧凑形态，不能继续压缩完整 Chat 正文。

## WUI-043 项目对话、工作台布局与本机消息操作

完全展开的生产桌面固定为“左侧全局导航 / 中左 Chat / 中右工作台画布 / 最右工作台导航”。项目下展示所属会话，不再展示工作台；Chat 和工作台组件不得因表面切换换位或重建。窗口空间不足时先折叠左侧导航，再折叠最右工作台导航；最右导航向右收起、向左恢复。左侧导航取消 `220px` 拖拽硬下限，可连续压到 `52px` 并进入真正折叠态，重新展开恢复拖动前宽度。

Chat 顶部显示当前项目名称。操作系统文件拖入整个当前 Chat 面板后成为待发送附件，不自动发送，并复用 `WUI-011` 的短期授权和失败关闭合同；工作台表面不接收聊天附件 Drop（拖放）。

用户消息提供本机 `删除 / 修改 / 重发`：删除只持久隐藏本机投影；修改和重发把内容作为新回合发送并隐藏原用户消息，失败时恢复原消息。Cline 历史、AI 上下文、已有回复、工具和文件副作用均不改变。界面必须说明该边界，不能称为撤回、历史重写或副作用回滚。核心动作具有可见或键盘替代路径，不只依赖 Hover、右键或拖拽。

状态：Integrated With Bounded Electron Evidence（已集成并取得有界 Electron 证据）。布局、会话命名、Drop 覆盖层、删除重启、修改/重发成功与失败恢复已在隔离 Electron 中通过；文件路径授权和失败关闭由定向测试覆盖。真实操作系统拖入仍需人工验收，不能由脚本构造的 DOM `File` 代替。

## WUI-044 创意库分享接收与大列表交互

创意库“发送到对话”只在 Runtime（运行时）明确接收用户消息前保持提交等待；接收成功后立即关闭选择面并让 AI Run 在后台继续，不能等待完整 Provider 回复。接收前失败必须保留选择面和真实错误；接收后失败继续由 Session Run State（会话运行状态）与 Runtime 错误事件投影。该分享合同不得改变普通 Composer 发送等待完整 Run 的既有语义。

分享选择面在提交期间仍可通过 X、Escape 和遮罩关闭；关闭不取消已接收或正在接收的 Run。会话列表支持标题和路径搜索，并在大列表下只挂载可见窗口；不得通过截断条目换取性能。全屏遮罩不得对图片密集背景使用动态模糊。

## WUI-045 对话打开时一次性定位到底部

每次真正进入或切换到一个会话后，Renderer 必须等待该会话历史首次非空提交到主对话滚动区，再立即定位到最底部一次。空历史不消费本次定位；同一打开周期内的 React 重渲染、工作台开关、窗口缩放和历史后续提交不得再次触发打开定位。离开该会话后再次进入形成新的打开周期，可以重新定位一次。

打开定位只负责初始阅读位置，不取代 `WUI-033`：首次定位完成后，用户仍在底部时流式输出继续黏附；用户向上滚离底部后新增内容不得抢走位置，并继续使用“回到最新”恢复。Chat 与 Workbench 表面切换复用同一逻辑对话实例时不得被误判为重新进入会话。

## WUI-046 传承库目录由可核验数据驱动

内置传承库保持 20 条版本化目录，`OC创作`、`艺术欣赏`、`世界观`、`图画创作` 各 5 条。分类和来源筛选由目录数据生成，不能由页面组件另行硬编码；升级目录不得覆盖用户 Profile 中的导入、喜欢或收藏。

每条内置内容必须保留可追溯 HTTPS 来源、作者或机构、内容摘要与可转化的创作方向。摘要只描述已核验的来源内容；无法读取正文或视频时必须明确标为尚未核验，不能根据标题推断。来源不设平台配额，方法内容优先可稳定核验的中文来源，艺术欣赏可使用博物馆、美术馆和艺术家官网。

## WUI-047 工作台画布与导航边界可调整

Workbench 完全展开时，中央画布与最右工作台导航之间的 `workbench-canvas` 分隔线必须支持指针连续拖动和左右方向键，并调整最右工作台导航的宽度。宽度沿用 Renderer 本机偏好持久化，保持既有 `168–520px` 边界，并为中央画布保留至少约 `300px` 的预算。该边界只有最右导航折叠或当前布局不显示它时才不可操作。

## WUI-048 对话项目引用打开现有工作台

对话中的当前项目图片和标准 Markdown 相对文件链接必须复用现有 `openWorkbenchFile` 打开链，展开工作台并展示同一 `projectId + fileId` 的真实文件。项目图片本身是键盘可达的打开控件；临时聊天附件继续只使用附件预览，不按名称猜测项目文件。

相对链接可以携带 `#标题`。工作台完成真实文件打开后定位到匹配 Markdown 标题；没有匹配标题时仍打开文件但不伪造成功定位。绝对路径、`file://`、路径穿越和不存在文件失败关闭；外部 HTTPS 链接不进入工作台。点击不得清除对话、草稿、Run 或滚动，也不得新增通用路径读取接口。

## WUI-049 诺文可见品牌、统一字体与 Composer 紧凑控制

当前用户可见品牌统一为“诺文”，覆盖桌面窗口、导航、启动和错误文案、内置艺术库及 Windows 安装显示身份。该规则仅属于 Brand Surface（可见品牌层）：内部 `creatx` 包、协议、API、LocalStorage、Profile 和 `appId` 保持稳定，不得通过品牌替换触发用户数据迁移或形成第二份应用身份。

桌面 Renderer 与内置艺术库离线携带 JetBrains Mono Regular / SemiBold，并把它作为界面、阅读正文和代码文字的首选字体。中文缺失字形必须回退到 `Microsoft YaHei UI` 或可用的 Noto CJK 字体；界面不得显示缺字方框，也不得把中文回退误称为 JetBrains Mono 字形。

“点子库”的用户可见名称改为“灵感库”，其本机收藏与分享语义保持不变；传承库仍是独立的内置创作参考目录。Skill 挂篮进入 Composer 底栏并紧邻“自由 / 审批”，前置一次性启用勾选采用小尺寸但保留 Checkbox（复选框）的焦点、禁用和 `aria-checked` 语义。

用户消息气泡不显示冗余的“你”。修改、重发和删除默认只投影图标，Hover（悬停）或键盘焦点时才展开文字，同时保留完整 `aria-label`。对话图片使用统一圆角，对话主滚动条轨道透明。Run 活动后，唯一发送按钮必须在原位置、原命中尺寸内切换为灰色停止方块，不得在旁边保留发送按钮或新增第二个停止按钮；运行结束后恢复发送箭头。该状态只调用现有 Run 取消链，不改变状态机。

## WUI-050 对话即时切换与目标路由

无脏编辑器时，点击会话必须在下一次 Renderer（渲染层）提交中显示目标会话身份并卸载旧 Timeline（时间线）；目标历史尚未返回时显示轻量加载状态，不得继续展示旧内容或错误空态。脏编辑器继续先走 `WUI-021` 的真实保存事务，保存失败不得离开。重复选择当前会话不形成新的打开周期，也不清空历史或滚动位置。

跨项目会话的 Timeline 必须与项目扫描并行读取。Chat（对话）不得等待 Growth Goal（生长目标）和 Workbench（工作台）投影；核心项目打开后两者在后台补齐。发送、Steer（追加指令）、附件和 Skill Sequence（技能序列）必须显式绑定用户刚选择的 Session ID（会话标识），不能读取上一帧会话作为回退。快速 A→B→C 只允许最新选择提交项目投影，旧项目完成结果不得覆盖新选择或 Main（主进程）的最终当前项目。

## WUI-051 传承库可学习视频置顶与会话入口

版本化传承目录继续保持 20 条且四类各 5 条；每类一条经过真实字幕核验的视频优先排列，并显示“可学习”状态。置顶只由目录中的可信字幕证据驱动，不能由平台、标题、收藏或手工 CSS 顺序暗示。无字幕条目保留来源入口，但“学习并生成 Skill”不可伪装成功。

点击可学习视频的“学习并生成 Skill”复用已有大列表会话选择面和 `WUI-044` 消息接收语义。确认后请求作为正常用户消息进入所选会话，页面切换到该会话展示真实 Agent、工具、当前权限模式下的审批与错误；传承库不运行独立 AI，也不在 Renderer 生成或写入 Skill。生成和安装语义由 `CSK-329..331` 唯一拥有。

## WUI-052 项目导入导出入口

项目标题操作区在“打开项目”旁提供“导入/导出项目”。窗口明确分为“导入诺文项目”和“导出当前项目”；无当前项目时只禁用导出。导出展示简介、文件/大小/排除范围和同一持久案例开关；导入展示来源未验证、校验、目标目录、进度、取消、冲突和失败阶段。Renderer 不读 ZIP、不写内部记录、不在成功提交前显示新项目。

导出文件选择器优先打开可写的 `D:\`；设备没有可写 D 盘时回退系统“文档”目录。用户仍可改选位置；若目标文件系统不支持 V1 的安全原子提交，界面要求更换位置，不假装导出成功。

## WUI-053 项目首页系统入口

最右工作台导航中的系统“项目首页”固定第一，内置“文件”调整为第二且继续不可移除。导入成功自动打开首页；完全展开仍为项目导航、Chat、工作台画布、工作台导航。首页展示受控简介、本地真实案例或导入只读案例，以及真实文件/工作台入口；没有简介时只显示编辑引导和真实概况，不自动调用 Provider。

本规则只取代此前“内置文件固定第一”的排序部分；真实文件兜底、文件身份和工作台内容权威不变。

## WUI-054 案例标记与继续

项目会话 Hover 与键盘操作区提供“作为项目案例”开关，已标记者显示“案例”标签；导出窗口操作同一事实。案例详情只读，包内文件引用复用现有工作台打开链。“以这个案例继续创作”先显示可编辑说明，只有确认后才创建新本地会话；取消或起草失败保持首页和案例不变。
