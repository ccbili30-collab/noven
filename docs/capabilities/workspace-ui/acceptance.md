## 当前证据

- `ACC-WUI-045`：通过生产 Electron 定向探针。V2 主页自动打开并加载同工作台 CSS、JavaScript、JSON 和 SVG；外部网络请求被 CSP 阻断，iframe 中不存在 `window.creatx`。临时展示的项目/会话匹配和只消费一次由稳定事件合同与全仓测试覆盖；未用真实 Provider 发起工具调用。

- `ACC-WUI-001`、`002`、`003`、`005`、`006`、`007`：通过第一条骨架验收。
- `ACC-WUI-004`：部分通过。等待审批时取消可与工具完成区分，错误合同也可分类；尚未在 UI 中分别触发真实 Provider 故障和工具执行失败。
- `ACC-WUI-008`、`009`、`011`：新版生产布局通过。内置与注册工作台进入同一动态选择器，真实目录树、中央 Markdown 画布和持续存在的 Conversation DOM 节点由 Electron 覆盖。2026-08-04 的 Workbench 回归进一步证明内置“文件”保留普通 JSON，注册工作台排除 JSON、裁掉仅含 JSON 的机器目录并保留真正空目录。
- `ACC-WUI-010`：部分通过。损坏记录的非阻塞诊断已在重启 Live 中验证；缺失目录 UI 只由实现与 Runtime 测试覆盖。
- `ACC-WUI-012`：通过生产 Electron 失败/恢复验收。观察到真实 `active -> waiting`、审批启动无 Goal、继续门禁、结束、退出暂停和重启暂停；有效 Provider 长任务另由 `ACC-CSK-314` 验收。
- `ACC-WUI-013`：通过生产 Electron 探针。项目入口的可访问名称为“打开项目”，生产树中没有“新建项目”“创建项目”、回收站或侧聊按钮；没有新增 Desktop API。
- `ACC-WUI-014`：通过生产 Electron 探针和真实 Cline Core/SQLite Runtime 测试。取消、多选、移除、发送后历史回读、受控打开、伪造授权和选择后文件变化均已覆盖；Provider 响应使用确定性替身或明确无效凭据，因此不是有效 Provider 附件 Live。
- `ACC-WUI-015`：通过真实 Electron 视觉探针与截图验收。纸张模式、Chat 主区域、按需 Workbench、真实文件、1360×860、900×700、860×620、窄窗工作台可达、退出和重启均已覆盖；没有调用有效 Provider。
- `ACC-WUI-017`：通过 `release/win-unpacked/CreatX.exe` 启动验收，观察到 `app.isPackaged=true`、真实 Markdown、无溢出、无 Renderer 错误和正常退出。安装包和便携版已生成；未执行交互式安装向导。
