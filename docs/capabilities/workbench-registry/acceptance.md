# Workbench Registry 验收矩阵

| ID | 规则 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| ACC-WBR-001 | WBR-001 | 打开未包含 `.creatx` 的项目 | 内置文件表面仍列出真实文件 |
| ACC-WBR-002 | WBR-002, WBR-003 | 从文件入口与预览打开 AI 新写文件 | 两处引用同一文件身份和当前内容 |
| ACC-WBR-003 | WBR-002 | 外部修改文件后刷新 | 文件与预览一起更新，不出现第二份内容 |
| ACC-WBR-004 | WBR-005 | Schema 未接受时请求注册工作台 | 明确返回能力不可用；没有生产元数据写入 |
| ACC-WBR-005 | WBR-001 | 打开没有 `.creatx` 的项目 | `builtin:files` 固定排第一，不产生隐藏写入，隐藏内容不出现在文件工作台 |
| ACC-WBR-006 | WBR-004, WBR-006, WBR-010 | 真实 Provider 根据用户要求调用 `register_workbench` 注册现有文件夹 | 审批前无写入；批准后只新增一条合法 JSON，真实文件和文件夹未移动或复制 |
| ACC-WBR-007 | WBR-007 | 使用相同文件夹和输入重复注册 | 返回同一 ID；注册文件数量、内容和修改时间不变 |
| ACC-WBR-008 | WBR-008, WBR-010, WBR-011 | 工具真实成功后观察 Electron | 工作台标签立即出现；打开后显示正确标题、路径和该真实文件夹子树 |
| ACC-WBR-009 | WBR-011 | 注册成功后退出并重启应用 | 同一工作台从真实 `.creatx` 恢复，不需要重新调用 Provider 或工具 |
| ACC-WBR-010 | WBR-009 | 注册文件夹被外部删除或移动 | 标签保留并显示 `missing` 与原路径；不猜测新路径，内置“文件”仍可用 |
| ACC-WBR-011 | WBR-009, WBR-012 | 一条 JSON 损坏、字段非法或版本未知 | 该记录不成为可用工作台并产生非阻塞诊断；其他工作台和内置“文件”正常 |
| ACC-WBR-012 | WBR-007, WBR-009 | 外部制造两条指向同一文件夹的有效记录 | 两条均不被任意选为权威，产生冲突诊断，真实文件不受影响 |
| ACC-WBR-013 | WBR-006, WBR-010 | 工具输入为空、绝对路径、`.`、`..`、文件路径、项目外 Junction 或不存在目录 | 失败且没有 `.creatx` 写入和项目内容副作用 |
| ACC-WBR-014 | WBR-010 | 用户拒绝审批、取消 Run 或元数据写入失败 | 不出现成功回执和新工作台；重启后也不存在该注册 |
| ACC-WBR-015 | WBR-002, WBR-008 | 从注册工作台选择文件并打开预览 | 与窄文件面板使用同一 `fileId` 和磁盘内容，没有视图副本 |
| ACC-WBR-016 | WBR-007, WBR-013 | AI 首次注册 `folder=小说`，显示标题使用作品名 | 注册合法；文件夹身份仍为 `小说`，不要求标题等于文件夹名 |
| ACC-WBR-017 | WBR-013 | 用户要求把已注册工作台标题改为“小说” | 审批后同一 ID 立即显示新标题；`folder`、真实文件夹和内容不变，重启后保持 |
| ACC-WBR-018 | WBR-013 | 改名目标为内置、未知、损坏/冲突记录，标题非法或元数据并发变化 | 失败关闭；原记录、文件夹和内容不变，不产生第二条注册 |
| ACC-WBR-019 | WBR-014 | 读取 V1，并为其设置有效主页 | V1 继续可读；一次原子写入后成为严格 V2，同一 ID、文件夹和标题不变 |
| ACC-WBR-020 | WBR-014 | 重复设置相同主页或改名 | 重复设置不改修改时间；改名保留主页 |
| ACC-WBR-021 | WBR-014 | 主页路径穿越、越出注册目录、非 HTML、缺失或是目录 | 失败关闭且注册记录不变 |
| ACC-WBR-022 | WBR-014 | 已登记主页随后缺失 | 工作台仍可用，主页标记缺失并回退文件树，不显示空白画布 |
| ACC-WBR-023 | WBR-015 | AI 调用 `show_in_workbench` | 只对当前项目和会话发布展示请求，不修改注册记录 |
| ACC-WBR-024 | WBR-016 | HTML 加载相对脚本、样式和图片，并尝试跨目录或联网 | 同工作台资源正常；跨目录、外网、表单、弹窗和 Electron Bridge 全部不可用 |
| ACC-WBR-025 | WBR-017, WBR-019 | AI 为已注册工作台设置只包含 `**/*.md` 的可见范围 | 审批成功后工作台只投影 Markdown 及其祖先目录；图片和 JSON 不出现，真实文件均未改变，内置“文件”仍显示这些普通文件 |
| ACC-WBR-026 | WBR-018 | `autoIncludeNewFiles=true` 后新增匹配与不匹配文件 | 新 Markdown 自动出现，不匹配文件不出现；重启后规则保持 |
| ACC-WBR-027 | WBR-018 | `autoIncludeNewFiles=false` 时保存规则，再新增、删除和改名文件 | 保存瞬间的匹配文件清单被冻结；新增文件不出现，删除项消失，改名项按新文件处理且不自动出现 |
| ACC-WBR-028 | WBR-017, WBR-019 | 设置排除优先规则、大小写不同路径和嵌套 `**` | Windows 下稳定命中；排除覆盖包含；目录只在有可见后代时保留 |
| ACC-WBR-029 | WBR-017, WBR-019 | 输入绝对路径、`.`、`..`、空段、非法 `**` 或超限规则 | 工具失败关闭，注册记录和真实文件不变 |
| ACC-WBR-030 | WBR-018, WBR-019 | V1/V2 设置范围，随后改名、设置主页或重复设置 | 首次原子升级 V3；ID、文件夹、标题、主页和范围按操作保留；相同有效状态不产生多余写入 |
| ACC-WBR-031 | WBR-019 | 新规则会隐藏已有主页，或为已隐藏 HTML 设置/临时展示主页 | 修改或展示失败关闭，不写注册记录，不旁路可见范围 |

`ACC-WBR-004` 保留为 Schema 接受前的历史门禁，不复用其编号。父子工作台、模板、布局、封面、手动注册、重新定位、删除和迁移属于后续验收。

## 当前证据

2026-08-10 的便携交换批次复用现有 V1/V2/V3 权威解析和内部原子写入，在同项目串行门禁内导出/导入注册工作台显示元数据。真实 Windows 临时项目定向 27/27（120 次断言）验证主页、冻结可见文件、中文排序、内置“文件”重新生成、损坏/未知/重复/越界记录隔离、目标现有记录不覆盖、单项写失败继续和非规范路径失败关闭。该证据服务 `ACC-IEX-109` 的工作台层，不新增工作台产品语义；尚无真实 `.np`、导入目录提交、Electron 或重启验收。

2026-08-10 的 V3 批次通过 `ACC-WBR-025` 至 `031` 的 Runtime（运行时）定向验收：真实临时项目记录证明 Markdown-only 投影、自动新增、冻结后的新增/删除/改名、排除优先、Windows 大小写、目录裁剪、V1/V2 到 V3、主页保护、非法模式和损坏 V3 隔离。工具已注册进正式 Desktop Runtime，Production Build（生产构建）含工具名称；没有外部 Provider 自主调用或 Electron 视觉证据，因此这些编号标记为 Runtime 通过、Provider Live（真实运行）未完成。完整结果见 `../../baseline/creatx-workbench-visible-scope-2026-08-10.md`。

2026-08-05 的 V2 批次通过 `ACC-WBR-019` 至 `024` 的 Runtime、协议和 Electron 定向验收：V1/V2 双读、原子迁移、幂等、改名保留主页、非法路径与缺失回退、临时展示不落盘、token 文件夹限界、CSP 和无 Electron Bridge 均有可执行证据。AI 工具已注册进 Cline Adapter（Cline 适配层），但本批没有真实 Provider 调用 `set_workbench_home` 或 `show_in_workbench`，因此工具自主选择不标记 Provider Live。

提交 `c9a4ae4` 已通过 `ACC-WBR-001`、`002`、`003`：没有 `.creatx` 的项目仍有内置文件表面，文件入口与预览引用同一磁盘文件，外部修改后一起刷新。

`ACC-WBR-004` 的停止条件在 ADR-0007 接受前得到遵守，现作为历史门禁保留。
