# Import Export 产品规格

## Live Archive（真实运行档案）

### IEX-001 完整 Live 必须进入正式产品

通过整本 Live 验收的运行必须保存真实项目文件、Owner/Worker 会话、Growth 历史、图片任务和最终汇报。仅保留临时项目目录不构成产品保存完成。

### IEX-002 保持既有事实权威

归档清单只协调跨 Store 晋升。它不得复制 Cline 消息、Growth 状态或图片任务成为新的运行权威。

### IEX-003 持久项目身份重映射

项目必须复制到正式 Profile 的持久项目区。目标 Project ID 按目标绝对路径重新计算，并在 Cline metadata、Growth、图片任务和其他项目关联中一致替换。不得让正式产品继续依赖临时缓存路径。

### IEX-004 Inbox 接收边界

隔离运行成功后写入正式 Profile 的 Inbox。正式桌面只在各权威 Store 打开前接收 Inbox，避免并发篡改正在使用的 SQLite。失败档案保留，不能拖垮桌面启动。

### IEX-005 幂等与冲突

相同 Archive ID 和相同内容重复接收是无副作用成功。相同会话、Goal、图片任务或目标路径已存在但内容不同，必须分类为归档冲突并停止该档案。

### IEX-006 图片费用边界

成功和失败图片保持原状态；`queued` 与 `generating` 在归档时转为带原因的 `interrupted`。归档不得自行继续付费图片任务。

### IEX-007 隐私与配置

Live 档案不包含模型密钥、Provider 凭据、浏览器 Cookie、缓存或隔离 Profile 的通用设置。会话中的历史 Provider/模型标识可作为历史元数据保留。

### IEX-008 原始运行保留

归档成功不删除原完整运行目录。Inbox 可以移动到正式 Archive 区，但不得以清理为理由删除唯一完整副本。

### IEX-009 历史完整运行兼容

旧版完整运行可以缺少当前新增的完成列，Owner 也可能在完成后被再次打开而处于 `idle`。只有源 Goal 已 completed、Owner 消息存在最终 Assistant 文本、没有活动 Provider 工作，并且档案副本能迁移到当前 Schema 时才允许接收；兼容迁移只能作用于档案快照，不修改历史源库。

## Portable Project Package（便携项目包）

以下规则已接受。Task 1–7 已实现独立 Runtime（运行时）；Task 8 的 Desktop API（桌面接口）实现源码保留但不接入 `0.1.20` 的生产 Main、Preload 或应用依赖图。Renderer（渲染层）入口、项目首页、继续创作、重新接线和纵向 Live（真实运行）验收统一延期至 `0.1.21`。它们不改变 `IEX-001..009` 的内部 Live Archive（真实运行档案）语义，两种格式与 Runtime 必须分离。

### IEX-101 两种项目入口

“打开文件夹”只打开现有真实目录，不按路径猜测其他设备会话；“导入诺文项目”只接收合法 `.np`，恢复文件、净化工作台和用户选择的案例记录。两者不能自动猜测或互相降级。

### IEX-102 V1 容器与内容权威

`.np` 是标准 ZIP，逻辑根包含 `manifest.json / checksums.json / files/ / conversations/ / workbenches/`。`files/` 是唯一项目内容权威；案例与工作台不复制正文事实。

V1 使用普通 ZIP，不要求 ZIP64：项目文件与目录合计最多 60,000 项，未压缩项目内容总量最多 2 GB，普通项目文件单项最多 2 GB。Manifest、Checksums、单个案例和单个工作台等结构化 JSON 单项最多 128 MB；异常压缩比超过 1,000:1 的条目失败关闭。超限整体失败，不允许截断、漏项或生成部分包；ZIP64 与更大媒体工程延期到有真实需求后再设计。

### IEX-103 双身份

包内稳定 `projectId` 表示来源项目血统，确定性 `packageId` 表示一次规范内容。Project Catalog 必须把导入来源双身份与本地项目身份分开保存：普通导入的本地 ID 等于来源 ID；独立副本获得新本地 `projectId` 和只读 `forkedFromProjectId`，但仍保留原 `importedProjectId + importedPackageId` 供重复导入幂等定位。副本首次再导出时，以新本地身份生成新的 `packageId`。同来源项目、不同包内容必须提示冲突，只允许取消或显式独立副本。

### IEX-104 项目简介

项目用途、当前成果和使用说明由用户在导出界面编辑，通过受控项目元数据保存并进入 Manifest。AI 起草只能由用户显式启动并审阅；打开、导入和导出不得自动调用 Provider（模型服务），也不强制创建根级说明文件。

### IEX-105 文件范围

导出包含完整作品与源码，固定排除 `.git / .creatx / node_modules`、诺文临时文件、系统缓存和越界链接。项目简介与工作台从原权威生成净化交换记录。导出前显示排除数量、可直接测量的文件大小、未扫描目录/链接数量和原因；不得为计算排除目录大小而遍历 `node_modules` 或跟随链接。V1 不提供自定义排除规则。

### IEX-106 完整性不等于作者真实性

Manifest 保存版本、双身份、简介、计数和交换记录版本；Checksums 保存空目录的规范相对路径，以及每个文件的规范相对路径、字节数和 SHA-256。二者共同参与 `packageId`，且 `packageId` 不受导出时间和 ZIP 压缩差异影响。V1 不做作者签名或联网证书，必须显示“发布者未验证”；导入不执行包内内容。

### IEX-107 案例是净化只读记录

`conversations/<caseId>.json` 只包含用户确认的标题、用途、结论、用户可见消息、AI 最终回复、白名单工具活动摘要、包内文件引用和 `continuationBrief`。禁止隐藏思维链、System Prompt、协议消息、压缩上下文、原始工具参数/结果、绝对路径、凭据、个人信息、Run 与审批授权。

### IEX-108 继续创作隔离

导入案例不能写入或冒充 Cline 原生历史。继续前展示并允许修改 `continuationBrief`；确认后创建普通本地项目会话，把它作为第一条可见用户消息发送，并重新读取当前文件。没有说明时必须手工填写；AI 起草只允许显式、可审阅地调用。

### IEX-109 暂存后提交

导入先验证 ZIP 头、版本、加密/ZIP64/链接属性、条目数、声明大小、压缩比、双身份、重复路径、Windows 设备名/备用数据流、路径穿越和校验清单，再解压到目标旁暂存目录并校验真实字节；全部通过后才原子提交、登记并加载。导出同样在临时文件完成复核后原子形成最终 `.np`。

V1 导出通过同目录硬链接发布已经完整复核的临时包，绝不覆盖同名目标。不支持硬链接的文件系统失败关闭并要求用户更换位置，不退化为可见的逐字节复制或空占位文件。

### IEX-110 新目录、取消与降级

V1 只导入用户选择的新目录，不覆盖或合并。提交目录前的取消、磁盘不足或校验失败不得登记半项目，并清理本批受控暂存目录。目录已经原子提交后若受控元数据、案例或 Project Catalog 持久化失败，不删除已提交的用户文件，也不伪称完整成功；项目内受控导入状态记录 `committed-unregistered` 和失败原因，返回可恢复结果。Checksum 不匹配或案例语义损坏使整包在提交前失败；工作台字节完整但语义损坏时项目仍导入，忽略损坏记录并保留内置文件兜底。

### IEX-111 项目登记不复制内容

轻量 Project Catalog（项目目录登记）保存本机路径、便携身份、来源、包身份和缺失状态，使尚无本地会话的导入项目可在重启后出现。它不保存文件正文或会话副本；路径丢失显示不可用，从列表移除不删除磁盘文件。

### IEX-112 明确延期

V1 不做签名、联网发布者身份、拖入导入、自定义排除、项目版本升级/合并、差异应用、导入会话续写、后台导入、活动 Run、排队/生成中付费图片任务或 Profile/数据库复制。
