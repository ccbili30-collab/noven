# Creative Skills 产品规格

## 1. 词汇

| 术语 | 权威含义 |
| --- | --- |
| Skill | 同一个 Coding Agent 按需加载的创作方法、工具教程和上下文，本身不是独立 Agent Runtime。 |
| Growth Goal | 由 `/growth` 显式创建的持久创作目标；它可以编排多个有界 Cline Run，但不复制 Cline 的消息、Run 或工具事实。 |
| 显式 Skill | 只有用户输入命令才能开启的会话级能力。当前包括 `/living`、`/unliving` 和 `/growth`。 |
| 普通创作 Skill | 用户可以强制调用，Agent 也可以为完成当前任务自动激活的能力。当前包括 `/study`、`/draw-map`、`/draw-comic` 和 `/causality`。 |
| 工作台协助 Skill | 教会 Agent 检查真实文件、设计视图、预览注册、调用受约束工具并验证结果的内置教程。 |
| 自由视角 | `/living 天空` 一类不要求项目文件的临时角色视角。 |
| 项目绑定视角 | `/living @天空` 一类显式读取或创建项目 Markdown 文件后进入的视角。 |
| 可选择地图 | 同时具有视觉地图图片和可点击区域几何的工作台结果。 |
| 因果关系网 | AI 根据当前作品形成的可视化因果理解，不是客观证明或确定性模拟器。 |

## 2. 共同 Skill 合同

### CSK-001 同一个 Coding Agent

状态：Accepted Product Behavior（已接受产品行为）。

CreatX 仍是完整 Coding Agent。Skill 复用 Cline 的会话、Run、工具、Tool Policy（工具策略）、Steer（插话）和 Abort（中止），不能建立平行执行内核。Growth 的持久 Goal 只负责产品级生命周期和阶段调度，不成为第二套模型循环。

### CSK-002 渐进式加载

状态：Accepted Product Behavior。

核心 Prompt 只保存旅鸽身份、权限、真实文件和基本协作原则。创作方法、工具教程与领域知识按当前任务加载；模型只获得当前权限允许的工具描述。不能把所有 Skill 永久塞入上下文。

### CSK-003 教程与强制边界分离

状态：Accepted Product Behavior。

Skill 教程说明何时、为何和怎样使用工具，包含清晰步骤、输入、输出、失败和示例。CreatX 自有工具必须由自己的合同强制项目关联、Schema（数据合同）、幂等和失败关闭；Cline 原生工具沿用当前会话的审批或自由 Tool Policy。两种模式都不承诺严格项目路径沙箱，这些边界不能只依赖 Prompt。

### CSK-004 真实活动可见

状态：Accepted Product Behavior。

Skill 的真实工具、文件、Provider 和图片事件保持可见。UI 可以用创作语言概括并允许展开详情，但不能伪造进度或隐藏失败。

### CSK-005 触发所有权

状态：Accepted Product Behavior。

- `/living`、`/unliving` 与 `/growth` 只能由用户显式触发。
- `/study`、`/draw-map`、`/draw-comic` 与 `/causality` 可由用户强制调用，也可由 Agent 为当前任务自动激活。
- `/growth` 可以组合普通创作 Skill，但不能自行进入 Living。

### CSK-006 Skill 不自行提升 Harness 权限

状态：Accepted Product Behavior；具体会话模式由 `session` 拥有。

Skill 不能私自改变当前会话模式。普通 Skill 沿用会话的审批或自由 Tool Policy；`/growth` 的产品前提是会话进入自由模式，由 Session 的公开命令完成，而不是由 Skill 绕过权限。第一版只保留审批与自由两种行为，不恢复计划、审批、协作、自由四档。

### CSK-007 Composer Skill 序列只安排方法

状态：Implemented；真实 Provider 多轮结果待验收。

用户可以通过挂在 Composer（对话输入框）上沿的小挂签展开 Skill 挂篮，为当前会话保留有序的普通 Skill 插槽，并在正文中只写一次真实任务。每条插槽可独立选择；挂签旁另有一次性的总启用按钮。只有总启用已勾选时，本次已选择的插槽才进入冻结发送序列；未选择插槽继续保留。用户原话是唯一任务权威；序列只规定各轮采用的方法与顺序，不能替用户生成阶段任务，也不能把内部续轮伪装成新的用户消息。

序列在同一个 Cline Session（会话）中逐轮执行。首轮保存并展示用户原话；后续轮次读取同一会话历史与前轮真实项目文件，内部续轮默认不投影为用户消息。中间回复属于同一回合的可折叠过程，最后一轮形成正式 Assistant（助手）回复。

### CSK-008 序列是会话偏好而非项目状态

状态：Implemented。

挂篮及其逐槽选择状态在发送后保留，并按 Session ID 隔离；切换会话加载目标会话自己的配置，切回时恢复。删除会话时同时删除该会话的本机挂篮偏好。一次性总启用不持久化，消息提交或切换会话后立即取消。空挂篮、全部插槽未选择或总启用未勾选严格等同普通聊天；运行中的 Steer 不重新附带序列。旧 V1 序列首次读取时迁移为全部插槽已选择，但不会自动开启总启用。

第一版只由 Renderer 的版本化 Local Storage（本地存储）保存选择偏好，不承诺应用退出后从精确 Skill 槽位自动恢复执行。真实消息、工具和文件仍由 Cline 与项目文件拥有，不能建立第二套消息库或 Run 状态机。

### CSK-009 可排队 Skill 与失败边界

状态：Implemented；取消和失败的真实 Provider 多轮路径待验收。

只有 Creative Skills 唯一注册表中正式安装的普通 Skill 可以进入挂篮并排队；Growth 路线、未生产化能力和未知名称失败关闭。允许有意重复同一 Skill，最多保留十二条插槽；发送时保持已选择插槽的相对顺序。序列沿用当前 Session 权限，不提升工具权限；任一轮失败或取消后不再启动剩余轮次，已完成文件与真实回复保留，整体不能伪装成功。序列不能与斜杠命令组合，项目存在未终结 Growth Goal 时也不能启动另一条序列主任务。

### CSK-010 序列预算触顶自动续跑

状态：Accepted Product Behavior；实现与真实 Provider 验收进行中。

普通 Session 的单 Turn 迭代预算触顶不等于当前 Skill 失败。已启用的 Composer Skill 序列必须把 `maxIterations` 触顶作为可恢复执行边界，在同一 Cline Session 中读取已持久化的消息、成功工具结果和真实项目文件，自动继续当前 Skill；内部续轮不投影为新的正式用户消息，也不得重复覆盖已成功产物。第一版每个 Skill 最多四个十二次执行片段；前三次触顶不形成未解决红色错误，第四次仍未完成时停止后续 Skill，并结构化区分已完成、当前部分完成和未启动。应用退出仍停止活动工具；用户重开原会话并发送新的“继续”后，才从同一历史恢复，不自动重放。

### CSK-011 序列步骤可信完整交付

状态：Implemented；真实 Provider 五项连续 Live Verified（已验收）。

一个 Cline Turn 正常结束不等于当前 Skill 完成。挂篮的当前步骤必须通过只在序列受众中可用的结构化回执报告 `completed`、`partial` 或 `blocked`；Runtime 验证回执引用的真实项目产物。地图、人物群像和漫画还必须引用其全部必需图片任务，且任务已经成功。只有可信 `completed` 才能启动下一 Skill；缺回执会在同一 Skill 的有限片段内请求核验，`partial`、`blocked`、失败、取消或预算耗尽均停止后续序列。普通会话不能发现或调用该回执工具。

同一结构化完成回执的精确重试必须幂等返回第一次结果；内容不同的第二份回执继续失败关闭。需要等待多张持久图片时，序列 Agent 只能调用内部一次性等待工具，由 Runtime 等待当前步骤实际提交的任务；不得通过 Shell 睡眠、扫描目录或重复列表调用轮询。同步 `generate_image` 只在当前步骤中形成可信图片证据，序列开始前存在的旧图片任务不得复用为本轮交付。

## 3. 工作台协助

### CSK-101 工作台教程

状态：Accepted Product Behavior。

工作台协助 Skill 必须教会 Agent：检查真实文件和已有注册；由当前创作任务判断是否需要注册；选择内置组件与布局；生成可检查预览；按权限应用；验证结果；处理普通目录、嵌套注册、未知类型、缺失文件和损坏元数据。

### CSK-102 注册不改变内容身份

状态：Accepted Product Behavior。

工作台注册只写视图元数据，不移动、复制或重新定义真实文件。没有专用模板时退回普通文件、文档和媒体组件，不能隐藏未识别内容。

### CSK-103 不进行无任务后台改版

状态：Accepted Product Behavior。

Agent 只能由当前创作任务触发工作台注册或调整，不能因后台扫描目录就自动大规模注册、重排或改版。

### CSK-104 工作台规则分三层

状态：Accepted Product Behavior；基础 Prompt、工具说明和首个领域 Skill 已实现。

每个项目会话的基础 Prompt 只保存文件权威、工作台用途、不要滥注册、不要为注册移动文件、禁止直写 `.creatx` 和成功后再报告等不变量。`register_workbench` Tool Description（工具说明）拥有调用前提与幂等语义；小说等领域 Skill 拥有具体内容结构。领域结构不能永久塞进基础 Prompt。

### CSK-105 首个小说启动 Skill

状态：Implemented；自然语言完整 Live Pending（待验收）。

用户提供小说题材并要求开始时，小说 Skill 不先追问人物、设定或风格，而是作出可逆创作选择，创建有题材内容的 `小说/大纲.md` 与 `小说/第一章.md`，随后注册绑定 `小说/` 的工作台。显示标题可以使用清晰作品名，也可以省略并回退到文件夹名；用户纠正标题时使用 Workbench Registry 拥有的显式改名工具。已有目标文件必须先读取并保留；不得创建空模板、TODO 或无关目录。

项目已有世界材料时，同一 Skill 先读取世界基准、当前冲突、人物、关系、地点和故事入口，从成熟故事母型中选择能够承载明确人物欲望的路线，再形成长期、阶段和当前目标。成品默认包含大纲与前两章；开篇必须具有期限、失败损失、私人意义和不可逆变化，不能把世界设定或制度说明冒充故事。新增人物、事件和关系应与来源事实区分。没有既有世界但用户已经给出可用题材时继续兼容直接起稿，不能强迫先建世界。

Skill 沿用普通 Cline 权限。第一版允许模型申请项目内目录查询或显式创建目标目录的 Shell，用户通过原生审批决定；Skill 不获得额外授权，也不保证只有三次审批。

## 4. Study

### CSK-201 Study 是研究 Skill

状态：应用本地 Skill 与真实 Provider 普通研究已 Live；代理网页抓取已 Live，自动网络 Study 方法已内置但尚未 Live。

`/study` 负责搜索、读取、比较和整理资料，是普通创作 Skill，不是独立页面、Agent Runtime 或专用状态机，也不训练或微调模型。

用户只需一句简短目标，例如 `/study 学习当前项目里的资料和参考图片。`。资料盘点、真实图片读取、多维分析、首轮产出上限、原资料保护和工作台注册由 Skill 教程承担，不要求用户复述这些内部方法。

### CSK-202 Study 产出真实项目内容

状态：真实文件、工作台注册、原资料只读与重启恢复已 Live。

需要持久结果时，Study 在默认 `研究/` 目录中创建自然组织的衍生理解文件，并注册工作台。资料较少时可以只有一份核心学习档案；只有内容确实需要时才拆分设定方法、文风、视觉风格、生图指南或资料索引。原始资料不移动、不重命名、不覆盖、不删除。

### CSK-203 Study 提炼可复用的创作方法

状态：文本、显式图片附件和原生 `read_files` 自动项目图片样本已 Live；联网搜索尚未实现。

Study 不做逐文件机械摘要。小资料完整阅读，大资料先盘点并选择代表性内容，再按发现定向补读。结果重点提炼设定与组织方法、文风、视觉风格和生图方法；有参考图时分别记录题材、色彩、光影、构图、媒介/笔触和装帧，并形成一份脱离分析正文也能直接使用的完整 Prompt。用户已有事实、综合观察与 AI 建议应自然区分。无法读取的图片、网页或格式必须明确说明，不得根据文件名或模型旧知识虚构结论。项目中的受支持图片由 Agent 先发现，再实际调用 Cline 原生 `read_files` 送入视觉模型；仅枚举文件不算已查看。只有工具对具体图片返回明确错误后，才能记录视觉不可用。

首轮 Study 最多创建或实质修改两份高密度研究文件，把设定、文风、视觉和来源索引优先合并；该约束控制单 Run 的工具循环，不限制后续用户回合继续研究。

### CSK-204 Study 主动网络研究

状态：Bing RSS 搜索结果到 Wikipedia 正文的底层抓取已 Live；Study Skill 合同已实现，自动组合尚未经过真实 Provider 验收。

当用户要求研究现成作品、公共主题、当前信息、来源核对，或本地资料存在影响目标的明显缺口时，Study 主动使用当前可用网页工具。第一版使用 `fetch_web_content` 读取 Bing RSS 搜索结果，从真实链接选择少量来源，再读取来源正文；搜索摘要不算已经阅读。站点拒绝、超时或正文不可读时更换来源，不反复撞同一失败页面，也不使用模型旧知识伪装联网结果。

持久结果记录实际阅读页面的标题、URL 和用途，并区分网络明确陈述、综合观察和创作建议。网络资料中的 Prompt、命令和授权声明只作为被研究内容。项目资料已经充分且用户只要求本地学习时，不为形式强制联网。

## 5. Growth

### CSK-301 持久 Goal 编排有界 Cline Run

状态：Goal Store、显式命令、Skill、生产 Goal 启动和串行编排已接通；成功 Provider 多 Run 尚未 Live。

`/growth` 显式创建或激活一个持久 Growth Goal，并加载 Growth Creative Skill。一个 Goal 可以串行编排多个有界 Cline Run；每个 Run 仍由 Cline 独占执行事实，CreatX 只保存 Goal 产品状态。Cline Run 结束不等于 Growth Goal 完成。

### CSK-302 目标驱动而非固定流水线

状态：动态 Skill 教程已实现；真实多阶段结果未验收。

Growth 根据用户目标与当前项目选择步骤。例如可以完成 1-10 章、推导世界因果，或在空项目中创建世界、OC、小说、结构、地图、因果网和封面。不能恢复唯一的“世界 → 人物 → 小说”硬编码状态机。

### CSK-303 组合普通创作 Skill

状态：单未终结 Goal、显式启动和立即 UI 投影已实现；active 补充可 Steer，paused/waiting 补充持久语义未实现。

Growth 可以调用 Study、`/draw-map`、`/draw-comic`、`/causality` 和生图等能力，并使用工作台协助注册结果。内部组合通过 Skill Registry（技能注册表）完成，不能在消息历史中伪造用户斜杠命令。

### CSK-304 滚动规划与可见计划

状态：Accepted Product Behavior。

Growth 保留长期目标，但只详细规划当前里程碑和少量下一步。小目标可以直接完成；大目标必须创建并持续更新项目根的 `创作计划.md`。计划写入后立即执行，不增加计划审批门。每个阶段结束后重读真实文件、计划、图片状态和用户 Steer，再决定下一阶段。

### CSK-305 显式触发与单活动 Goal

状态：Accepted Product Behavior。

只有 `/growth` 启动持久 Goal，普通自然语言任务不得自动升级。启动成功后 UI 必须立即显示 Growth 已启动及其真实状态，不能只让任务在后台静默发生。每个项目最多一个未终结 Goal，`active`、`paused` 与 `waiting` 都占用该位置；期间新的 `/growth` 默认补充或转向同一 Goal，用户明确结束旧 Goal 后才能创建新 Goal。完成的 Goal 可以由用户重新打开并继续，但不能与另一个未终结 Goal 并存。

Creative Skills 维护唯一斜杠命令目录，供解析器和 Renderer 共同使用。Growth World 的连字符写法是显式别名，必须先规范化再进入同一 Goal 路由。未知斜杠命令不得作为普通模型输入；否则模型可能只复述 Skill 流程而没有创建 Goal。

### CSK-306 阶段汇报与空转门禁

状态：阶段汇报、可信证据、结果转换、持久幂等、缺报告恢复、空转门禁和串行下一 Run 调度已接入生产 Main；有效 Provider 成功路径尚未 Live。

每个阶段通过 `report_growth_progress` 报告 `continue`、`waiting`、`completed` 或 `failed`。Runtime 只验证引用存在、必需图片完成等低成本事实，不评判艺术质量。缺少报告时只允许一次恢复回合；连续两次缺少报告或连续三个阶段没有文件、图片任务或计划进展时进入 `waiting`。

### CSK-307 自由模式执行

状态：生产权限门禁与可见切换已实现；自由工具成功长任务尚未 Live。

Growth 只在 Session 定义的自由模式运行，所有已启用的 Cline Act 工具自动批准且不显示逐工具审批弹窗。用户若已主动切到审批模式，`/growth` 失败关闭并提示先切回自由，不能静默改变用户选择。自由模式不是项目沙箱，文件和 Shell 工具可能访问整台机器。Growth 不切换到会禁用 Skills 的 Cline `yolo` Agent Tool Preset。

### CSK-308 Steer、暂停、结束与继续

状态：生产 Steer、暂停、结束和继续入口已实现；有效 Provider 在途行为尚未 Live。

Publication Genre（文类）和项目文风保留为创作建议，不是正文接收合同。十二层仍为 entry 保存合法 `genreKey`，group 不接受该字段；Publication Genre Library（文类总库）继续提供适用对象、叙述位置、组织方式、语言技巧和避免项，但 Writer 可以更换主文类、混合备选、调整顺序或忽略不适用技巧。

题材不复制文类定义。Topic Genre Profile（题材文类配置）和 World Style Profile（项目文风配置）继续保存可复用的候选排序、叙述距离、语体、知识位置、语言约定和避免项。Runtime 保留 Writing Contract（写作合同）快照作为历史身份和建议来源，但 V4 Writer 不被结构 beat、候选排序或固定文类形式约束。

Pro 当前使用四个有界产品阶段：一，路线、资料与世界方向；二，十二层骨架；三，全世界蓝图；四，自由物化。阶段一的 `initialize` 建立持久方向容器、唯一世界根工作台和十二份空层蓝图；阶段二只检查并确认这十二层入口完整，不创建具体 group、entry 或因果；阶段三是具体蓝图对象、来源映射和因果的唯一创建阶段。`prepare_review`、用户修订、再次审阅和 `freeze` 属于阶段三收尾，不构成独立创作阶段。`create / continue / reconcile` 是恢复和入口路由，不替代四阶段。每次阶段尝试与物化对象尝试都有持久身份；缺报告和停滞计数跨 Scheduler 重建保持一致。

执行入口与来源路线相互独立。Runtime 在 Provider 调用前选择 `create / continue / reconcile`：空项目创建新蓝图；唯一权威世界的旧 Goal 已终结时，新建带前驱关系的后继 Goal，复制并校验蓝图、物化状态、研究包、回执和关系索引，最后原子切换作品所有权；项目已有内容却没有权威世界时进入整理。多个权威世界、活动所有者或身份不一致时，在 Provider 和项目正文副作用前失败关闭。终结的前驱 Goal 与其内部证据保持不可变。

整理入口不把旧资料当空项目重建，也不直接把既有文件冒充已完成物化对象。蓝图建立后必须为每个 entry 保存 `existing / partial / conflicting / missing` 映射；前三类绑定实际存在的项目相对文件，`missing` 不得伪造来源。原文件不移动、不改名、不覆盖。映射不完整时不能进入 `review`；正文研究必须读取对象对应的匹配资料，并至少实际采用一份，整理后的正式版本只写入新的不冲突作品根。

后继接管若发现对象正文已存在但持久研究包缺失，不得直接进入 Recovery，也不得删除或覆盖正文。该文件先作为未审草稿交给受限 Research Worker 核对；研究包真实落盘后，下一轮才以禁用直接文件写入的 Recovery 接管。未审草稿不能单独充当 canon 权威来源，也不能被填入自己的 claim `sourcePaths` 形成循环依据。

每层在自己的目录保存 `蓝图.json`；作品根的 `世界蓝图/index.json` 汇总十二层，`世界蓝图/relations.json` 只保存世界内部因果。蓝图状态保存题材配置和项目文风；蓝图对象保存稳定 ID、全世界唯一语义 key、标题、所属层、对象类型、同层父对象、计划路径、冻结的受限 `genreKey`、简短定位、大致顺序和 `planned` 状态。`parentId` 表达 group 与 entry 的同层结构，不重复写成关系边。因果边只使用 `causes`，方向固定为“原因 -> 结果”，并保存具体 reason；禁止混入 `dependsOn` 或 `adopts` 正文生成依据。

十二层通常各规划 10 至 14 个正文 entry，以约 11 至 12 个为自然目标，并允许按题材浮动；每层另有 2 至 8 个结构 group。工具仅保留每层 8 个 entry 的宽松防空壳下限，group 不计入下限；单层 80、全世界 720 的运行保护上限继续保留。数量不得代替题材覆盖、层级结构和跨层因果质量。蓝图阶段不写正式正文、空 Markdown、图片任务或正文 `关系/index.json`。

阶段三审阅回执必须同时证明 `世界基准.md`、`资料索引.md`、状态为 `review` 的 `state.json`、十二份层蓝图、状态同为 `review` 的总索引、因果关系和一个已注册的世界根工作台。Runtime 从经过验证的唯一嵌套 `世界基准.md` 路径持久化作品根；根工作台或任一蓝图门禁缺失时不提交回执。回执成功后 Goal 转为 `waiting` 供用户检查。只有同一阶段的冻结收尾证明 `state.json` 与总索引都为 `frozen`，阶段四才可开始。

正式上游必须通过项目会话的 Cline 原生 `read_files` 名称读取，但执行器由 CreatX 使用 Cline 公开扩展点固定到当前 Session 的真实项目根并按 UTF-8 解码。项目外绝对路径、路径穿越、目录、符号链接逃逸、缺失文件和无效 UTF-8 必须失败关闭。必需读取失败时进入 `waiting`；不得退回 Shell、文件名猜测、模型旧记忆或近义词改写继续生成。内部制作记录中的依据只能逐字引用当前阶段成功读取的真实项目相对路径。

正文物化是第四阶段。Runtime 从冻结蓝图领取当前最早未完成层的有限对象束，每批最多三个一次性 Worker。Research 只提交 V4 短简报：对象与目的、最多十二条实际读取材料路径、最多十二条显式锁定事实，以及候选文类和文风建议。资料不足、普通未知和未覆盖建议只会缩短简报，不产生语义阻塞。Writer 在不直接否定锁定事实的前提下自由创作完整正文，不需要预声明所有新数字、人物、因果、规则或器物细节。

正文写完后再执行 V4 轻量抽取。实际事实按 `source / derived / created` 标记来源级别，并保存正文内实际关系；这些标签只存在于私有抽取，不得进入公开正文。篇内明显矛盾和对锁定事实的直接冲突阻止完成；技术 Schema、对象身份、正文哈希、来源路径、图片任务和回执不一致继续失败关闭。正文、抽取、关系索引、图片任务和回执支持精确重放幂等。后续更晚层 Research Prompt 可以读取已完成正文及其抽取事实。

每个研究单元的候选来源包括 `世界基准.md`、`资料索引.md`，以及所有更早层且已有有效对象回执的正文。Prompt 只提供路径选择题和前文抽取事实，不预载全部正文；研究 Worker 根据当前对象选择少量相关材料，再通过 `read_files` 读取真实内容。直接因果前驱优先，但不是唯一准入条件；同层兄弟、未来层、未完成正文和无回执文件不得进入候选。生成依据写入关系索引；`adopts` 边只记录本次简报实际采用的已完成来源，正文后抽取事实和实际关系也写入同一私有索引。Markdown 继续拥有正式世界事实，关系索引只承担可追溯检索。

候选文类的研究维度只用于帮助选择来源和形成建议，不是必填结构。V4 brief 不保存 claims、contentCards、consistencyGuard、criticalGaps 或另一份创作计划。正式正文不得出现 `source / derived / created`、检索过程、来源标签、内部 JSON 或制作术语，也不得复制来源中的大段正文。不把整个世界、上一 Session 的工具历史或全文摘要传入下一阶段。

用户在运行中给出修正时，Main 必须将活动 Growth 会话输入路由到 Growth Lifecycle，而不是只 Steer 可见 Owner Session。最新修正先独立持久化，不改变正在运行阶段的乐观版本；当前 Worker 可以立即收到，下一 Worker 必须再次收到，并先写入 `世界真相.md` 与 `创作计划.md`，标记受影响层和下游。暂停先阻止新阶段并中止当前 Worker；重启后保持暂停，用户显式继续才创建新 Worker，已完成文件束不得重做。

第一轮生产实力证明以约 `3–5` 万中文字符、`25–40` 个正式 Markdown 文件作为内容不过薄的观察区间，不是机械完成门槛。后续完整版本目标是自然生长到约 `15–25` 万中文字符和 `80–150` 个文件，但验证第八步时可以在达到多个连续阶段、约一万字以上、修正与暂停恢复均真实通过后主动停止，不要求跑完整世界。

工具提供 `initialize`、`append`、`map_sources`、`inspect`、`prepare_review`、`amend`、`freeze` 七种动作。`initialize` 接收作品根、路线、结构化 Source Record（来源记录）和独立 Creative Direction（创作方向），创建 UTF-8 基准文件、十二份空层蓝图、状态、索引与因果文件，并通过 Workbench Port 注册作品根一次；十二层只作为根内目录存在。精确重试修复部分初始化，元数据冲突不覆盖已有内容。原著整理至少需要原著或网页证据；二创同时需要原著证据和用户或项目资料。

`append` 每次只接收一个层的少量语义对象与因果。AI 提交 key、标题、group/entry、同层 parentKey、从工具提供候选中选择的 `genreKey` 和归层理由，不提交 ID、文件路径、顺序或索引。工具生成稳定 ID、可读 Windows 安全路径、顺序和定位，验证全局 key、父对象、文类键、题材准入和因果端点，以 `batchId + payloadHash` 实现精确幂等；层、关系和索引已写但状态提交中断时可以重放恢复。

工具 Schema 必须从同一出版文类库按十二层生成 layer -> genreKey 组合约束，执行期仍从同一权威库重复校验，防止绕过 Cline Schema 直接调用。`genreKey` 继续只是后续 Writer 的候选建议，不能因此恢复正文结构门禁。根工作台只由 `initialize` 经 Workbench Port 幂等创建；蓝图 Worker 不直接获得或调用 `register_workbench`。

`map_sources` 只接受 Runtime 注入的可信 `reconcile` 身份。它把蓝图 entry 与覆盖状态、真实来源路径和简短说明写入独立内部清单；group、未知对象、重复冲突映射、不存在路径、绝对路径、`.creatx` 或路径穿越均失败关闭。`inspect` 只读返回蓝图阶段、逐层数量、因果统计、候选文类和整理覆盖统计，不让模型读取或修改内部 JSON。

`prepare_review` 从真实十二层文件重新派生索引并执行完整门禁，确认世界根工作台后进入 `review`。`amend` 只接受处于 `review` 的蓝图，以完整层对象和全量因果形成新修订并回到 `draft`，之后必须再次 `prepare_review`。`freeze` 只接受 `review` 状态；状态和总索引必须一致。数量不足、分组不足、因果不足、Goal 所有权/版本冲突、Windows 大小写路径冲突或损坏状态均失败关闭；冻结后拒绝追加和修订。新 Schema 明确拒绝 V1、V2 状态；历史蓝图只保留为证据，不提供迁移或恢复。旧项目已经持久化的十二层注册没有删除协议，本批不自动改写；它们只作为历史证据，不可恢复到新链。

Pro 第一轮对每份新完成的正式正文提交一个持久生图任务。管理、导航、索引和纯研究文件不触发。输出路径固定为正文同目录下的 `图片/<正文文件名>.png`，稳定幂等键来自完整正文路径；任务 ID 进入阶段回执的 `imageTaskIds`，但 Pro 自动配图默认不是 `requiredImageTaskIds`。提交成功后文字立即继续，图片排队或失败不阻塞后续正文，也不阻塞正文 Goal 完成。通用 Growth 只有显式声明的必需图片才参与完成门禁。该规则不追溯启用前已经完成的正文，也不默认对后续正文修订重复生图。

### CSK-321 十二层正文物化调度

状态：Materialization Schema V4、短写作简报、正文后抽取和持久阶段尝试已通过定向自动测试。旧 V3 `criticalGap` 阻塞在迁移时重新开放，技术 attempt-limit 阻塞保留；已完成正文、路径、图片身份和回执迁移保留。当前没有 V4 Provider Live 证据，历史 V2/V3 与 DeepSeek 内容证据不得冒充新链通过。

冻结蓝图后，Runtime 严格按十二层顺序物化正文。层间使用完成屏障；当前层的蓝图 entry 是独立工作单元，group 只表达层级，不创建正文 Worker。每层默认最多三个隐藏一次性 Cline Session 并行，一个 Worker 独占一个 `plannedPath`。当前层全部 entry 提交完成回执后才进入下一层。

每个对象使用相互隔离的研究与写作上下文。研究侧接收世界基准、资料索引、当前蓝图对象、更早层已完成正文和它们的正文后抽取事实，只选择少量相关材料并提交 V4 brief。Writer 只接收对象目的、少量锁定事实和候选文类/文风建议；它可以更换、混合、省略建议并自由补全正文，不接收旧 claims、contentCards、consistencyGuard 或 criticalGaps 合同。

Worker 不直接修改共享关系索引。它创建唯一正文，向持久图片队列提交该正文唯一对应的图片任务，然后调用专用对象完成工具提交正文后 extraction。Runtime 验证公开正文不泄露内部生产标签、抽取身份与正文哈希一致、事实来源合法、篇内矛盾和锁定事实冲突为空、图片任务路径正确、Goal 与 attempt 身份可信，再写入独立回执并串行重建关系索引。

物化状态是世界蓝图能力的项目私有状态，不加入公共 Growth Goal Schema，也不复制 Cline Run。每个对象从初始化起保存完整合同快照和哈希，研究包与完成回执继续绑定该哈希。完成回执保存提交时正文 SHA-256；用户后续编辑正式文件是有效事实，不把编辑误判为回执损坏。无回执的 Result Unknown 恢复另保存并严格比较恢复正文 SHA-256，禁止覆盖变化正文，并复用同一图片幂等任务。暂停中止当前层全部 Worker并停止派发；已提交回执继续有效，迟到旧版本提交失败关闭。

全部正文对象与十二层回执完成后，Coordinator 收集本次回执引用的真实图片状态，并启动一个无写入、无生图权限的最终交流阶段。交流 AI 根据可信统计汇报正文完成范围和失败、被中断或仍在处理的图片；最终 Assistant 回复进入 Cline 持久会话后，Runtime 才以专用完成权限提交 `completed`，普通模型进度工具不能获得该权限。图片队列独立继续。最终阶段使用稳定 attempt ID；重启恢复时优先复用已经持久化的合法回复，不能重复汇报。历史上正文已完成但停在 `waiting` 的 Pro Goal 走同一收尾路线恢复。

### CSK-322 OC Pro 世界角色设计生产

状态：候选 Skill 源码和既有世界 Provider Pilot 已形成，但未进入生产安装清单或 Growth World Pro 自动加载；R3 单个中世纪女王结构化文字探针通过，人物文风质量尚未证实，标准立绘队列仍返回 Result Unknown。

OC Pro 的目标产品形态是 Growth World Pro 内部按需加载的角色设计能力，不新增公开 `/oc_pro` 命令，也不替代普通角色写作。候选方法每次只选择一个已有世界角色，读取角色正文、世界基准、可用关系索引和 4 至 8 份相关真实世界文件，形成 `design-manifest.json`、角色总卡、人物圣经、结构化角色卡、关系文件和视觉制作规范。角色总卡负责快速认识，人物圣经负责欲望、错误信念、旧伤、恐惧、缺陷、矛盾、不可逆选择、角色弧和声音，视觉制作规范负责轮廓、形状语言、比例、表情、动作、色板、材质与禁止漂移。原始角色正文保留为来源，不覆盖、不移动。独立 Pilot 已有生产分析术语门禁，但生产执行链尚未接入该门禁，且只有一个中世纪女王样本，因此仍不得安装或由 Pro 自动加载。

AI 根据角色用途选择快速档、完整档或制作档；Pro 世界中的主角、主要反派、阵营领袖和世界象征人物优先制作档。角色目录位于 `<作品根>/人物、关系与阵营/OC设定/<角色名>/`。形成真实可浏览内容后，只注册 `<作品根>/人物、关系与阵营/OC设定` 为标题“角色设定”的独立工作台，使它与世界工作台并列；不为每个角色注册工作台。

图片必须先生成标准全身立绘。表情、服装装备、三视图、色板和道具等后续设计只有在标准立绘成功且队列能够表达 reference image（参考图）依赖时才提交；否则只保留计划，不并发生成无关图片冒充角色一致性。图片失败不删除文字产物，也不将角色制作报告为完整成功。

### CSK-323 Growth 问题恢复语义

状态：Runtime、生产 Electron 接入、自动测试与前三阶段外部 Provider 蓝图审查 Live 已实现；第四阶段正文故障语义尚未由本批重跑。

Growth 的工具、Provider、合同或对象故障先登记为持久 Issue 并以红色出现，随后由 Runtime 根据错误语义、持久证据和蓝图因果影响分流。存在确定安全修复方式的错误进入有界自动重试；只有研究包、正文回执或其他权威持久证据通过后才能转绿。回合尾声失败但权威证据已存在时可标记为安全绕过并转绿。绿色只在界面停留三秒，审计记录继续持久保存。

蓝图阶段工具故障同样进入该状态机。Adapter 按可信 stage attempt 和 `toolCallId` 收集根错误，Tool 失败与其 Runtime 汇总只能形成一个 Issue；原始调用仍由 Cline 历史拥有。Scheduler 只有在关闭 attempt 并接受通过权威蓝图证据校验的阶段回执后，才可把已被后续合法调用修正的问题标为 `resolved`，或把不需要的操作在目标不变量已经满足时标为 `bypassed`。未知错误、缺失回执或未通过权威证据时不得标绿。

蓝图阶段明确识别的 Provider 连接重置、socket 关闭和传输超时使用“模型服务连接中断”摘要，并允许最多三次同阶段 attempt 从持久蓝图继续；第三次仍无可信回执即停止等待。普通无回执或未知失败保持既有两次停止边界，不能借传输重试扩大为无限生成。

自动修复耗尽且没有因果下游的对象转为黄色待返工；它不阻塞其他对象和后续层，但不能计为正文完成。存在因果下游的对象保持红色，Issue 进入 `waiting_user`，Goal 进入 `waiting`。未知错误不得直接标绿。

用户主动暂停与系统红色阻塞是两套语义：`paused` 只能由继续按钮恢复；`waiting_user` 不要求再次点击继续，用户的普通回复进入同一会话的有界语义判断。信息不足时只追问并保持红色；信息足够时，受信任工具先把阻塞对象恢复为可重试，把模型整理的重试说明与 Issue 解决、Goal 激活事务性保存，然后 Main 自动唤醒原 Scheduler。工具不能由模型指定任意 Goal 或 Issue。

原始错误详情保存在默认折叠的审计区。对象 Worker 的错误不得同时升级成无归属的全局错误横幅；普通会话和非 Growth 错误仍按原错误通道显示。

## 7. Draw Map

### CSK-501 统一可选择地图结果

状态：Accepted Product Behavior。

`/draw-map` 的产品结果是“视觉地图 + 可选择区域”，不绑定一种算法。成功图片保存为真实项目文件；区域拥有稳定 ID、名称和选择几何，工作台显示高亮与详情。

生产 V25 使用一张原生高清完整底图和一张同尺寸、不透明、无抗锯齿的区域 ID 蒙版。整张矩形的每个像素都必须属于已声明的陆地、水域或未知区域。蒙版只负责隐藏命中、裁切、高亮和边界；不得为了适配低分辨率蒙版而降采样、遮罩或重写可见原图。

### CSK-502 两种生成策略

状态：Accepted Product Behavior。

- 视觉优先：图片模型先生成高清艺术地图，再根据同一画面形成完整区域 ID 蒙版并逐区核对。
- 结构优先：先形成完整区域蒙版，再将其作为构图约束生成同尺寸艺术底图；最终仍必须逐区核对图像和蒙版的视觉含义。

Agent 根据当前素材和目标选择策略；用户可以明确指定。

### CSK-503 视觉与几何分离

状态：Accepted Product Behavior。

图片负责视觉表达，ID 蒙版负责交互所有权。两者必须天然同尺寸；Viewer 以原图为唯一可见底图，不能显示蒙版、网格或调试边界。无法验证逐区对齐、无主像素和未知颜色时不得宣称可选择地图完成。

### CSK-504 地图选择交互

状态：Accepted Product Behavior；组件实现属于 `workspace-ui`。

单击区域后使用同一原图裁切该区域并形成金边与轻微抬升；水域或巨大外层区域原位提亮。区域说明只在选择后以靠近选区的可拖动、可关闭浮窗出现；再次选择当前区域、关闭按钮或 `Esc` 关闭。选择只是视图状态，不修改项目内容。

### CSK-505 第一版停止边界

状态：Accepted Product Behavior。

第一版不提供拖动边界、手绘区域、逐格编辑泰森网格、GIS（地理信息系统）、地图专用版本系统或复杂区域管理。

### CSK-506 清晰底图质量门禁

状态：Accepted Product Behavior。

视觉优先路线必须先取得原生分辨率清晰底图，再进入蒙版推导。Skill 对分辨率、动态范围、平均梯度和强边缘比例执行确定性门禁，并真实打开图片检查完整构图、闭合边界、区域数量、文字与裁切。单次任务最多尝试三个 Provider（模型服务）结果；全部不合格时失败关闭。不得模糊、重绘、降采样或覆盖已接受的 Provider 原图来迁就蒙版。

### CSK-507 从真实视觉边界反推蒙版

状态：Accepted Product Behavior。

视觉优先路线使用底图内部安全种子与图像梯度确定性推导完整 ID 蒙版。长区域、外层区域、纹理复杂岛屿和具有多个内部视觉盆地的同一语义区域必须布置覆盖种子；不能只凭一个点期待跨越内部脊线。推导必须拒绝微小区域和弱边界贴合，并输出配准审查图；Agent 逐区对照原图后才能构建。圆、椭圆、平滑宏观多边形、泰森格或手工近似轮廓不能冒充对底图视觉边界的贴合。

每个人物拥有独立立绘、身份资料、人物关系、地域或势力归属和六部分角色圣经；同时生成一份群像入口工作台，点击后进入各自人物页。立绘必须通过项目图片队列提交以集中应用统一画风，不能绕过队列或手工复制视觉母版。缺图、未应用母版或无法真实读图时必须准确报告，不能伪装为已完成角色成品。

## 9. Draw Comic

`/draw-comic` 把故事、剧本、回忆、点子或项目正文转为原创漫画页、跨页或多格叙事。每部作品从文本本身推导 Art Direction（艺术指导）、Page Direction（页面导演）、视觉节拍、格数与格形，不使用日漫、国漫、美漫、欧漫等固定预设菜单，也不默认等分网格。

漫画生产必须先读取作品和连续性事实，再把可见变化拆成画面节拍；长期作品按需要建立角色、服装道具、地点和视觉语言参考。生图 Prompt 使用明确的保存、可变和禁止项；生成后必须检查实际图片的叙事、角色连续性、文字与构图。没有图片工具或 Provider（模型服务）时只能交付可审查指导和最终 Prompt，不得声称图片已经生成。

### CSK-701 小说联动与故事门禁

状态：Accepted Product Behavior。

用户明确指定的来源优先；项目中已有用户接受或正在推进的小说章节时，漫画默认改编该章节，不得擅自换成世界设定条目或事件纪要。正式分镜前必须识别主角的当前目标、主动阻碍、失败代价、因果行动链、不可逆转折和翻页钩子。来源缺少这些条件时，Agent 可以在开放设定内先写有限的漫画改编桥段，但必须说明哪些行动与对白属于改编新增，不能假装原文已有成熟故事。

### CSK-702 项目视觉权威

状态：Accepted Product Behavior。

漫画视觉按“用户本次明确要求 → 最近的《统一画风.md》 → 已接受的角色、服装、地点、建筑和材质参考 → 来源正文的文化、时代、技术证据 → 开放空间内的有限决策”解析。不得根据用户语言、人物名字写法、Agent 所在地区或模型默认习惯猜测视觉文化。西幻不得无依据漂移成中国古代，反向漂移同样属于生产失败。

### CSK-703 逐格绘制与确定性排字

状态：Accepted Product Behavior。

多页或连续性敏感漫画默认逐格生成真实图片，再使用 HTML、SVG、Canvas 或其他可验证的确定性方式完成裁切、格框、气泡、旁白、拟声和精确文字。整页生图只用于缩略分镜、构图探索或已经通过代表页验证的特例。绘图 Prompt 禁止模型生成文字不等于最终交付无字漫画；除非故事明确需要沉默，最终页面必须恢复脚本中的文字信息。廉价模型只用于草图和可丢弃试验，正式格、角色连续性、复杂动作和最终页面资产使用标准高质量图片模型。

### CSK-704 真实视觉验收

状态：Accepted Product Behavior。

验收必须同时检查无字状态与带字状态：隐藏文字后应大致看懂谁在行动、发生了什么变化和危险从何而来；恢复文字后应明确理解目标、阻碍、代价、因果和阅读顺序。Agent 必须用真实读图能力检查每个成品格和合成页面；文件落盘、字节有效、Provider 返回成功或图片重新读取成功均不能代替视觉验收。无法读图时只能标记为未审查，不得宣布漫画完成。

## 10. Causality

### CSK-601 可视化因果理解

状态：实验性内置 Skill 已实现；真实 Agent 注册工作台待 Live 验收。

`/causality` 读取当前世界已经物化的关系，只把明确存储为 `type: "causes"` 的方向和原因投影为全世界因果图。它可以由普通项目会话调用，也可由 Growth 用于检查自洽性；两条入口使用同一个内置 `creatx-causality` Skill，不建立隐藏专用 Runtime（运行时）。第一版不在生成阶段重新推导或补写因果。

### CSK-602 因果不等于普通关系

状态：Accepted Product Behavior。

目录包含、文件引用、采纳、支持、归属、位置、共同出现、相似度和普通关联都不能成为因果边。每条输出边必须保留权威关系中的原方向与 `reason`；没有任何明确 `causes` 时以 `NO_CAUSALITY` 失败关闭，不能用关联图降级冒充结果。

### CSK-603 图谱交互

状态：离线 Viewer（查看器）与生成器已实现；工作台工具真实调用待 Live 验收。

Skill 生成项目内、无网络依赖的 Viewer，支持搜索、拖动、缩放、选择节点、突出上下游因果并查看真实内容摘要。生成成功并经 Agent 检查后，Agent 使用通用 `register_workbench` 和 `set_workbench_home` 注册目录与 `index.html`；不得直写 `.creatx`，两次工具调用未成功时不得宣称工作台已注册。

### CSK-604 第一版停止边界

状态：Accepted Product Behavior。

第一版不提供手动画图、复杂模拟、反事实推演、专业图数据库编辑器或客观因果证明。产品称其为“AI 对当前作品的可视化因果理解”。

完整物化关系是首选输入。冻结蓝图只可作为明确标记的降级来源；多世界歧义、显式选中的损坏 Goal、越出项目的路径和非本 Skill 所有的既有输出目录均失败关闭。因果图只写世界作品目录，不修改蓝图、Growth 状态、数据库、Cline Core 或 Provider（模型服务）配置。

## 11. 尚未决定

- Skill 包格式、版本、更新、可见性和是否允许用户自定义。
- Study 的结构化 `web_search` Provider、非视觉模型兼容和超大资料继续边界；第一版来源记录只要求页面标题、URL 和一句用途。
- Growth V1 持久 Schema 已由 `@creatx/growth-runtime` 冻结；预算上限和 Renderer 视觉样式仍未决定。
- 工作台注册 V1 Schema、通用预览和幂等已经由 `workbench-registry` 的 ADR-0007 拥有；本能力只剩“Agent 何时以及怎样使用该工具”的 Skill 教程尚未决定。
- 地图视觉文件、区域几何与图生图输入的最小可迁移格式。
- 因果节点、边、来源文件和工作台布局的最小可迁移格式。
- 世界关系球的最终表现形式仍在重新设计；现有 Prototype 不进入正式挂篮，不能作为当前五项生产序列之一。

这些开放项不能因本规格建立而自动接受。

## 13. Growth 路线与 Runtime 分离（2026-08-05）

### CSK-324 创作路线只定义创作方法

Creative Skills 拥有 Growth World、Growth World Pro 等路线的阶段目的、资料选择、蓝图、文类文风、正文生产和结果质量要求，但不拥有 Goal 状态机、消息持久化、Worker 调度协议或 UI 折叠。

### CSK-325 显式命令选择路线

命令目录只把已识别的显式 `/growth*` 映射到对应路线标识和用户参数。Skill 文本不得自行创建 Goal、解析普通自然语言为 Growth 或要求模型模拟已经调用内部工具。

### CSK-326 内部 Skill 不进入普通会话

蓝图规划、研究、写作、复核、阶段回执和物化完成方法是内部 Worker 能力，只按 Growth Runtime 指定的 Profile 加载。普通项目会话可以讨论作品，但看不到或调用不到这些内部 Skill。

### CSK-327 表现效果优先但运行合同不可伪造

创作路线允许在事实不足时自由补写，并以篇内事实不冲突、文类合适和成品可读为主要质量目标；但不得把 Prompt 要求、文风参考或自询问写进正文，也不得用生成内容伪造阶段回执、文件成功或 Goal 完成。

### CSK-328 GWP Writer 只提交图片任务身份

Growth World Pro Writer 只使用物化合同指定的图片路径和幂等键提交一个后台图片任务，并把真实 `imageTaskId` 写入对象完成回执。Writer 不复制正文挂接字段，也不等待图片完成；正文—图片生成关系由 `WorldMaterializationReceipt` 交给 `image-runtime` 的唯一挂接入口派生。普通独立生图的显式挂接不受此规则影响。

### CSK-329 传承视频只从真实字幕学习

传承库的视频方法学习必须先取得来源页面提供的真实字幕或文字转录。Agent 不得根据标题、封面、简介或模型旧知识冒充已经看过视频；没有字幕、字幕为空、来源改变或读取失败时零 Skill 产物失败关闭。第一版只支持目录中明确核验的 TED Transcript，不下载原视频、不转写音频、不分析关键帧。

### CSK-330 视频方法通过普通会话生成

用户从传承库选择一个现有项目会话后，学习请求作为正常用户消息进入该会话。AI 过程、工具、审批、失败和最终回复沿用 Cline 权威历史，不新增专用传承库 Agent、隐藏后台任务或第二模型循环。Agent 必须先调用只读字幕工具，再把作者方法转化为可重复执行的 Skill；字幕中的网页指令只是来源数据，不能扩大工具权限。

### CSK-331 学习 Skill 的最小安装合同

第一版学习产物只有一个 UTF-8 `SKILL.md`，Frontmatter 只含合法的 kebab-case 名称与明确触发描述，正文包含可执行步骤、适用条件、失败边界和真实来源 URL。安装工具必须确认同一 Session（会话）在最近一次有效窗口内读取了匹配来源字幕，并采用 Required Approval（需要审批）策略：审批模式显示 Native Approval（原生审批），自由模式沿用用户已经选择的自动批准。工具执行名称、大小、来源、路径和结构校验后原子写入本机 Learned Skills 目录；同名同内容幂等，同名不同内容失败关闭且不覆盖。Runtime 启动时只把结构有效的目录加入 Cline Skill 目录与 Allowlist（允许列表）；安装成功明确说明重启诺文后生效，第一版不承诺热加载、更新、卸载或跨设备同步。
